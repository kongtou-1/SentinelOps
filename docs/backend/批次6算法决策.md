# 第六批次算法调研与决策

调研日期：2026-10-02。依据 docs/plan.txt、技术方案和用户要求，首版由纯直线外推调整为支持周期的统计预测，运行于本地 CPU。

## 实际应用依据

| 产品 / 实现 | 官方公开的方法 | 证据边界 |
| --- | --- | --- |
| Grafana Cloud | 2023 年公开使用 Prophet，包含日、周、年周期 | 属于已公开产品实现，不据此断言现在全部模型仍是 Prophet。[说明](https://grafana.com/blog/how-to-forecast-holiday-data-with-grafana-machine-learning-in-grafana-cloud/?src=s) |
| Datadog Anomaly | Agile 为稳健 SARIMA，Robust 为季节趋势分解 | 异常检测的产品方法，不等同于其全部预测功能。[文档](https://docs.datadoghq.com/monitors/types/anomaly/?s=anomaly+algorithm) |
| AWS CloudWatch | 分析趋势和小时、日、周周期，最多两周训练数据 | 官方未公开具体内部模型，不推断为某种深度网络。[文档](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Anomaly_Detection.html) |
| Datadog CCM | 2026 年公开云成本预测使用 Toto 时序基础模型 | 有实际产品用途，但不证明资源监控的小数据场景也需要同类模型。[说明](https://www.datadoghq.com/blog/cloud-cost-management-budget-forecasting/) |
| StatsForecast | MSTL 分离多个周期，非周期模型预测去季节化序列，再叠加周期 | 是开源算法实现依据；不声称上述商业厂商内部使用相同 MSTL 实现。[说明](https://nixtlaverse.nixtla.io/statsforecast/docs/tutorials/multipleseasonalities.html) |

关键区别是“单条直线外推”和“包含周期结构的模型”。SARIMA 等统计模型也能够预测周期，并非所有线性统计方法都没有周期能力。

## 采用的方案

- 主候选：稳健 MSTL + 非周期 AutoETS。5 分钟采样下日周期为 288 点，周周期为 2016 点；需要至少三天或三周历史。MSTL 的局部平滑识别周期和缓慢变化，AutoETS 选择趋势与平滑参数。它不负责预测未知部署事件和突发宕机。
- 备选：非周期 AutoETS；基线是 Naive（保持最近值）及日 / 周 SeasonalNaive（重复上一周期）。按每个预测时长的滚动回测 MAE 选优，公开所选模型。常量负载由 Naive 获胜是正常结果。
- 首版不同时增加 Prophet / SARIMA：避免多个依赖和参数搜索体系；MSTL 已满足日、周多周期需求。此为当前项目的工程选择，不宣称对所有数据优于其他方法。
- 用户选择暂不加入预训练时序模型对照。保留真实基线和评价记录，未来更换模型必须用同样的数据、时间切分和时长比较。
- 异常检测使用前一轮预测的残差：Robust Z-Score 识别尖峰，EWMA 识别连续小偏移。EWMA 的 λ=0.2 与 3σ 控制限参照 [NIST](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm)；不将该控制限描述为独立于数据分布的概率保证。

工程实现使用 StatsForecast 2.1.1，通过 uv 锁定。稳健 STL 对长平滑窗口使用步长为最短周期 10% 的插值计算，季节项仍逐点平滑；在最终配置上重新验证精度和完整 worker 耗时。

## 回测和质量判断

1. 1h / 6h / 24h 各使用三个不重叠验证窗口，训练只使用对应截点之前的数据。缺失值也仅用该训练窗口内部观测插值。
2. 记录模型 MAE、各基线 MAE、相对改善比例及 95% 区间的实际覆盖率。零值较多的资源指标不使用 MAPE。
3. 首次满足训练与验证条件时、每天及新周期候选具备资格时重新回测，普通运行复用评价结果并更新预测。
4. 回测不足为 provisional，风险 unknown；实际区间覆盖率低于 80% 为 interval_low_confidence，不产生仅由区间上界越界触发的预警。
5. 自适应模型没有被强制选中。点预测和区间的质量必须分别报告，不能把模型名或设置的 95% 当成实际准确率。

## 模拟数据验证结果

固定随机种子 20261002；指标为缓慢增长趋势、日周期、可选周周期及标准差 0.25 的噪声。预测未来 24h。直线基线使用最近一天拟合；该比较只说明此明确含周期的模拟场景，不代表所有真实工作负载。

| 场景 | MSTL + AutoETS MAE | 直线 MAE | 单次拟合和预测耗时 |
| --- | ---: | ---: | ---: |
| 日周期 | 0.200 | 28.617 | 0.25 秒 |
| 日 + 周周期 | 0.249 | 24.816 | 8.52 秒 |

完整 28 天、三个预测时长的首次回测和计算在本机 CPU 子进程中耗时 97.48 秒，未超过 120 秒限制；三个时长均选择 mstl_daily_weekly。1h 区间实际覆盖率不足，系统正确标为 interval_low_confidence；6h / 24h 标为 validated。证据为 `.local/batch6-algorithm-report.json`，可用 `backend/scripts/benchmark_predictions.py` 重现。

本地真实历史验收时只有约 7.4 小时。真实数据仅证明采集、查询、调度、计算和数据不足处理可用；日、周周期的真实准确率尚未验证。
