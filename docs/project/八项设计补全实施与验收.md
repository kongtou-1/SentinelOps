# 八项设计补全实施与验收

本次范围：业务目标、依赖影响、事故响应、稳定恢复、效果评价、复盘整改、平台自监控与灾备、数据与成本治理。按七个阶段交付，现有审批、执行权限和历史冻结证据保留。

## 已确认边界

- 站内待办与现有 SMTP；外部收件人及通知启用由 Admin 明确配置。
- 业务埋点只改平台与 testlab 示例；固定案例、确定性检查和人工确认用于评价。
- 清理先预览再由 Admin 确认；备份人工执行并记录新鲜度与恢复演练。
- 不部署未授权远程目标，不自动付费回放，不自动修改业务服务器。

## 第一阶段：业务目标与后台基础

新增 `0025_service_objectives`，创建服务目标与 worker 心跳表；均包含 UTC 时间、软删除和更新时间触发器。新 `operations-worker` 使用 PostgreSQL 单实例锁，计算有界的到期目标，不执行备份、清理或服务器动作。

服务详情「运行治理」可添加、编辑、暂停、删除业务成功率、探测可用率、请求 P95 和 LLM 首字 P95 目标。Admin 填写具体目标；窗口为 1、7、30 天，默认 7 天。修改与删除校验版本，监测项必须属于当前服务。比例目标原始单位为 0–1，性能单位为秒。错误额度以窗口允许失败次数减去观测失败次数计算，可为负数。

目标计算读取 Prometheus，业务库只存配置及最新评价。当前采集新鲜度、窗口覆盖率、请求总数和目标值分别检查。无请求、未上报、历史不足、暂停和采集过期分别展示。有效观测覆盖不足 95% 时仅展示暂定值，不判定达标。采集配置变化后旧时间序列不混入当前目标。

### 新增埋点协议

沿用服务 `traffic_target` 和 `/metrics` 接入，服务发现注入 `application_id/source_epoch`。指标标签为有限操作名 `operation`、模型 `model`、`traffic=business|probe` 及有限结果，不包含用户、请求 ID 或完整 URL。

| 指标 | 含义 |
| --- | --- |
| `sentinelops_business_requests_total{operation,outcome,traffic}` | 应用明确报告的业务成功/失败；HTTP 200 的逻辑错误计失败 |
| `sentinelops_llm_requests_total{operation,model,outcome,traffic}` | LLM 调用结果 |
| `sentinelops_llm_tokens_total{operation,model,kind,traffic}` | Provider 返回的 input/output token 数 |
| `sentinelops_llm_usage_observations_total{operation,model,availability,traffic}` | usage 已知/未知次数，缺失不能作为零用量 |
| `sentinelops_llm_duration_seconds` | 调用总耗时直方图 |
| `sentinelops_llm_ttft_seconds` | 实际首次内容增量耗时直方图，非流式响应不填造首字时间 |

testlab 保留 `/ask`，增加 POST `/ask/stream` SSE。显式 `mock_llm/mock_slow/mock_interrupted/mock_missing_usage` 场景用于不付费测试；`logic_error` 产生 HTTP 200、业务失败。正常模式仅人工问答调用已配置的 Provider，后台 `/work` 流量不调用付费模型。

### 升级

按 README 备份数据库及独立主密钥，停止写入与 worker，升级镜像后执行 migrate。`monitoring` profile 增加 `operations-worker`，就绪版本为 `0025_service_objectives`。未配置目标的存量服务保持原业务健康规则。

## 第二阶段：稳定恢复与依赖影响

新增 `0026_stability_impact`：服务运行策略、事故关联、告警稳定起点与最近证据时间。Admin 在服务「运行治理」设置 30–1800 秒恢复窗口，默认 180 秒。规则显式应用时将窗口冻结进通知；无该字段的存量通知保持原解释，策略调整不重写旧通知。

核验先取得新鲜、同资产、同规则和当前来源版本的正常证据，再累计不同证据时间。窗口届满时在事故锁外读取有界历史，检查采样完整和阈值；采集失联、失败与缺口不能作为持续正常。动作执行状态不负责决定事故恢复。

依赖视图只使用登记关系，最多三层、100 个服务，循环去重并显示截断。关键监测的当前观测与潜在关联分别展示。当前服务与依赖服务的相关事故产生候选；同服务恢复后 30 分钟内的新事故关联最近一次已恢复事故。Operator/Admin 可确认或排除候选，记录版本和时间线；不自动合并、重开事故或认定根因。

数据库仅使用独立 `sentinelops_design_test`、端口 25435，容器属于 `sentinelops-design-acceptance`；不对业务数据库执行测试。

- 第一阶段：后端目标、真实本地 HTTP/SSE、结构和数据库定向 50 项通过；前端 128 项通过，类型检查与生产构建通过。浏览器使用隔离账号实际创建目标并核对列表状态。
- 第二阶段：依赖、复发、稳定窗口及原恢复/事故/服务监测/结构/数据库回归 136 项通过；追加新鲜度历史保护和服务配置审计后定向七项通过，前端生产构建通过。浏览器实际保存恢复窗口并查看依赖状态。

## 第三阶段：响应、通知与维护

新增 `0027_incident_response`。服务策略绑定有效 Operator/Admin，用户通知邮箱由 Admin 配置。新事故冻结服务响应策略；站内阅读不接单，显式接单或开始处理记录首次响应。超时只升级一次，存量事故不追补通知。维护、静默与父子规则抑制保留监测事实和恢复核验，暂停通知与自动诊断。

`operations-worker` 调度持久化通知；SMTP DATA 后断连记为 unknown，重启不自动重发。投递前重查收件用户、邮箱、策略版本及配置者权限。Admin 明确切换通知后，通过共享配置卷移除 Alertmanager 原始邮件配置并核对生效状态；失败恢复文件和运行配置。

验收：响应、通知、维护与权限相关回归 103 项通过；前端 130 项及生产构建通过。独立 Alertmanager 与 Mailpit 实际完成切换、单封投递、sent 状态和旧配置恢复，集成测试一项通过。浏览器实际完成待办已读及事故接单，确认二者独立。外部真实邮件未发送。

## 第四阶段：效果评价

新增 `0028_effect_evaluation`。正式诊断可追加人工评价，不改写「采用」或原诊断；私有会话不作为公共案例入口。Admin 从正式诊断收录脱敏冻结案例，版本不可变；保存工具参数、结果、知识、模型配置和哈希。回放由人工发起，真实模型另需显式确认费用，AI worker 在生产诊断无任务时执行。未收录工具请求只返回 case_data_gap，不调用生产数据源。

回放分别记录结构、引用、工具、根因词、耗时和人工结论；比较限定同一案例版本，模拟与模型来源分别展示。支持人工选择当前 Skill 的冻结版本用于回放。预测完成后按 1、6、24 小时窗口读取后续观测；完整样本才产生阈值命中和提前量，未验证预测及不完整观测排除。真实事故关联由人工确认，与资源越界分开存储。

验收：新增四项测试通过，覆盖版本冲突、幂等、人工评价、付费确认、冻结工具无生产回退、观测缺口和提前量；相关原回归 55 项通过。前端 131 项、类型检查和生产构建通过。浏览器实际收录案例、发起模拟回放并确认结构与引用通过。真实模型效果与付费 Provider 未验证。

### 分阶段回退

关闭服务目标、维护窗口及自动诊断策略可停止对应计算或抑制。通知接管须先在 Admin 界面切回原 Alertmanager 配置并核对成功；不要直接删除共享通知卷。停止 operations-worker 可暂停新增治理巡检与通知，原审批执行 worker 独立运行。停止发起回放即可保留既有生产诊断优先级。数据库降级会删除新表，应先备份，仅在停写且不需要新增记录时按迁移逐级回退；历史冻结证据与已审核报告不重写。

## 第五阶段：整改与知识有效期

新增 `0029_improvement_knowledge`。从当前已审核报告人工选择条目，按报告、版本、条目建立唯一任务；不根据报告中的自由文本猜测用户或日期。任务独立于事故关闭。Operator 可认领并提交自己的任务，Admin 分配、验收、退回或取消；状态和修改校验版本，审计保留每次提交与决策。修复交接结果和部署核验作为冻结证据引用。到期提醒复用站内待办和已启用邮件。

文档与 Skill 增加适用服务、版本、负责人、复核和到期时间。当前检索和诊断工具排除明确过期内容，历史冻结记录仍可读，无到期值保持有效。有效期修改有版本校验；报告提炼知识先保存停用草稿，Admin 通过原知识编辑入口修改并发布。

验收：新增整改、到期检索及范围、停用草稿测试，与效果评价和结构合计 16 项通过；原 AI、自动诊断、对话、复盘和数据库回归 204 项通过。前端 133 项、类型检查和生产构建通过。浏览器从报告选项建立任务、配置负责人/期限/验收条件、提交及验收完成，并核对知识「已过期」状态。回退前停止任务写入，先保存新任务及审计；停用新知识草稿不影响存量知识。

## 第六阶段：平台健康与灾备

新增 `0030_platform_health`。系统状态增加独立组件接口、各 worker 持久化最近轮询、队列数量与最老等待、近一天失败/未知数、Prometheus/Alertmanager 连通性、数据库容量与存储空间。存活和数据库就绪接口保持原语义。`PLATFORM_WORKERS` 为逗号分隔的预期 worker 清单，按实际启动 profiles 配置；未启动组件显示未观测，不伪装为数据库故障。

备份和恢复由 Admin 人工登记产物名、SHA256、大小、时间和校验依据；不接收宿主机文件路径。已校验备份超过 24 小时生成待办及已启用邮件。恢复目标为 7200 秒，实际未登记时为未知；仅实际登记校验通过的演练才判定该次是否达标。

独立脚本 `deployment/watchdog/watchdog.py` 仅使用 Python 标准库，HTTP 检查和 SMTP 不依赖平台数据库，相同故障不重复发送。部署与跨机器说明见相邻使用说明。Windows 交接导出按完整 Compose 服务清单检查，纳入新增 worker、通知配置卷与新队列；数据库指纹按所有表动态核对，导出/恢复后登记结果。密码和主密钥仍由原加密交接流程独立保护。

验收：平台健康、备份、看护及前阶段/结构/数据库定向 57 项通过，前端类型检查与构建通过，交接 PowerShell 语法检查通过。实际 operations-worker 在独立测试库写入心跳。分别停止测试 API、测试数据库后，看护实际送达 Mailpit 两封不同故障通知，数据库随后恢复。`sentinelops-design-restore` 独立项目恢复 `sentinelops_design_restore_test`，59 张表指纹全部一致；本次创建容器、恢复和核对合计 4.781 秒，界面已展示目标和实测值。原完整加密交接包的全镜像搬迁未重跑；远程看护、外部邮件及生产规模恢复耗时未验证。

回退时停止独立看护和新增治理巡检，保留备份产物、密码及独立主密钥。迁移降级前先导出灾备登记；原存活/就绪和手工备份恢复入口继续可用。

## 第七阶段：数据保留与成本

新增 `0031_data_cost_governance`。容量统计区分数据库（含 TOAST 和索引）、源码快照、缓存、临时目录及归档。清理白名单为已结束且未采用的诊断会话 90 天、无引用源码快照 90 天、无引用预测结果 180 天、非活动源码采集临时目录七天。事故、审批、执行、报告、审计、整改及冻结证据不在清理白名单中。

Admin 在「数据与成本」生成清理预览，查看引用保护，再明确确认。worker 执行时重新检查用户权限、活动任务和引用；数据库引用保护触发器与事务锁阻止清理和新引用并发穿透。对象先保存 gzip 归档并核对 SHA256，再软删除和释放白名单大字段/文件；重启从持久化步骤继续。归档保留原访问权限，私有会话仍按所有者或原 Admin 权限读取。路径由服务端固定对象标识推导，拒绝符号链接、目录跳转和任意宿主路径。

「释放文件」表示实际删除的原文件字节；「数据库可复用」表示清空的大字段逻辑字节，不代表数据库文件立即缩小。归档仍占空间，界面单独统计，不把备份产物作为清理对象。归档文件保存在 `archives` 卷，API 只读，operations-worker 可写；源码文件保持原 `source_store` 卷。备份和搬迁必须同时保留数据库、源码、归档和通知配置，以及独立保管的主密钥。

用量按业务、探测、诊断、报告和评测区分。平台网关在发起请求前登记未知记录，结束后记录实际 usage、耗时和流式首段内容时间；中断或缺失 usage 保持未知，不填零。应用埋点按五分钟完整窗口和一分钟滞后读取，标记估算来源；网关来源不再次计入应用汇总。模拟 Provider 使用 `AI_PROVIDER_KIND=mock`，与实际模型分组且不计费。生产默认 `model`，不得用模拟标志隐藏实际付费用量。

模型价格由 Admin 以模型、币种和生效时间追加，历史用量按调用时间选取价格；无价格只显示 token 和未定价状态，不合并币种。月预算达到 80% 和 100% 各提醒一次，不阻断诊断或执行。缺失和未定价用量在预算状态中独立显示。

平台认证 `/metrics` 现包含显式业务结果和模型用量/耗时；新增固定 `platform` 采集任务。平台目标选择 `metric_source=platform`，仅接受有限工作流：业务结果为 diagnosis/report/execution/source_snapshot，首字延迟为 diagnosis/report/evaluation/probe。应用目标默认 `application`，仍需应用开放指标并配置流量采集；接口不接受自由 PromQL。标签不包含用户、请求 ID 或完整 URL。七天窗口历史不足时显示历史不足和已有样本值，不能认定长期达标。

回退先暂停新清理确认并等待已运行归档步骤结束。关闭预算和目标、停止 operations-worker 可暂停新增巡检。若已清理数据，单独数据库降级无法恢复原大字段和文件；须使用清理前备份或经校验的归档恢复，并保留归档索引。不得仅删除 `archives` 卷。

## 最终部署与入口

完整 profiles：`monitoring ai execution reports sources`，本机模拟资源另加 `local-test`。部署前按 README 手工备份数据库及独立主密钥，停止写入与全部 worker，升级到 `0031_data_cost_governance`，运行 `init_monitoring.py` 更新固定采集配置，准备持久化卷，再启动 API 与六类 worker。`PLATFORM_WORKERS` 按实际启用清单设置；组件故障通过 `/api/v1/system/components` 单独显示，不改变数据库就绪语义。

| 入口 | 使用与权限 |
| --- | --- |
| 服务详情「运行治理」 | Viewer 查看目标、依赖和策略；Admin 明确设置目标及结构化负责人 |
| 事故详情 | Operator/Admin 接单、确认关联；查看冻结稳定窗口及证据时间 |
| 顶部「我的待办」 | 当前用户独立已读状态和邮件投递结果 |
| 通知设置 | Admin 明确配置邮箱并接管原始邮件；失败回滚原配置 |
| 效果评价 | Operator/Admin 人工评价、案例与回放；真实模型回放须明确发起 |
| 报告「整改与知识」、整改任务 | 人工导入已审核条目；执行人提交，Admin 验收/退回 |
| 知识有效期 | Admin 编辑范围与有效期；报告提炼只创建停用草稿 |
| 系统管理、数据与成本 | Operator/Admin 查看平台状态及成本，Admin 登记灾备、配置价格预算与执行清理 |

存量服务不猜测目标、身份或邮箱；存量事故不补发接单超时通知。付费回放、外部邮件接管、清理和备份均保留人工入口。本轮未升级业务数据库或改变远程服务器。

## 最终隔离贯通验收（2026-10-23）

使用独立 `sentinelops_design_test`、本地业务容器、Prometheus、Alertmanager、真实 Harness/MCP 与本地模拟 Provider、Mailpit。HTTP 健康和业务请求均为 200 时，显式业务结果为 false，断言探测产生真实告警、事故与站内待办，邮件队列最终为 sent 且 Mailpit 收到邮件。短暂正常时稳定状态保持 pending；持续新鲜正常采样后为 verified/stable_normal_evidence，冻结窗口 30 秒。
