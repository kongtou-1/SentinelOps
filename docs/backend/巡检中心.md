## 结构

继续使用 FastAPI、SQLAlchemy、PostgreSQL、Vue 3、Element Plus 和现有后台进程。`operations-worker` 调度到期计划，`inspection-worker` 采集、判断并持久化结果；Skill 通过现有 Harness、DiagnosticGateway 和三个只读工具执行，不引入工作流引擎或多 Agent。

## 数据源

`InspectionDataSource` 保存名称、服务范围、环境、类型、读取配置、版本、连接测试时间和结果。HTTP 认证保存为 Fernet 加密请求头，只返回 `headers_configured`。支持 API Key 请求头、Bearer、Basic 和自定义请求头；不回填密钥，更换地址且未提供新认证时清除旧认证。

数据库复用 `ServiceDatabase`。在数据源页的“数据库连接”中新增或编辑账号、密码、TLS，刷新结构并授权表和字段；再创建巡检数据源并选择连接、表、对象标识和检查字段。MySQL、PostgreSQL 共用现有只读适配器、权限核验、SELECT 白名单和查询超时。数据库密码不复制到数据源或计划。

2026-10-30：`/inspections/sources` 页面及导航统一为“数据源管理”，主页面以“查询”和“数据库连接”页签直接展示列表，移除包裹连接列表的抽屉，以及独立的 HTTP 连接页签和“新增连接”入口。新增按钮随当前页签显示，新增和编辑使用表单抽屉。HTTP 地址、认证、参数和数据映射在“新增查询”中完成。已有共享 HTTP 查询继续运行，编辑保存时转为该查询自己的配置，保留未修改地址的加密认证，不影响其他引用查询；修改地址且未提供新认证时清除旧认证。数据库连接列表直接展示可访问连接，服务关联可选；无服务归属的连接也可供同环境的服务查询及独立查询使用，仍受资源授权、只读权限和表字段范围校验。

本次验证：独立 PostgreSQL 测试库及专用 Python 沙箱下，后端连接生命周期、资源权限、旧 HTTP 查询认证兼容、真实只读取数、巡检、OpenAPI 和模型结构回归共 98 项通过；28 项依赖专用外部 PostgreSQL/MySQL 验收配置的测试未启用。前端 262 项测试、类型检查及生产构建通过。浏览器在隔离环境验证无服务关联的连接保存，以及 HTTP 查询新增、保存和样本预览。没有向真实外部数据库新增连接或执行查询。

HTTP 只执行固定 GET，禁止 URL 内凭据、重定向和认证查询参数。支持两种格式：

- `response_format=records`：沿用 `{items: [{id, version, updated_at, facts, ...}], next_cursor}`，平台发送时间窗口和游标。
- `response_format=json`：接收普通 JSON 对象或数组；用 `items_path` 选择对象列表，如 `data.items`，用 `object_id_path` 指定编号，默认 `id`。根对象可不设路径；无编号时单对象采用 `response`，数组采用位置编号，长期跟踪应配置稳定业务编号。版本按实际内容计算。

单次 HTTP 响应最多 2 MiB、单对象最多 32 KiB。普通 JSON 在内存中分页；大数据接口应使用 `records` 协议提供服务端分页。新增适配器遵循 `READERS` 中的 `(db, plan, run, limit) -> (records, cursor)` 接口。

计划通过 `data_source_id` 复用主源；最多四个关联源也可指定该字段，并配置别名、关联字段和一对一／一对多关系。未关联服务的数据源可用于相同环境的独立计划；已关联服务的数据源限该服务。引用中的数据源不可删除。修改或停用数据源会阻止进行中的批次继续读取，新批次使用新版本；批次保留执行时的配置快照。

## 计划与调度

一个计划配置多条规则，查询返回的每条记录是一个检查对象。规则支持必填、等于指定值、字段比较、数值范围及数组通配路径；不执行用户提供的 Python 或 Shell 表达式。数字等值规则使用十进制比较，兼容数据库返回的数字文本。

| `schedule_kind` | 行为 |
| --- | --- |
| `interval` | 启用后首次到期执行，此后按 `interval_seconds` 调度 |
| `cron` | 五字段数字 Cron：分、时、日、月、周；支持 `*`、列表、范围、步长，默认时区 `Asia/Shanghai` |
| `once` | 在带时区的 `scheduled_at` 执行一次，入队后清空下次时间 |
| `manual` | 仅手动执行，`next_run_at=null` |
| `event` | 由持有运行权限的调用方通过触发接口执行，`next_run_at=null` |

所有启用计划均支持手动执行和扫描触发。同一计划只允许一个活跃批次，重复触发返回现有活跃批次；编辑、暂停、删除继续核对 `expected_version`。事件入口不自动订阅其他业务系统。

`timeout_seconds` 为执行总时限，10–3600 秒；排队时间不计入。数据获取失败可按 `max_retries=0..3` 重试，退避为 5、10、15 秒，已保存结果不重复插入；业务规则不通过不会重试。HTTP 单请求 10 秒，数据库查询沿用 5 秒上限，单对象 Agent 时限不超过 60 秒及计划剩余时间。

`max_records=1..10000` 控制批次范围。达到上限且仍有数据时，批次为 `partial`，保留游标供下批继续；手动计划需再次手动或触发执行。`max_agent_items=1..200` 限定分析对象数，未分析对象在详情中显示状态。

## 结果语义

- `checks` 保存实际值、期望值、规则依据和逐项状态；`rule_verdict=pass/fail/unknown` 单独持久化。
- `agent_status`、`agent_result` 单独保存 Skill 分析、引用、资料缺口和分析错误。Agent 不修改规则结果。
- `final_status`：有规则时采用规则健康状态；仅 Agent 检查时采用其结构化结论。旧 `verdict` 继续保存“与原判定是否一致”的兼容信息，不作为新页面的业务健康状态。
- 规则不通过是对象异常，批次仍可 `completed`。数据获取失败、规则执行错误、Agent 分析失败、超时分别使用 `error_stage=collection/rule/agent/timeout`。
- 规则已完成而 Agent 失败时，执行状态仍为完成，界面明确显示“检查已完成，智能分析失败”。Agent-only 失败时显示未得出结论，不显示正常。
- 去重范围改为本批次的对象编号和版本。跨批次重复读取同一版本也保留新观察，历史批次不会因为全局去重而空白。
- 批次详情按现存未删除对象计算 `summary.health_counts`、`objects`；原执行汇总、证据和复核记录保留。总览 `issues_total` 统计规则未通过的对象记录。

## 接口

路径前缀均为 `/api/v1`，分页返回数组及 `X-Total-Count`。

| 方法与路径 | 用途 |
| --- | --- |
| GET / POST `/inspection-data-sources` | 查询／新增数据源，支持 `search`、`kind`、分页 |
| GET / PUT / DELETE `/inspection-data-sources/{id}` | 详情／版本校验更新／引用保护软删除 |
| POST `/inspection-data-sources/{id}/test` | 实际读取验证，返回 `success`、`error_code`、`records_read` |
| GET `/inspection-data-sources/{id}/plans` | 分页查看引用计划 |
| GET `/inspection-plans`、GET `/inspection-plans/{id}` | 搜索／启停筛选、最近结果、上次和下次时间及详情 |
| POST `/inspection-plans/{id}/runs` | 立即执行，返回新建或正在进行的执行记录 |
| POST `/inspection-plans/{id}/trigger` | 请求体 `{kind: "event"}` 或 `{kind: "scan"}` |
| GET `/inspection-runs` | 按 `plan_id`、`search`、`status` 分页查询批次 |
| GET `/inspection-runs/{id}/items` | 按 `search`、`result=pass/fail/unknown` 服务端筛选与分页 |

沿用 `inspections:read/manage/run/review` 权限、资源范围限制、取消和人工复核接口。数据源变更、测试和删除均追加操作审计。

任务暂停时，停止定时、事件和扫描触发。具有执行权限的用户仍可点击“立即执行”，按任务现有配置执行一轮；本次执行不恢复调度。试运行快照不能通过此接口执行正式巡检。

## 页面

`/inspections/plans` 使用计划表格；创建／编辑抽屉分为“基本信息、数据与检查项、调度与执行”。`/inspections/plans/{id}` 展示配置、检查项和最近五次执行。

`/inspections` 默认显示执行批次；`/inspections/runs/{id}` 为独立详情，顶部展示时间与结果，中部仅列对象名称、状态和一句说明。对象搜索、筛选、分页直接请求后端，不预加载全部证据。点击对象才加载详情抽屉，分别查看实际数据、规则判断、Agent 分析和人工复核，技术信息默认折叠。

`/inspections/sources` 集中管理数据源及引用计划，数据库连接编辑复用原组件。页面保持现有深色主题，不再使用原来的侧栏加结果工作区。

测试使用独立 `_test` 数据库。覆盖连接认证与加密、MySQL/PostgreSQL 只读查询、300 对象分页、规则及 Agent-only/组合结果、真实 Harness 与本机隔离 Provider 的三个工具调用、定时与事件触发、失败重试、总超时、资源权限、历史查询和迁移保留。隔离 Provider 验证不等于真实外部模型服务联调。

## 需要语义理解的检查

Agent 检查适用于答复是否符合业务政策、材料描述是否相互矛盾、上下文是否满足适用条件等判断。任务应提供待判断的文本、相关上下文和业务依据；Skill 明确正常、异常和资料不足的标准。字段非空、状态码与明确数值条件仍由规则检查承担。

同一对象的规则与 Agent 各自判定。规则通过而 Agent 发现语义矛盾时汇总为异常；语义依据不足为 unknown，模型执行失败为未完成，不视为正常。现有工作响应快照任务没有问答正文，转换为独立检查后仍不评价问答正确性。
