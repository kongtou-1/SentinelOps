## 唯一异常

第三条问答 `432e4a6b-1ecf-4e59-ae6d-0b15229f8b3c`，执行 `1b13024e-6d3d-4d71-b0d3-bdeb835771da`，检查 `8792633f-bc0c-417e-a53a-e9d8ac33e288`：

1. Agent 读取 Skill、当前对象、授权接口，并运行 Python 核验。
2. 首次回写把 `evidence_ids` 放进 QA 的 `result`，接口拒绝，工具记录 `inspection_api_http_error`。QA 回写结构仅接受 `status`、`summary`、`details`。
3. Agent 自行去掉多余字段，12:27:17 回写成功，返回 `updated=1`、`checked=true`、结论 `pass`。
4. 后续未出现平台 `submit_inspection_result` 成功轨迹，12:27:39 平台记录 `provider_unavailable`，该项最终 `error/unknown`、该轮 `partial`。现有证据不能进一步区分外部 Provider 的具体失败原因。

这暴露了 QA 回写成功与平台最终判定之间的中断窗口：QA 已被标记检查完成，后续 `checked=false` 轮询不再选择它，平台判定仍为未知。此次实测保留原始错误，没有手工补写平台成功、重置 QA 或追加重跑，也没有改动生产巡检实现。
