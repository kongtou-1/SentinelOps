# Docker 服务视图

> 本文记录最初的容器视图。当前资源中心已按“服务器 → 业务服务 → Docker 容器”调整，业务用途、归属和聚合展示以[业务服务分层调整](业务服务分层调整.md)为准。

## 实施范围

以“服务器 → 多个 Docker 服务”为入口，先支持同一台服务器内的依赖维护。沿用现有多服务器资产，通过服务器选择切换视图；不新增部署、执行或自动修复权限。

原实现已有 cAdvisor 容器清单、资源指标和 Docker 状态采集，但资源中心缺少服务语义及关系展示。本次补齐：

1. 服务卡片：服务名称、用途备注、容器与镜像、实际运行状态、健康检查、状态采样时间、CPU 和内存。
2. 人工依赖：在同服务器内选择依赖服务，箭头从使用方指向依赖方。允许真实存在的相互依赖；禁止依赖自身、跨服务器或已退役容器。
3. 网络归属：只读采集 Docker Engine `/containers/json` 中的网络名称，不读取环境变量或新增 Engine 操作。共享网络提供连接条件，不能证明真实调用或实际可达，host/none 模式也不代表服务互通。[Docker 网络说明](https://docs.docker.com/engine/network/drivers/bridge/)
4. CPU 和内存环形图：以整台服务器容量为分母，列出各容器、系统及其他占用、剩余资源，中心显示主机已用比例。CPU 将容器消耗的核心时间除以主机核心数，避免多核下比例失真；内存采用 cAdvisor 工作集。[cAdvisor 指标说明](https://github.com/google/cadvisor/blob/master/docs/storage/prometheus.md)
5. 卡片分页，每页 9 个；资源图和依赖图仍基于该服务器完整资产。服务名称和用途也可通过原容器清单搜索。

## 数据与接口

`0017_container_services` 仅向 `containers` 增加 `service_name`、`purpose`、`depends_on`，不新增表。保留原有带时区的 `created_at`、`updated_at`、`deleted_at` 及更新时间行为；容器同步不会覆盖人工备注与依赖。备注绑定当前容器资产，重建后产生新 Docker ID 的容器需要重新维护。

- `PUT /api/v1/containers/{id}/service`：编辑名称、用途和依赖；沿用 `resources:manage`，当前仅 Admin。
- `GET /api/v1/servers/{id}/container-overview`：完整资产及当前观测；沿用 `resources:read`，Viewer、Operator、Admin 均可查看。

概览使用固定 9 次只读 Prometheus 查询，不逐容器发请求；数据限定服务器及采集配置版本，并检查采样新鲜度、采集器与 Docker Engine 状态。暂停监控时不查询；单项缺失不会导致整页失败。原始资源数据不写入业务数据库。

运行状态与最近清单状态分别展示，缺失或过期显示“未知”，不把无数据变成停止或零占用。网络库存标记区分“已采集但无网络”与“尚未采集”。资源图保留未知服务占用的提示；主机分母缺失或容器合计明显超过主机已用量时不绘制误导图表。

## 使用入口

- 资源中心 → 服务器 / Docker 容器：选择服务器，查看服务、关系和资源分布。
- 服务器详情：查看该服务器完整的 Docker 服务视图，替换原先只显示前 10 个关联容器的表格。
- 容器详情：查看所在服务器的服务关系并编辑用途。
- Admin 点击“编辑用途与依赖”，填写业务可读名称、用途和依赖后保存。

已将关闭的 Docker 轮转日志归档到 `.local/docker-rotated-logs-20261015`，释放约 55 MB；未删除数据库、数据卷或容器。后端 Dockerfile 只调整工作目录权限，避免每次改代码时递归修改整个 Python 环境、重复生成大体积镜像层。恢复后镜像构建、非 root 启动和隔离 Linux 权限检查均通过；该权限调整步骤从约 113 秒降至 0.5 秒。
