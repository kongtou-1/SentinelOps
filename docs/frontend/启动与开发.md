# 前端启动与开发

智能问数阶段 2 开放 `/askdata/catalog`（数据目录）、`/askdata/models`（业务模型）和 `/askdata/settings`（问数设置），权限均为 `askdata:read`；构建、编辑、认证与复核按钮按 `askdata:manage` 显示，后端仍独立核验。数据库连接复用已有 ServiceDatabases 组件；问数开关由 `askdata:manage` 控制，连接编辑与测试继续使用原管理权限。设置列表从 `/askdata/settings/connections` 读取，连接 CRUD 与结构刷新使用既有接口；主外键来自结构缓存，旧缓存未含主键信息时显示“未获取”。

三个页面共用 `features/askdata/api.ts` 与 `VersionPicker` 选择连接和模型版本。设置页的“语义构建”标签按需加载，展示版本状态、构建步骤、失败原因、结果计数，并支持发起、取消、重新构建、启用和停用；活动构建期间轮询刷新。数据目录展示库表字段、主外键、说明和授权范围内的样本值；业务模型提供术语与指标的查看、编辑、认证、关系图谱、版本对比和待复核处理，图谱使用 ECharts `graph`。

`api:types` 从 `docs/backend/openapi.json` 生成 TypeScript 类型。后端路由/模型变更后，先重新导出 `app.openapi()`，再生成类型并运行检查。

代码目录与新增文件放置见[前端代码组织](代码组织.md)，协作约定见 `frontend/AGENTS.md`。

主控制台的栏目切换统一使用侧栏或顶部主导航，页面内不再重复资源类型、相关功能及巡检栏目导航。页面标题与内容分卡展示；系统状态、Agent 配置、通知与维护、数据管理及详情页保留实际功能分区，统一使用内容卡片内的下划线 Tab。`page-tabs` 用于独立内容卡片，已有卡片内的 Tab 使用 `workspace-tabs`；抽屉和编辑表单的局部 Tab 保持原有交互。

智能巡检的任务列表、执行记录、连接管理、详情及创建／编辑任务页均不再渲染重复的栏目 Tab；“巡检任务 / 执行记录 / 连接管理”统一从主导航切换。任务编辑页的步骤条及详情内的业务分区保留。

巡检各页统一使用 `page-header`、`page-heading` 和 `actions`，沿用全局标题卡片尺寸、标题字号和操作区布局。效果评价的标题与操作区固定在页面内容首位，“最近 30 天”统计放在标题下方。

2026-10-30 验证：巡检、路由与运维 API 共 128 项测试通过；Docker 内类型检查和生产构建通过。仅更新本机前端容器，健康检查及页面资源请求通过。浏览器工具因无法可靠识别当前 URL 中止，尚未完成目视验收。

主控制台所有列表、详情与巡检任务编辑页已移除标题区域的指标卡，不再发起标题统计专用请求；正文中的监控图表、统计和业务信息保留。历史实现与修订记录见[页面标题关键指标](页面标题关键指标.md)。

页面只保留一处栏目标题；列表不重复页头名称，详情页 Tab 内不再重复同名标题。预测中心移除任务选择框前的冗余标签，选择框保留占位与无障碍名称。列表及分组移除额外的总条数、当前页提示和数量角标；分页仅保留页码、上一页／下一页、原有每页数量与跳页控件。总量数据继续用于计算页数，筛选、翻页及导出逻辑不变。图表、预测质量和检查结果等业务分区保留各自标题。

页面标题卡片统一最小高度 64px、水平内边距 20px、垂直内边距 14px，标题字号 20px；窄屏使用 18px 标题、16px 水平内边距和 12px 垂直内边距。标题说明小字继续隐藏，操作按钮靠右；含返回入口、多行标题或换行操作时由内容自然撑高。标题与页签卡片占满内容区宽度；普通内容卡片和独立页签卡片的内边距维持 20px，窄屏下为 16px。

服务器与容器列表的手动刷新统一位于页头，同时刷新列表和服务／容器区域。服务器页通过一个“新增”菜单选择“新增服务器”或“新建服务”；容器页在页头保留一个“新建服务”入口。内嵌服务组件不重复显示刷新与新建按钮，服务器选择、容器筛选及同步操作保留；服务器详情里的独立服务组件维持原有操作入口。

角色与权限 `/roles` 默认只读，权限勾选不可更改。管理员点击“编辑默认权限”后才显示“取消／保存默认权限”；取消恢复已保存的权限，保存成功后返回查看状态。非管理员不展示编辑入口。保存确认、版本校验和后端管理员限制维持原有行为。

权限申请与授权页中，管理员的“待审批”排在首位且默认选中。“资源策略”提供“按资源查看”和“按角色查看”：资源视图按资源类型、名称及管理对象展示分页列表，支持单项设置和勾选当前页资源后批量保存；角色视图先选择运维人员或查看者及具体资源，再按用户名筛选该角色的启用用户，支持逐个或勾选当前页用户批量禁止、取消禁止。角色只用于筛选，设置保存到具体选中用户，不建立角色规则，也不自动影响以后加入该角色的用户。切换视图、资源、角色或分页后清空勾选。

用户的“禁止访问”覆盖已有授权，“不单独禁止”仅取消该用户的直接禁止。所有非管理员的“需单独授权”使角色默认权限及全局补充授权对该资源失效，具体资源的补充授权仍有效。应用、服务器的限制包含下属资源；解除直接限制不等于获得权限，上级资源限制仍然生效。批量操作逐项核验版本并记录审计，部分失败时显示完成数量及各项错误，不自动重试写请求。

执行动作目录采用表格展示中文动作名、适用对象、风险等级、执行授权和版本。点击动作名称或“查看详情”打开抽屉，分区查看用途与影响、执行前检查、恢复验证与回滚情况；原始技术定义默认折叠。目录仅展示已注册的固定动作，审批与人工发起仍沿用现有流程。

告警事件、事故记录、预测结果、执行记录及审计日志提供“导出 CSV”，巡检记录提供批次汇总导出，批次详情另提供对象结果导出。导出读取点击时的筛选条件并遍历全部分页，不受当前页大小限制；预测导出保留所选任务及 1／6／24 小时各自的结论与首次预计超限时间。文件采用带 BOM 的 UTF-8、中文列名和已选定的业务字段，文本公式字符会转义，可直接用 Excel 打开。空结果提示无可导出记录，任意分页失败不生成部分文件，离开页面取消未完成导出。所有读取继续使用认证请求和已有后端资源权限；不导出凭据、原始证据 JSON、模型上下文或审计排查信息。

工作台入口为 [http://127.0.0.1:8080](http://127.0.0.1:8080)。登录使用已有用户名；初始管理员凭据保存在本机 `.local/admin-credentials.txt`。令牌仅保存在当前标签页的 sessionStorage，退出后清除；不放入 URL 或下载链接。

8080 为默认端口；本机 `.env` 已设置 `FRONTEND_PORT=18088`，实际入口为 [http://127.0.0.1:18088](http://127.0.0.1:18088)。Windows 出现端口访问被拒绝时，用 `netsh interface ipv4 show excludedportrange protocol=tcp` 检查保留端口，改用可绑定的本机端口后重建前端容器。

## 本机 Compose

基础环境及模型准备见项目 README。已有服务可执行：

```powershell
docker compose build backend frontend
docker compose --profile monitoring --profile ai --profile execution --profile reports --profile local-test up -d --wait
```

Nginx 前端默认仅监听 `127.0.0.1:8080`，通过 `FRONTEND_PORT` 调整本机端口。`/api/`、`/health/` 转发至 backend:8000；其他业务路径回退 index.html，详情直达和刷新均可用。前端容器有独立健康检查。前端 build 阶段使用 Node 22.22.1、pnpm 11.19.0 和冻结的锁文件，运行阶段使用 Nginx 1.28 Alpine。

## 前端开发与检查

安装 Node 22（Vite 要求至少 22.12），使用 package.json 指定的 pnpm 版本：

```powershell
cd frontend
corepack enable
corepack prepare pnpm@11.19.0 --activate
pnpm install --frozen-lockfile
pnpm dev
```

Vite 在 [http://127.0.0.1:5173](http://127.0.0.1:5173) 提供开发页面，代理现有本机 API 的 8000 端口；无需改成跨域或将访问令牌嵌入配置。

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm api:types
```

`api:types` 从 `docs/backend/openapi.json` 生成 TypeScript 类型。后端路由/模型变更后，先重新导出 `app.openapi()`，再生成类型并运行检查。页面按路由加载，图表只使用同一指标的单位；LLM 比例显示为百分比，延迟为秒，容器 CPU 可超过 100%。缺失采样保持空值并展示原因。

总览及监控每 30 秒刷新。旧版诊断、执行、报告和知识索引按 2–10 秒退避查询，任务完成后停止；页面隐藏、离开页面时停止。报告编辑使用独立草稿及 `expected_revision`，版本冲突保留未保存输入，需人工核对后再编辑。刷新页面通过后端详情、历史和投递记录恢复任务进度。

轮询条件变化会取消或恢复定时查询：打开编辑弹窗时暂停，关闭后按原间隔继续；已结束的异步任务仍保持停止。报告、采集配置和修复交接下载统一使用认证请求，令牌刷新后仍被拒绝时清理会话并返回登录页。

知识有效期列表按文档、Skill 的顺序合并分页，默认每页 20 条，可切换为 50 或 100 条并跳转页码。列表使用现有接口的 `offset`、`limit` 和总数，只读取当前页所需记录；刷新和保存有效期后保留当前页，切换每页条数回到首页，记录减少导致当前页超出范围时回到末页。

预测中心按任务选择，每个任务只显示一项，选项不受下方结果表分页及筛选影响。主图在同一时间轴展示最近 24 小时实测、历史预测及最新批次的未来预测，可切换 1h / 6h / 24h 预测范围并缩放时间轴。历史预测在每个时间点采用该点之前已完成的最近批次，不使用事后结果回填，也不混合不同容器实例或采集配置的数据；悬停可查看预测生成时间。当前范围的预测质量、模型、生成时间、数据截至时间及样本质量直接展示在本页，图表下方不设详情跳转。历史批次在下方预测记录中查看，任务配置通过顶部“预测任务”进入。顶部刷新同时更新任务及曲线。

总览分别显示容器运行、服务主动监测和 Docker 检查，只展示状态，通过应用名称进入详情。Admin 在应用详情“服务监测”或容器详情“主动监测”中添加监测，无须重建目标容器；容器页固定绑定当前容器，应用页统一管理全部规则。未关联服务的容器先通过“关联服务”入口确定归属。Docker 检查未配置不改变容器运行状态。详见[业务服务分层调整](业务服务分层调整.md)。若 `/api/v1/service-monitors` 返回 404，应核对后端镜像与迁移是否包含已有的 `0022_service_observability`，升级前备份数据库。

主动监测的最近结果保存在平台数据库，耗时与成功率历史还依赖 Prometheus 的 `service-probe` 采集任务。若检测正常而曲线无数据，应检查运行中的配置及实际挂载路径；本机曾挂载旧项目目录，2026-10-18 已切换到当前项目配置并补齐该任务。曲线只包含启用采集后的样本，无法补回此前未采集的历史。真实业务请求图另需服务开放指标端点、配置真实流量采集和对应业务路由；就绪探测请求不计入真实业务流量。

应用详情默认进入“应用主页”，集中显示源码、发布及部署资料，业务用途放在顶部服务信息区。“使用的 LLM 服务”位于“服务监测 → LLM 服务”独立标签，顶部统一刷新同时更新当前标签的数据。`view=monitoring` 保留监测页位置，既有 `monitor` 参数链接直接进入监测页。

LLM 服务列表按当前筛选和分页，为本页每个服务分别展示状态卡片；卡片直接标明服务名称、模型和 API 地址，不再通过下拉选择单个服务。端点详情使用相同身份信息。每张卡片仅查询对应端点，分别展示近 30 分钟探测成功率、总次数、成功次数，以及 60 格时间条（每格 30 秒）。绿色为全部成功、黄色为部分失败、红色为全部失败、灰色为无记录；悬停或键盘聚焦可查看对应区间和次数。状态每 30 秒刷新，页面隐藏时暂停；卡片标注“主动探测”，不将探测请求标为真实用户流量。统计复用已持久化的探测用量记录，无记录显示“—”；查询失败显示错误，不沿用上次成功数据。列表不再展示或查询平均延迟、P95 延迟及分类错误率三张趋势图；端点详情保留原有指标查询入口。服务列表为空时直接显示空状态，不生成无所属服务的统计卡片。

“Agent 智能巡检”分为巡检计划 `/inspections/plans`、巡检记录 `/inspections`、数据源 `/inspections/sources`。计划采用表格和分区编辑抽屉，点击名称进入独立计划详情；记录默认按执行批次展示，点击批次进入独立执行详情。对象列表只显示名称、状态和一句说明，搜索、状态筛选和分页均在后端执行；点击对象才加载实际数据、规则依据、Agent 分析和复核抽屉，不一次拉取全部对象证据。

新增或编辑 LLM 服务时，可在“Key 来源”选择已启用的 Agent 模型通道，或填写独立 Key。选择通道会带入 API 基础地址和默认模型；关联通道轮换 Key 后，下次探测直接使用新 Key。部署更新需应用数据库迁移 `0043_llm_agent_channel`。

计划详情的“关联服务”可点击服务名称进入对应服务详情 `/applications/:id`；未关联服务时显示“独立巡检”。

巡检记录列表支持由具备 `inspections:manage` 权限的用户删除已结束的单次执行，确认后软删除该批次及其对象结果，保留巡检计划及其他批次。运行中的记录需先进入详情停止执行。删除当前页最后一条时返回上一页，并刷新列表总数。

巡检任务列表与详情都提供“立即执行”和“暂停任务／启用任务”。暂停期间仍可立即执行一轮，任务保持暂停；进行中的巡检会继续。运行详情的“停止执行”只取消本轮，后续定时安排保留。操作先确认任务名称和影响，提交时防止重复提交；取消确认不发送写请求。

关键操作统一提供确认交互：手动运行预测、停止巡检或诊断、采用正式诊断、申请执行审批、事故接单、生成复盘、撤回申请、Agent 和数据库连接启停、角色默认权限变更、自动诊断及通知邮件启停、真实模型通道测试、发送测试邮件、重建知识索引、源码同步、建立整改任务、资源审核发布及删除等。已有审批意见、发送收件人、合并事故等专用表单弹窗的操作沿用该确认步骤，不叠加弹窗。查询、刷新、筛选、读取数据、普通编辑保存与聊天发送不增加确认。

“数据源管理”通过“API”“数据库查询”“已接入数据库”三个页签直接展示各自列表，按钮分别为“新增API”“新增数据库查询”“接入数据库”。API 和数据库查询从各自入口创建，不再在新增表单里切换类型；API 配置页签为“接口地址与请求设置”，数据库查询为“选择数据表与字段”。新增默认允许巡检任务使用，不展示“启用”开关；编辑已有配置时通过“允许巡检任务使用”明确选择允许或禁止。列表区分使用权限与取数测试结果，提供测试取数、预览数据与关联任务入口。已有认证只显示已配置状态；旧共享 HTTP API 编辑后保存为独立配置，保留有效认证且不影响其他 API。

“接入数据库”填写已有数据库的地址与只读账号，不创建实际数据库。表单分为“数据库地址与账号”“数据表与字段”“允许读取的数据”，新增时不展示连接启用开关，停止／恢复使用保留在列表操作中。先保存数据库，再获取数据表与字段、勾选允许读取的字段并保存授权；未授权业务数据时显示“仅表名和字段名”，授权后显示“已选表和字段”。只读权限核验、凭据加密和敏感字段限制保持原有规则。列表允许具备读取权限的用户查看，接入和修改仍需资源管理权限；关联服务可选。

巡检任务列表使用表格逐行展示任务名称、关联服务、环境、执行方式、状态、下次执行与最近结果，移除服务／环境分组卡片及规则／Agent 数量；任务和最近结果分别进入详情与执行报告。创建任务时明确选择从 API 或数据库获取检查对象，并提供两个对应新增入口。计划支持间隔、五字段 Cron、固定时间、手动和事件触发，并配置超时、采集失败重试和每批 1–10000 个对象。启停、编辑、删除继续使用原有权限与版本校验。

任务详情仅保留“概览”“检查内容”“执行历史”。“检查内容”展示数据来源、检查要求、方法名称、可调用的 API／数据库查询，以及规则的通过要求和判断依据；补充输入按字段和值展示，不再输出整份任务 JSON。方法与数据来源沿用各自读取权限，无法读取时明确显示状态。旧版任务按实际规则和智能检查配置展示，不修改已保存的判定方式。“删除任务”位于顶部“更多”菜单，继续保留删除确认与版本核验。执行历史一行代表一次正式执行，点击“查看检查结果”进入对应报告，不在任务页混排所有对象与单项结果。

Agent 历史结果查询中，统一检查任务只列出真正完成的 Agent 检查项，不把对象的“全部检查通过”等汇总再次计作 Agent 结果；旧版独立 Agent 分析结果仍保留。一次执行可检查多个对象或检查项，因此结果条数与执行次数不要求相等。此修复不删除历史结果或改变巡检结论。

对象正常／异常采用独立规则结果，Agent 分析失败不改变规则状态，界面明确显示“检查已完成，智能分析失败”。仅 Agent 检查失败时显示尚未得出结论。规则不通过与批次执行失败分开；跨批次保留同一对象的新观察。删除仍为软删除；批次详情按未删除对象统计，历史证据和复核保留。

页面组件位于 `features/inspections/pages/`，计划、数据源编辑和对象详情抽屉位于 `components/`。当前模型、接口、调度、迁移及验证方式见[巡检中心](../backend/巡检中心.md)。

总览顶部以紧凑统计行展示相同的六项巡检全局统计，桌面六列、中等屏幕三列、窄屏两列，不再嵌套高统计卡片。复用 `/inspections/summary`，随总览每 30 秒刷新，顶部“刷新数据”同时更新。统计区及“查看巡检”入口仅对有 `inspections:read` 权限的用户显示，无权限时不请求巡检接口。加载失败时显示告警，数值显示为“—”；接口返回的真实零值正常显示为 0。导航与页面标题统一为“总览”。

“权限管理”单独列为导航分组，包含“我的权限”和管理员可见的“角色与权限”。应用页“编辑服务与源码连接”与服务器、容器页共用系统用户负责人选择框；不允许自由创建姓名，已有历史负责人可保留、替换或清空。

管理员在“权限申请与授权 → 资源策略”默认管理指定用户：选择用户与资源，设置“禁止访问”或“跟随原有权限”后保存；页面显示已保存策略和实际查看状态。所有非管理员的统一普通／受限策略通过“生效范围”切换。加载失败时不能保存，切换用户或资源不会沿用旧策略；保存确认明确列出用户与资源，保存期间锁定选择。后端需完成 `0039_user_resource_policies`，并同步升级业务 worker。

表单必填字段通过 Element Plus 的必填标记在标签前显示红色 `*`。自定义表单与通用记录表单采用同一方式；密码、API Key 按新增/编辑状态区分，SSH 主机公钥按是否绑定凭据区分，其他条件必填项跟随当前配置。权限申请禁选已拥有的权限，并按每个所选资源排除重复申请。说明与验证见[表单必填与权限申请调整](表单必填与权限申请调整.md)。

诊断工作台使用认证 SSE 展示实时模型请求、只读工具、接收回执和回复；隐藏页面时断开订阅，回来按序号重连。事故诊断采用个人会话和手动采用方式，旧诊断继续可读。[工作台启动、API 与复验说明](AI诊断工作台.md)。

异步接口的 202 只表示排队，SSH 测试和 LLM 探测必须检查响应里的 success，执行及投递必须等待真实终态。网络失败不会自动重试写操作；同一投递请求的幂等键保留供重试。操作按钮按 `/me.permissions` 控制，后端仍执行权限和状态校验。

“我的待办”打开内容时自动标为已读，也可使用“标为已读”按钮；后端确认成功后立即刷新顶部未读角标，未读数为 0 时隐藏数字。角标仍每 30 秒检查新增待办，页面隐藏时暂停、恢复可见时刷新。

预测中心下方的历史记录跟随顶部选中的任务，切换任务会重置页码，状态和时间筛选仍保留；重置筛选不清除选中的任务。任务选择写入 `task_id` 查询参数，刷新及浏览器前进后退均恢复选择。列表直接展示预测对象名称、运行时的任务名称及指标、预测时间、未来 1 / 6 / 24 小时风险和首次预计超限时间，不再将结果 UUID 或任务 UUID 作为主列。对象关联按每次运行的配置快照读取，名称不可用时保留预测记录并明确标记。对象与任务合为一列，三个时段的相同结论合并展示，不同结论及不同超限时间逐项保留。运行状态、数据是否足够及结果时效明确区分；数据不足不显示为正常风险，初步预测与区间可信度不足也保留独立状态。“时效内”只表示时间和配置检查通过，不等同于预测质量通过。

预测详情按“预测结论、曲线、数据质量、残差异常、历史缺口、后续观测对照”排列。顶部明确区分运行结束、结果时效与预测可用性；采样完整但全部时段历史不足时显示“历史不足，暂无法预测”。质量摘要合并有效样本与总数，以两行展示；“当前连续段缺失率”与被排除的历史缺口分开，短历史直接显示分钟。历史缺口按最近优先、每页 5 条展示起止时间、持续时长及缺失采样点，持续时长按表中起止时间差计算；残差异常每页 10 条，标准化偏差和平滑偏差放在展开行，无记录时显示紧凑空态。后续观测对照仍直接展示三个窗口，不加分页。缺失字段显示“—”，不当作零值。

## 权限开发与验收
