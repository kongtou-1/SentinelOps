# 独立多源巡检实施与验收

2026-10-25。基于既有[自动只读业务巡检](自动只读业务巡检实施与验收.md)扩展，已部署本机。入口：[Agent巡检](http://127.0.0.1:18088/inspections)。

## 配置与完整链路

「巡检计划」可不选关联服务，`application_id=null`。计划保存环境、自动间隔、回查范围、数据源、关联关系、确定性规则、可选 Skill 和预算。Skill 负责 Agent 的业务审查指引；连接凭据、数据关联和调度仍由平台控制。独立计划只能选择全局 Skill，服务限定的 Skill 仍绑定相应服务。

数据库连接沿用现有「服务详情 → 数据库」登记、结构刷新和表/字段授权；独立计划可明确选择同环境的已授权连接，无需绑定该服务。当前没有新增独立的数据库连接管理页。关联服务的计划继续限制连接属于该服务。

2026-10-26 表单调整：巡检频率和回查范围使用分钟、小时、天的常用选项，也支持自定义数值及单位；接口继续保存秒数，旧计划的秒数原样恢复。每轮检查上限提供常用条数，也可输入 1–200 条。

数据库字段不再预填 `id`、`updated_at`；选项仅包含已授权且存在于最近刷新表结构中的列，切换连接或表时清空字段映射。对象唯一标识必须明确选择已有主键或唯一业务编号；检查数据字段明确授权本轮读取内容。版本、更新时间、原结论列均可不配置，不要求修改接入库表结构。没有版本列时，以实际读取字段内容计算版本；没有时间列时，不使用回查窗口，按对象标识分页扫描，达到每轮上限后下一轮继续，完成一遍后重新扫描，相同内容去重。证据分别标记 `version_basis=content_hash`、`time_basis=query_time`，后者为实际查询时间。原结论未配置时保留 unknown。主源和关联源采用相同的可选字段语义；API 接入协议保持不变。

链路为：到期调度 → 冻结计划/Skill/数据库授权 → 分页读取主对象 → 按关联字段查询资料 → 组合并检查 → 可选 Agent 评审 → 持久化对象结论 → 人工复核。复用原有 Harness 和模型网关，独立巡检 worker 执行，没有新增多 Agent 架构。

| 平台表 | 保存内容 |
| --- | --- |
| `inspection_plans` | 数据接入、关联、规则、调度、预算与当前版本 |
| `inspection_runs` | 冻结配置、窗口、进度、汇总及错误 |
| `inspection_items` | 每个对象的组合版本、原结论、资料快照、逐项检查、最终结论和 Agent 状态 |
| `inspection_reviews` | 只追加的人工复核意见 |

所有表保留 UTC 创建、更新和删除时间。业务系统只接受 GET/受控 SELECT；写入的是平台的巡检记录。

## 多源关联

一个主源负责枚举对象，最多四个关联源分别选择 API 或数据库；支持一对一和一对多。主源任意事实字段或对象 ID 与关联源字段等值匹配，各源可有不同连接和凭据。源别名使用小写字母、数字、下划线，`main` 保留给主源。

例如封面来自 API，内页来自数据库：

```json
{
  "application_id": null,
  "related_sources": [{
    "name": "pages",
    "source_kind": "database",
    "source_config": {
      "connection_id": "已授权连接 UUID",
      "table": "public.certificate_pages",
      "id_column": "id",
      "version_column": "version",
      "time_column": "updated_at",
      "fact_columns": ["certificate_id", "instrument", "error", "unit"]
    },
    "main_field": "",
    "match_field": "certificate_id",
    "cardinality": "many",
    "required": true,
    "max_records": 20
  }]
}
```

上例为关联部分，完整请求还需主源和规则等字段。`main_field` 为空表示主记录 ID；一对一返回多条、必需资料缺失、关联键不符、查询失败或超限均记录资料问题，不输出“依据支持”。错误关联的记录不混入本对象。非必需源可为空，但引用其缺失字段的规则仍无法评估。

主 API 沿用 `updated_after`、`updated_before`、`limit`、`cursor` 枚举协议。关联 API 使用固定地址 GET，参数为 `match_field`、`match_value`、`limit`、`cursor`，不添加时间过滤；返回同样的 `{items, next_cursor}`，每项须含 `id`、`version`、带时区 `updated_at`、`facts`，其中 `facts` 含匹配字段。不能直接接入任意响应形状，业务 API 需提供此只读协议或适配接口。数据库关联由平台生成经过字段白名单检查和字面值转义的等值 SELECT，不接受任意 SQL。

认证请求头加密保存，响应只暴露是否配置。相同地址编辑留空保留，`{}` 清除；更换 URL 不复用旧认证。运行中在读取前后和保存前重查授权，网络读取期间不持有计划行锁，暂停和撤权可及时生效。

## 规则、变化检测与结果

多源事实分别放在 `main`、`pages` 等路径。必填、固定值比较、Decimal 数值范围继续可用；新增字段比较及数组展开：

| 检查 | 配置示例 |
| --- | --- |
| 每个检测点的数值 | `kind=numeric_range`，`path=pages.*.error`，`unit_path=pages.*.unit` |
| 内页与封面仪器一致 | `kind=field_equals`，`path=pages.*.instrument`，`compare_path=main.instrument` |

数值限值和依据版本由计划明确指定，不自动推导适用计量规程。数组检查落为 `pages.0.error` 等具体路径，保存实际值、期望值/范围、单位、状态和依据。空值、单位不符或缺失字段不会当作通过。

组合版本覆盖主源及关联源的身份、版本、事实内容和资料问题。多源计划每轮重查配置回查范围内的主对象，关联源单独变化也可产生新检查记录；单源仍按原水位增量。该机制只覆盖回查窗口中的主对象，主对象已超出窗口时，需要业务源更新主对象版本/时间或扩大回查范围，当前不提供跨库变更订阅。

预算沿用每轮最多 200 个主对象，新增每对象最多四个关联源、每源最多 50 条明细、组合证据 32 KiB、数组展开最多 1000 项检查。关联 API 翻页受总超时限制；达到预算保留明确的无法评估状态。Agent 每轮最多 20 项，超出评审预算显示未完成，不能宣称全部对象已由模型复核。

页面默认进入「巡检结果」，可按对象 ID、计划和结论查询。默认按「计划 + 对象 ID」选择最新记录后筛选结论，关闭“仅最新”查看历史。详情展示冻结计划/Skill 版本、源地址或表、每份资料 ID/版本/时间及逐项检查，保留原始证据折叠区和追加复核入口。

结果含义：`supported` 为配置规则支持原业务结论；`contradicted` 为规则与原结论矛盾；`unassessable` 为证据或规则不足；`needs_review` 为需进一步复核。批次 completed 只表示本轮完成。
