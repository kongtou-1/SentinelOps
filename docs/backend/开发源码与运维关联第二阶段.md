# 开发源码与运维关联：第二阶段

本阶段将第一阶段的服务、发布、部署和源码快照接入现有 AI 诊断。两种入口（事故直接分析和私有会话）均支持。修复交接、修改代码和发布操作留在第三阶段。

## 本轮版本如何确定

创建诊断任务时，按每条关联告警的目标和 `starts_at` 查找有效部署区间 `[started_at, ended_at)`，保存本轮 `source_context`。支持平台容器 UUID、同服务器的完整 cAdvisor `id`/Docker `docker_id`、预测告警冻结的容器目标和 LLM Endpoint。容器名、镜像标签或同服务器其他容器不能单独授权源码读取。

上下文保存告警时间、服务、发布、部署、环境、配置版本、登记时的镜像关联依据、服务入口、路径映射、变更说明、测试声明、允许的快照和缺口。只访问已经准备好的快照；不会等待 Git、SVN、宿主目录或 source-worker。创建任务以后就绪的资料只能由下一轮使用。

选择顺序：

1. 发布明确关联且已就绪的源码快照。
2. 发布没有可用快照时，该服务已就绪的其他快照，标为参考源码、版本未核验。
3. 同一服务、同一目标上一次部署的快照，用于差异比较；不宣称它是已验证正常版本。
4. 无源码时，继续使用发布说明、测试声明及原有运行证据。

本地目录始终标为参考源码。固定 Git commit / SVN revision、构建源码声明和镜像身份核对分别表达不同依据，不能相互替代。旧告警不会因为后来部署新版本而改读新版本源码；服务软删除也不改写已冻结的历史上下文。

主机级告警只展示当时部署的服务候选，不认定某个服务是故障来源，也不自动授权候选源码。告警对象或部署缺失、部署冲突时明确保留缺口。现有运行诊断仍可检查同服务器容器，源码权限不随这个范围扩大。

## 四个只读工具

以下工具由真实 Harness 经现有受控 MCP 提供，没有新增任意命令执行或 Git 网络权限。

| 工具 | 参数 | 返回范围 |
| --- | --- | --- |
| `list_source_tree` | `snapshot_id`，可选相对 `path` | 最多 100 个文件元数据，可按目录缩小范围 |
| `search_source` | `snapshot_id`、`query`，可选相对 `path` | 字面搜索，扫描最多 10 MiB，最多 50 条，每条带路径、行号和片段哈希 |
| `read_source_file` | `snapshot_id`，相对 `path` 或 `runtime_path`，可选起止行 | 每次最多 200 行，运行路径使用冻结的部署映射 |
| `compare_source_snapshots` | `snapshot_id`、`other_id`，可选相对 `path` | 同服务版本比较，最多 100 个文件变化或 400 行文件差异 |

工具仅接受本轮上下文允许的快照；比较的两个版本必须属于同一服务。路径越界和快照越权被拒绝。源码、注释、文档与变更说明作为不可信证据，不能改变系统指令或扩大工具权限。

源码证据带快照 ID、Git commit 或 SVN revision、内容哈希、路径和行号；文件、搜索片段和差异附带最终脱敏片段哈希。读文件时沿用快照文件哈希检查。缺文件、存储不可用、哈希异常、映射缺失和输出超限返回结构化缺口，不设置诊断阻断状态。不可用结果不能当作诊断事实引用。

源码上下文最多 64 KiB；工具单次输出沿用 128 KiB 预算。超过限制直接降级并记录原因。模型请求、调用数和超时继续沿用原有预算。

## 多轮、采用和复盘

诊断复用指纹包含源码上下文。新快照就绪或关联资料改变后，普通分析请求不会复用资料过时的结果。

多轮继承时核对冻结上下文和快照身份；不一致的源码证据、包含旧源码上下文的事故证据及依赖这些证据的候选结论不作为本轮有效引用。用户历史聊天仍是陈述，不是已核验事实。

后端把源码缺口合并到 `Diagnosis.data_gaps`，不依赖模型自行声明。人工采用时再次校验引用，正式分析复制本轮上下文和被引用的证据，不公开整段私有聊天。新生成的复盘冻结正式分析的源码上下文和证据；已有复盘快照不改写。旧诊断的上下文字段为空，明确显示未记录，不根据当前部署补写过去的证据。

工作台“诊断与证据”显示本轮开发资料、版本说明和缺口。事故详情显示正式采用的资料；文件按钮打开诊断时保存的片段、行号和哈希，不重新读取当前文件。Viewer 可查看公开证据；私有会话仍执行 owner/Admin 原有规则。

## 部署

升级前备份业务库并保留独立解密主密钥。构建后运行迁移 `0014_diagnosis_sources`，再启动服务。此迁移仅向 `agent_analyses`、`analysis_runs` 增加非空 JSON `source_context`，默认 `{}`；两表原有 UTC 时间字段、软删除和更新时间触发器保持。

```powershell
docker compose build backend frontend
docker compose run --rm migrate
docker compose --profile ai --profile sources up -d --wait backend frontend ai-worker source-worker
```

`ai-worker` 新增源码持久卷只读挂载，API 同样只读，只有 source-worker 写入。AI worker 不依赖 source-worker 的启动或健康状态；仍需按原工作台文档配置 Provider 才能实际运行推理。普通应用登记和已有源码浏览不要求启用 AI。

需要本机目录同步时沿用[第一阶段的可选挂载配置](开发源码与运维关联第一阶段.md)。源码快照与数据库应一并备份；数据库里的已保存诊断片段在源码卷不可用时仍可查看。

验证结果见[第二阶段验收记录](开发源码与运维关联第二阶段验收.md)。真实 DeepSeek 和外部私有仓库继续单独联调；本地模拟 Provider 通过只代表集成链路通过。
