# 智能问数阶段七复核与自有库实测

日期：2026-11-07。目标是核查已部署实现、修复实际问题，并在自有 `ops_platform` 数据库上验证真实模型问数。本报告区分确定性回归与真实模型结果。

## 修复内容

| 问题 | 修复与验证 |
| --- | --- |
| 上游返回英文 SQL 说明，没有中文结果结论 | 对非中文说明，直接从最终执行并脱敏的结果生成中文摘要，不增加模型调用；空集、NULL、部分结果和截断状态均明确标记，不从 SQL 说明猜测数值 |
| 结果页将 `query_time` 时间戳标为“查询耗时”并显示原始 UTC | 标签改为“查询时间”，使用已有本地时间格式化 |
| 模型将连接 ID 作为三段式 SQL 的数据库前缀，合法选表仍被 gate 拒绝 | 连接器解析 SQL，仅移除与自身 ID 精确相同的逻辑路由前缀，再执行原有权限校验；其它数据库前缀继续拒绝，覆盖普通查询与最终结果查询 |
| 检索线程持有 Connection 直到整题结束，多轮候选检索耗尽共享连接池 | 改为线程独立 Session，在显式事务外读写完成后结束事务并归还连接；显式事务继续保持原子性，失败回滚。单连接池回归验证读后可用、事务内保持占用、提交后释放 |
| 多表候选读取使用 `represents.union(via_attribute)`，被平台当成非 SELECT 拒绝，候选丢失后模型反复修正 SQL | `OntologyStore` 支持 SQLAlchemy `CompoundSelect`，每个分支继续限定模型版本与软删除；真实 PostgreSQL 回归验证其它版本数据不可读 |
| 目录集合 reset 清除整个模型版本的所有向量 | 清理限定到当前版本和当前集合，采用软删除；重建 upsert 恢复该行，不影响语义／代码向量和其它版本 |
| 只要存在任意向量就可能把缺少检索索引的构建判为完成 | 分别核验目录与语义集合，代码规则向量不能替代语义编译向量 |
| 构建关系探测仍走诊断用窄 SQL 方言，`UNION ALL`／子查询探测被跳过 | 仅将问数构建连接器切换到完整问数只读 gate；保留权限校验、授权列、连接锁、超时和结果限额，诊断与巡检入口不变 |
| 链式多批次 INSERT 只保留第一批 | 合并全部命名行批次，逐行注入版本；真实 PostgreSQL 测试覆盖多批次 upsert |
| 仓储中的提交回调违反事务分层，且先提交再复核授权 | 构建专用提交适配放在 integration 层，仓储只执行语句并复核授权；通过后再按事务深度提交 |
| 人工表说明已保存，但构建未消费 | 在授权连接器的元数据副本中合并表说明，送入目录、向量及语义编译；不修改原始结构缓存 |
| DeepSeek 的轻量角色没有关闭默认思考模式，结构化描述调用也进入高成本思考 | 仅对 DeepSeek 官方端点的 `non_reasoning` 角色显式传入 `thinking.type=disabled`；推理角色和其它兼容端点保留原设置，单测覆盖三种情况。参数依据 [DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/) |
| 冒烟脚本硬编码管理员／数据库口令并打印登录响应 | 凭据改由环境变量或本地 JSON 读取，登录令牌不写日志；临时 Viewer 使用随机口令并清理，不能因同名而覆盖其它连接，也不能清理复用的既有连接 |
| 阶段五模型变更未同步元数据契约 | 仅补齐阶段五八张新表和两张变更表的契约，没有放宽分层或模型检查 |
| 版本与对话时间直接截取 UTC 字符串，启用版本仍显示“可启用” | 使用平台已有本地时间格式化；启用版本显示“当前启用” |

## 自有库范围与保护

用户明确选择 `ops_platform`，并批准创建验收后删除的临时只读账号。账号只获得下列五表共 49 个字段的列级 SELECT 权限，未授予 INSERT／UPDATE／DELETE、表所有权或管理权限；默认只读事务，语句超时 5 秒。

| 表 | 测试前未删除记录数 | 本轮范围 |
| --- | ---: | --- |
| `inspection_plans` | 1 | 标识、名称、环境、启停、时间 |
| `inspection_runs` | 30 | 关联标识、状态、触发方式、采集量、调用次数、时间 |
| `inspection_items` | 6 | 关联标识、规则／综合判定、处理状态、时间 |
| `inspection_check_results` | 9 | 关联标识、检查与执行状态、严重级别、时间 |
| `inspection_reviews` | 0 | 关联标识、复核结论、时间 |

未读取证据正文、检查结果 JSON、账号、口令、密钥、HTTP 头或源码配置。本轮没有向上述业务表插入样例数据，没有业务库迁移。正常问数产生的连接、模型版本、会话、运行与用量属于平台功能记录。

验收确认 `transaction_read_only=on`、写权限为 false、`inspection_items.evidence` 的 SELECT 权限为 false。问数直接复用本机现有模型通道，没有复制模型凭据到其它实例。

## 验证方法

1. 真实 API 注册限定字段的连接，刷新结构并核验只读权限。
2. 真实 worker 完成目录、向量与业务语义构建，发布验收版本。
3. 六个独立会话分别提交总量、状态分组、采集／调用求和、任务与运行关联、检查状态与级别分组、规则判定分组问题。
4. 每题用人工编写的独立 SQL、同一只读账号查询实际数据库；核对模型最终执行结果，并检查前后参考值稳定。
5. 核对结果 CSV，并在浏览器检查连接测试、授权字段、目录、版本状态、问数结果及聚合统计。
6. 完成后停用临时连接、撤销列级授权并删除临时账号。

首轮实测揭示 `CompoundSelect` 不被接受的问题。发现后主动取消两条运行及四条排队验收请求，保留日志并修复；取消记录不作为模型准确率统计。

第二次重建在真实模型端出现 503／饱和重试，并暴露轻量角色未关闭思考模式的问题；主动取消该次构建，修复角色参数后重新构建。该次取消不计入查询评分。

随后一轮六题有四题通过，两题失败；日志显示逻辑连接前缀被拒与检索连接池耗尽。保留原始失败报告，修复后复用已构建的模型，用相同六道问题重新完整验证，没有向模型提供参考 SQL 或结果。
