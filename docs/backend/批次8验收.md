## 实现与部署

- 升级前业务库备份为 `.local/backups/batch8-before.dump`，88,172 字节。数据库改为 `pgvector/pgvector:0.8.7-pg17-bookworm`，保留 PostgreSQL 17 原数据卷；扩展版本 0.8.7。
- 迁移 `0008_ai_knowledge` 新增 knowledge_documents、knowledge_chunks、knowledge_skills、agent_analyses。全库十九张表，包括 Alembic 维护表，均含三个 UTC 带时区时间字段及更新时间触发器。普通查询排除软删除记录，分析历史无修改、删除接口。
- uv 锁定 deepseek-harness-sdk 及运行时 0.1.5rc1、FastEmbed 0.8.1、pgvector 0.5.0、MCP 2.2.0。MCP 使用该版本实际 Server 回调接口。
- 中文向量使用 BAAI/bge-small-zh-v1.5，固定 Qdrant ONNX 制品修订 `46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59`。显式准备模型及 SHA256 清单，运行时校验并只读加载，512 维 CPU 推理，无自动下载。
- 文本/Markdown 按标题、段落分片，最多 400 tokens，重叠 50；pgvector 余弦精确检索默认前五片，支持标签过滤。修改立即撤下旧片段，新索引原子发布；失败可重试，旧引用的内容和版本保存在分析快照。
- 独立 ai-worker 使用 PostgreSQL advisory lock 保证单并发，领取索引及分析任务。重启将 running 分析记为 interrupted，未完成索引重新排队；不自动重试推理。
- 四个初始 SOP 已安装且文档索引均 ready：disk_full、memory_oom、container_unavailable、llm_errors。
- 事故分析限定 open/in_progress/recovered，每个事故最多一个 queued/running；五分钟内输入未变的成功结果可复用，force=true 新建。结束前复查事故状态、发起人权限、引用及资产参数。
- 专用 sdk-minimal profile 关闭 Shell、文件修改、插件管理、子 Agent、额外日志上传。实际模型工具清单严格匹配十项 MCP 白名单；本地服务仅监听容器回环随机端口，短期令牌绑定分析与资源范围，不发布端口。
- Harness 子进程使用独立临时目录和白名单环境，只得到短期网关令牌。真实 Provider Key 留在 worker 网关，数据库、JWT、SSH 凭据不传给子进程。输入、工具证据、调用记录和结果在模型及持久化边界脱敏。
- 最多 12 次工具调用、总超时默认 180 秒；超时终止运行时进程树。SSH 只允许资产中解析出的 64 位容器 ID，固定 inspect/logs 命令与主机密钥验证，日志最多最近 15 分钟、200 行、16 KiB，执行超时 10 秒。
- 仅支持 restart_container 版本 1 的描述与参数校验，risk=medium、requires_human_approval=true、executable=false，没有执行命令或执行接口。

接口、权限、配置、模型准备和启动命令见 README 的“第八批次”。Viewer 可读取；Operator/Admin 发起分析；Admin 管理文档及 Knowledge Skill。AI 默认关闭，缺少配置返回明确 503。
