# 监控增强首批验收

完成日期：2026-10-11（Asia/Shanghai）。实现范围与部署方法见 [监控增强说明](监控增强说明.md)。

## 实施结果

- 服务器列表与总览摘要改为每页一次请求，1/50/100 台服务器均至多 6 次后端 Prometheus 请求；包含当前采集配置、采集器状态、采样时间及失败原因。单项查询失败隔离，真实 0 与未知分开。
- 服务器详情提供四步接入检查和采集器 Compose 下载，覆盖 node_exporter、cAdvisor、可选 docker-state 与平台侧 HTTP 探测。
- docker-state 持续输出健康状态，独立于重启/OOM 的完整五分钟窗口。新增固定 `container_unhealthy` 告警指标，沿用告警、事故与恢复证据链。
- 容器详情增加健康状态、固定 State 与近期日志抽屉。只读权限限定 Operator/Admin，继续复用固定命令、SSH 公钥固定校验、最近 15 分钟/200 行/16 KiB 限制及脱敏。
- 历史查询保留无效点、按步长补 null；派生速率与抓取状态关联。图表区分暂停、未配置、无数据、过期与真实零值；多序列默认显示六条并允许人工选择。
- 恢复检查的一半有界名额用于最近结束的可核验事件及其重试，其余名额继续处理历史队列。
- 无新增业务表或数据库迁移；原始指标仍保留在 Prometheus，35 天保留策略不变。
