## 自动运行机制

Admin 配置业务服务、环境、数据源、检查规则、可选 Skill 和预算，显式启用后自动运行，无需逐轮人工发起。新计划默认暂停。

- `operations-worker` 检查到期计划并持久化入队；独立 `inspection-worker` 读取、检查和评审，共享原有 Harness 和模型网关，不占用事故诊断 worker。
- 计划行锁及活动批次唯一索引阻止同计划重叠。错过多个周期只生成一个到期批次，不补排每个错过的周期。
- 间隔 60 秒至 7 天，首次回查 60 秒至 30 天，每轮最多 200 条、每页最多 50 条。正常完成后按水位增量读取，并固定重叠回查最近 300 秒。
- 超过记录预算时保存未完成窗口和游标，下轮继续同一窗口。记录按计划版本、业务 ID 和记录版本去重；资料或判定变化必须产生新版本。
- Agent 每项最多 60 秒，每轮最多 20 项，优先评审程序发现矛盾或无法评估的记录。中断的模型请求不自动重复；超预算保留未评审状态，批次显示部分完成。
- 暂停、删除、修改计划、停用服务、撤销配置人 Admin 权限、变更 Skill/数据库授权后，后续读取、工具调用、模型请求和结果保存均重新校验。已发出的请求由原超时结束。

平台保存计划、进度、结果、复核和审计。“只读”指被检查的业务系统：只开放固定 GET 与受控 SELECT，没有业务写请求、改判、修复或 Shell 工具。

## 模块与边界

迁移 `0032_business_inspections` 新建 `inspection_plans`、`inspection_runs`、`inspection_items`、`inspection_reviews`，均有 UTC 创建/更新时间、删除时间及更新时间触发器。计划软删除，人工复核只追加。

`app/services/inspections/` 中，`plans.py` 管理计划与授权，`sources.py` 接入证据，`checkers.py` 执行程序检查，`agent.py` 适配共享 Harness，`runtime.py` 推进批次。数据库操作位于 `app/repositories/inspections.py`。

迁移加入 `business_inspection` 和 `metrology_certificate_review` 两个指引型 Skill；已有同编码内容不覆盖。首版使用全局或绑定当前服务、未限定应用发布版本的 Skill。计划固定 Skill 版本，Skill 变更后重新保存计划。

首版程序检查包含必填、相等、含边界数值范围，可指定取绝对值和单位字段，使用 Decimal 比较。单位不同、数值无效或字段无法读取时记为无法评估，不自动换算或猜测。

计划规则均视为当前数据集的必需条件：任一明确失败形成 fail，全部明确通过形成 pass，其余为 unknown，再对照原业务结论。混合仪器/规则数据应先通过业务 API 按适用范围组织，不能把某一仪器的固定限值用于整张混合业务表。

Skill 不增加权限、不执行脚本、不覆盖程序矛盾。新业务可复用相同外层协议、任务和复核界面；新计算语义通过注册检查器实现，不开放任意公式执行。未实现任意扫描 PDF OCR、完整计量规程自动编码或自动改判。

## API 接入协议

配置业务方确认只读的固定地址，例如 `https://business.example/inspection/records`；不含凭据、查询参数或 fragment，不跟随重定向。认证请求头加密保存，响应只返回是否配置；编辑时留空保留，填 `{}` 清除。首版不提供自动登录或 Token 刷新，源端应提供持续可用的只读凭据。

平台向同一地址发送 GET，参数为：

| 参数 | 约定 |
| --- | --- |
| `updated_after` | 带时区 ISO 8601 起点，包含起点 |
| `updated_before` | 带时区 ISO 8601 终点，不包含终点 |
| `limit` | 本页最多记录数，源端不能超出 |
| `cursor` | 续页时提供的不透明字符串，不是下一页 URL |

返回结构如下，样例不代表真实计量规程：

```json
{
  "items": [
    {
      "id": "certificate-001/item-01/point-01/attempt-01",
      "version": "3",
      "updated_at": "2026-10-23T10:00:00Z",
      "facts": {"error": "0.04", "unit": "mm"},
      "original_verdict": "pass",
      "evidence": [{"page": 2, "cell": "B4", "text": "源系统提供的内页原文片段"}]
    }
  ],
  "next_cursor": null
}
```

`id` 应区分业务对象、分项和核验尝试；`version` 随资料或结论变化。`facts` 保持业务自己的结构，`original_verdict` 为 pass/fail/unknown。只返回已完成的业务核验任务。

单条上限 32 KiB，响应上限 2 MiB，单次读取上限 10 秒。时间越界、超量、重复游标或无效数据使本轮失败，水位不推进。源端需保证稳定分页；延迟提交超过 300 秒不在自动重叠窗口的保证范围，应通过新计划或保存新版本的首次回查范围重新检查。

原始文件保留在业务系统中，首版使用已提供的结构化事实和原文片段/位置，不自行下载任意附件，也不把原 Agent 的识别表格当作独立原文。

## 数据库接入

先按[服务级只读数据库接入](服务级只读数据库接入.md)登记、刷新结构、核验账号及授权字段。选择同服务、同环境的连接和普通表，指定稳定 ID、版本、更新时间、原判定及事实字段。

查询由平台生成，按 `(更新时间, ID)` 分页并限定冻结时间窗，每次核验已有只读账号和授权版本。视图、用户函数、跨库和自由输入 SQL 均不开放。原判定值可配置 pass/fail 映射，其他值归为 unknown；嵌套 JSON 或复杂内页证据建议通过 API 提供。

优先使用 PostgreSQL timestamptz。MySQL TIMESTAMP 按会话 UTC 解释；其他无时区字段默认拒绝，仅在业务明确确认原值就是 UTC 时启用「无时区时间为 UTC」。本轮真实数据库验证为 PostgreSQL；MySQL 复用已有适配层，新增巡检链路尚未真实实测。

## 权限与结果

| 角色 | 权限 |
| --- | --- |
| Viewer | 查看计划、批次、结果和复核 |
| Operator | 查看、运行已启用计划、停止本轮、追加复核 |
| Admin | 上述权限，加配置、启停和软删除计划 |

批次有 queued/collecting/evaluating/completed/partial/failed/cancelled 状态。completed 仅说明工作完成，不代表业务健康；逐项结果仍可为发现矛盾或无法评估。停止本轮不等于暂停计划。

自动结果为依据支持、发现矛盾、待复核、无法评估。人工独立记录确认误拒、确认漏检、原判定正确、资料不足，不改写原自动证据。

## 接口

统一加 `/api/v1`，完整字段见 [OpenAPI](openapi.json)。

| 方法和路径 | 用途 |
| --- | --- |
| GET `/inspections/summary` | 全局巡检次数、去重检查记录、矛盾记录、覆盖服务、启用计划和进行中批次汇总，沿用 `inspections:read` |
| GET/POST `/inspection-plans` | 查询、创建 |
| PUT/DELETE `/inspection-plans/{id}` | 版本校验后修改、软删除 |
| PUT `/inspection-plans/{id}/state` | 版本校验后启停；暂停不依赖源端可用 |
| POST `/inspection-plans/{id}/runs` | 立即运行，有活动批次时返回原批次 |
| GET `/inspection-runs`、`/inspection-runs/{id}` | 列表、详情 |
| POST `/inspection-runs/{id}/cancel` | 停止本轮 |
| GET `/inspection-runs/{id}/items` | 分页结果，可按 verdict 筛选 |
| GET/POST `/inspection-items/{id}/reviews` | 查询、追加复核 |

`InspectionSummary` 的 `runs_total` 包含所有未删除批次，`runs_active` 包含 queued/collecting/evaluating；`items_total` 与 `issues_total` 分别统计未删除批次中的未删除检查记录、其中 verdict 为 contradicted 的记录。`services_covered` 按未删除计划关联的未删除服务去重（包含暂停计划），`plans_enabled` 为这些服务下启用的计划数。统计不受列表分页或筛选影响，删除计划不抹去已保存批次和证据的累计数。
