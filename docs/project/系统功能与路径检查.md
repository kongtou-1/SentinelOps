# 系统功能与路径检查

检查日期：2026-10-22。范围为当前仓库源码、本机 Compose、独立测试库和浏览器。当前工作台入口为 <http://127.0.0.1:18088>。

## 功能与使用路径

系统主线是：登记资源与服务 → 采集和主动监测 → 告警/预测 → 事故 → 只读诊断与人工采用 → 申请审批 → Admin 审批 → 人工发起受控执行 → 恢复核验 → 关闭事故 → 生成、编辑、审核和导出复盘。

| 功能 | 页面入口 | 业务路径与边界 | 本轮检查 |
| --- | --- | --- | --- |
| 登录与权限 | `/login` | 登录后读取角色权限；会话刷新和失效返回登录 | 三角色接口矩阵、路由守卫和浏览器拒绝越权通过 |
| 运维总览 | `/` | 聚合服务、资源、告警、事故、待审批和预测风险 | 页面和聚合接口通过；缺少监测时保留未知状态 |
| 服务器和容器 | `/servers`、`/containers` 及详情 | 登记主机 → 接入检查 → 同步容器 → 关联业务服务 → 指标/日志下钻 | 页面、资源接口、监控测试通过；未对业务容器注入故障 |
| 应用、源码与版本 | `/applications` 及详情 | 登记服务 → 配置源码 → 同步快照 → 发布/部署绑定 → 诊断证据 → 修复交接和人工验证 | Git/本地源码、版本冻结、交接相关测试通过；SVN 三项未运行 |
| 服务与数据库监测 | 应用详情的服务监测、数据库标签 | 配置监测 → 测试/保存 → 历史趋势；数据库连接 → 结构读取 → 表/字段授权 → 受控只读查询 | 主动监测测试通过；独立 PostgreSQL/MySQL 真实连接验收通过 |
| LLM 服务 | `/llm-endpoints` 及详情 | 维护 Endpoint → 手动或定期探测 → 分类故障告警 → 服务归属 | 本地模拟 Provider 的接口与探测测试通过 |
| 预测 | `/prediction-tasks`、`/predictions` 及详情 | 创建任务（默认停用）→ 选择资源/序列 → 运行 → 结果/曲线 → 风险告警 | 任务、算法、时间线、指标隔离测试通过；长期真实预测效果另行评估 |
| 告警与事故 | `/alert-rules`、`/alerts`、`/incidents` 及详情 | 保存并显式应用规则 → 接收告警 → 聚合事故 → 确认/分派/处理 → 恢复核验 → 关闭 | 接口、状态、并发、合并和普通/强制关闭测试通过 |
| AI 诊断 | `/incidents/:id/diagnosis`、事故详情 | 个人会话 → 只读工具和 SSE → 人工采用；后台分析历史继续可读 | 工作台页面、真实 Harness/MCP 与本地模拟模型测试通过 |
| 审批与执行 | `/approvals`、`/executions`、`/action-skills` 及详情 | 已采用结论 → 固定动作提案 → 持久化审批 → Admin 批准 → 人工执行 → 前置检查和验证 | 绑定、权限、到期、幂等、异常及 worker 恢复测试通过；本轮未重启真实业务容器 |
| 复盘 | `/reports` 及详情 | 关闭事故 → 冻结证据 → 生成草稿 → 修订 → Admin 审核 → 导出；邮件由 Admin 显式发起 | 报告、修订冲突、证据引用、导出和投递状态测试通过；未发送外部邮件 |
| 知识与 Skill | `/knowledge`、`/knowledge/search`、`/skills` 及详情 | 知识索引/检索；诊断按需加载版本化 Skill | 页面、索引、检索、版本和权限测试通过 |
| 系统管理 | `/users`、`/roles`、`/ssh-credentials`、`/audit-logs`、`/system` | Admin 管理账号和凭据；Operator 可查看系统状态；审计只追加 | 页面、角色矩阵、账号撤权、凭据脱敏测试通过 |
| 资源市场与介绍 | `/discover/*`、`/project-intro` | 投稿 → 审核 → 发布；项目介绍使用独立布局 | 四个市场主入口、介绍页和市场后端测试通过 |

告警、事故和审批分别记录事实、处理过程和执行授权。AI 诊断、预测完成或审批通过都不会自动触发受控执行。

## 已修复和优化

| 问题 | 修改 | 验证 |
| --- | --- | --- |
| Windows 保留端口段包含 8080；容器内部健康但宿主机访问被拒绝 | 仅修改本机 `.env` 的 `FRONTEND_PORT=18088` 并重建前端容器 | 网页、静态资源、深层链接回退和经 Nginx 的 `/health/ready` 均返回 200 |
| 轮询在编辑期间仍可能触发，暂停后也不会随弹窗关闭恢复 | 公共 `usePoll` 在挂载后监听调度间隔；条件变化取消或恢复定时器，卸载清理监听 | 新增暂停/恢复、卸载及延迟初始化回归；浏览器复查服务器和容器页通过 |
| 下载请求独立处理认证，刷新后再次收到 401 时未执行统一会话失效处理 | 下载复用 `authorizedFetch`，保留认证 Blob 下载 | 新增下载持续 401 回归；不向 URL 写入令牌 |
| “新建事件”“导出审计”只是禁用占位按钮 | 从列表页移除两个无法操作的入口 | 菜单、详情和生产构建通过；事故仍从告警聚合生成 |
| MySQL 初始化临时 socket 使健康检查过早成功，随后真实 TCP 连接失败 | 独立数据库验收 Compose 改用 TCP 健康检查 | 冷启动重建 MySQL 后，58 项真实数据库验收通过 |
| 数据库完整性测试清单漏了 `service_databases` | 将已有表补入检查清单，继续核验它的 UTC 时间字段和更新触发器 | 后端基础与结构检查 41 项通过 |
| README 固定写入历史机器绝对路径 | 改为从当前仓库根目录执行，同步说明本机端口 | 与当前目录及运行入口一致 |

未修改业务接口、模型或审批执行权限；无需数据库迁移和重新生成 OpenAPI 类型。

## 验证边界与后续改进

- 本轮未复验真实远程服务器部署、外部 DeepSeek 推理质量、外部 SMTP 投递和长期预测效果。现有测试分别使用受控适配器、本地模拟模型或冻结证据，不能据此声称外部链路全部通过。
- 三项 SVN CLI/HTTPS 集成因本机缺少 `svn`、`svnadmin`、Apache 和 `htpasswd` 跳过。Git 和本地源码链路已测试。
- 综合健康评分、SLA/批量派单、双人复核和复盘改进任务跟踪仍是占位展示，未计入已实现闭环；本轮未新增这些功能。
- 后续可优先清理剩余占位模块，并在明确评分规则、派单流程和改进任务状态模型后单独实施，避免展示项与真实业务能力混淆。
