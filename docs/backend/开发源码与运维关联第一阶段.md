# 开发源码与运维关联：第一阶段

本阶段建立服务、源码、发布和部署之间的关系，提供只读源码浏览。AI 源码工具、事故轮次冻结和修复交接属于后续阶段，当前诊断仍使用原有工具。

实现及验证结果见[第一阶段验收记录](开发源码与运维关联第一阶段验收.md)。

## 服务与代码对应

每个可独立运行的服务登记一条 Application，包含稳定服务标识、入口、主要源码目录和运行路径映射。同一仓库和镜像可以供多个服务使用；部署记录按具体容器或 LLM Endpoint 分别保存。同一 Git URL、SVN URL 或同一已配置本地目录的服务可显式复用已有快照，发布版本与部署记录仍分别登记。服务软删除不删除历史快照内容。

本项目的示例关系：

| 服务 | 入口 | 主要源码目录 |
| --- | --- | --- |
| backend | app.main:app | backend/app |
| ai-worker | app.workers.ai | backend/app |
| prediction-worker | app.workers.predictions | backend/app |
| execution-worker | app.workers.executions | backend/app |
| report-worker | app.workers.reports | backend/app |
| frontend | Nginx 静态文件 | frontend/src |

后端路径映射可登记 `/app/app → backend/app`、`/app/migrations → backend/migrations`。路径相对于快照根，主要目录用于定位，并不裁掉仓库中的共享代码和文档。前端原始源码通过版本关联；当前未提供 source map 时不能精确还原压缩 JS 堆栈。

Release 固定版本、源码快照或预期 Git commit / SVN revision，以及 config image ID / RepoDigest。两类镜像标识分开保存。Deployment 固定目标、环境、时间、配置版本、服务入口、路径映射及登记时观测依据。结束部署后可登记新版本；重叠实例绑定被拒绝，历史记录不会因当前镜像变化而改写。

`verified` 只表示发布 image ID 与新鲜运行观测一致。构建源码关联另有开发者登记依据；本地目录始终显示为参考源码，不把目录当前内容当作过去部署的证明。

## 启动与目录挂载

源码 worker 与 API 使用同一后端镜像，通过 PostgreSQL 领取任务。基础 API/AI worker 不依赖源码 worker。API 只读源码卷，源码 worker 可写；凭据使用现有独立主密钥加密。

升级前备份业务库和独立主密钥，再构建和迁移。以下命令在项目根目录执行：

```powershell
docker compose build backend frontend
docker compose run --rm migrate
docker compose run --rm prepare-volumes
docker compose --profile sources up -d --wait backend frontend source-worker
```

启用本机目录读取时，指定一个真实存在的宿主目录，并使用可选覆盖文件：

```powershell
$env:SOURCE_INPUT_ROOT='D:/research/contest'
docker compose -f compose.yaml -f compose.sources-local.yaml --profile sources up -d --wait backend frontend source-worker
```

服务中填写 `local_path=.` 表示挂载入口本身，填写 `project-a` 表示入口下的子目录。接口不接受任意宿主绝对路径。目录缺失只影响可选源码 worker；移除本地覆盖文件即可按基础方式启动，核心服务不会等待目录或 Git。

只读挂载仍可能被宿主修改，所以同步会复制快照、保留文件哈希与内容哈希，读取时校验内容。排除 `.git`、`.svn`、依赖、缓存、运行数据和常见凭据文件；文本脱敏后存储。二进制、非 UTF-8、符号链接、子模块和 LFS 缺失会列出说明。

默认 Git 同步 120 秒，本地后备捕获额外最多 30 秒；快照最多 100 MiB、10,000 文件、单文件 2 MiB，单仓库缓存 1 GiB，总存储预留上限 5 GiB。达到限制会返回缺口或失败状态，保留已有快照。可通过 `SOURCE_*` 配置调整；企业 CA 可配置 `SOURCE_GIT_CA_FILE`，Docker 内须另行只读挂载该证书，始终执行 TLS 校验。

## 使用流程与接口

Admin 可在资源中心 → 服务器的新建、编辑服务表单中直接配置代码仓库、分支、源码目录、启动入口、路径映射和只读令牌；服务信息、源码连接与本机容器归属一次保存。应用与服务页的“编辑服务与源码连接”操作同一条 Application，两个入口共用源码表单。连接加载失败时阻止提交并允许重试，避免覆盖已有配置。

服务创建与编辑接口可传可选的 `source_connection` 对象；省略时保留原源码配置。Git 令牌加密保存，编辑留空保留；更换仓库地址或 Git 用户名且未提供新令牌时清除旧令牌。只读响应和审计不包含令牌。

源码同步、发布与部署记录仍在应用详情页维护。保存仓库地址不自动认定容器运行的是该仓库当前分支。Operator/Admin 发起同步；所有角色可只读查看源码。私有诊断会话仍遵守原有 owner/Admin 规则。

Git 分支/tag 在同步时解析成完整 commit。后续预期 commit 已在缓存中时可离线捕获。Git 无法使用时，自动尝试已配置的本地目录；两者都缺失时任务记录失败原因，API 和现有诊断不受影响。相同同步请求复用排队任务，不同 commit 分别排队。

### SVN 接入

服务源码表单选择 SVN，填写 `svn_url`（HTTPS 仓库、trunk、branches 或 tags 下的具体目录）、`svn_revision`（默认 `HEAD`，也可填写数字版本号）以及可选的 `svn_username`、`svn_password`。Git 与 SVN 二选一，两者都可配置本地后备目录。公开仓库无需密码；私有仓库使用只读账号。密码加密保存，编辑留空保留；更换地址或用户名且未提供新密码时清除旧密码，也可用 `clear_svn_password` 显式移除。

同步使用 SVN 1.14+ 命令行客户端，Docker 后端镜像已声明安装 `subversion`；宿主直接运行源码 worker 时须自行提供该客户端。先将 HEAD 解析为数字 revision，再以同一 operative/peg revision 执行只读 `list`、`proplist`、`cat`，不创建工作副本、不拉取 `svn:externals`、不执行仓库代码。密码通过标准输入传给客户端，不放入 URL、进程参数或认证缓存。TLS 始终校验，企业 CA 可设置 `SOURCE_SVN_CA_FILE` 并只读挂载对应 PEM 文件。

SVN 使用与 Git 相同的同步时限、文件数、文件大小和快照容量限制；自动同步失败时尝试本地后备，显式 `source=svn` 则直接报告失败。SVN 不维护离线仓库缓存，已完成的快照可离线浏览；获取新快照需要仓库可达。SVN 符号链接及外部引用记录为缺口，`.svn` 不进入任何来源的快照。

`SyncInput` 支持 `source=auto/git/svn/local`，SVN 可传 `expected_revision`。`SnapshotResponse.svn_revision` 保存实际数字版本，`git_commit` 保持为空。发布可填写 `expected_revision`，或在创建时从选定 SVN 快照带入；关联快照时校验版本，不能把本地后备当作该 revision 的证明。部署与诊断证据保留 SVN revision 和内容哈希。固定 SVN revision 只证明所读取的源码版本，构建来源仍为 `declared`，不标为 `clean_git`。

SVN 升级包含迁移 `0023_svn_sources`。备份数据库与独立主密钥后，按上面的构建、迁移命令更新镜像和数据库，并重建 backend、source-worker 及使用后端模型的其他 worker。迁移仅为现有表增加连接和版本字段，不改写已有部署或诊断证据。实际验收使用本地 HTTPS SVN（公开/私有认证、独立 CA），不代表用户的真实外部仓库已经联调。

| 方法与路径（前缀 `/api/v1`） | 功能 |
| --- | --- |
| GET/POST /applications；GET/PUT/DELETE /applications/{id} | 服务与来源管理，删除采用软删除 |
| POST /applications/{id}/source-syncs | 异步同步，source 为 auto/git/svn/local；Git 可传 expected_commit，SVN 可传 expected_revision |
| GET /applications/{id}/snapshots；GET /source-snapshots/{id} | 分页记录与任务状态 |
| GET /source-snapshots/{id}/tree、file、search、diff | 目录、按行读取、字面搜索、同服务快照比较 |
| GET /applications/{id}/resolve-source-path | 运行路径按已登记规则映射，找不到时返回缺口 |
| GET/POST /applications/{id}/releases | 发布登记；允许源码缺失 |
| POST /application-releases/{id}/attach-snapshot?snapshot_id=… | 就绪后手工关联，已有快照不可替换 |
| GET/POST /applications/{id}/deployments | 登记和查询实际部署历史 |
| POST /application-deployments/{id}/end | 结束实例绑定，保留历史 |
| GET /containers/{id}/deployments | 服务、发布与历史/当前镜像核验情况 |

文件读取每次最多 200 行；搜索最多扫描 10 MiB 并返回 50 条；单文件差异最多 400 行。读取失败返回 `availability=unavailable` 和原因，不把路径或网络资源缺失变成核心服务错误。

私有 Git 使用 HTTPS 用户名和只读令牌。令牌只通过受控 Git 凭据助手传给指定 HTTPS 主机，不放入 URL、进程参数、Git 缓存或接口输出。保存令牌后留空表示保留；更换仓库地址/用户名会清除旧令牌。

生成发布登记 JSON（不会构建、推送或部署）：

```powershell
& ./.tools/uv.exe run --project backend --frozen python backend/scripts/make_release_manifest.py --source . --image sentinelops-backend:local --version v1 --output .local/release-v1.json
```

可在发布页导入 JSON，核对说明和测试结果后保存。脚本只有在目录干净且镜像 revision 与 commit 一致时标记 `clean_git`，否则只登记声明。目录有未提交改动时不把 HEAD 当作完整构建源码。

容器身份来自 docker-state 的白名单 `docker_container_identity_info`，沿用已有 Engine 只读请求。采集器不输出全部标签、仓库 URL 或源码。旧采集器、过期样本和查询失败不会使 cAdvisor 容器同步失败。

## 验证边界

测试使用独立 PostgreSQL 测试库、本地 HTTPS Git 服务与模拟令牌；不代表真实外部私有仓库已联调。真实 DeepSeek、远程服务器和外部邮件沿用原有授权边界。后续阶段才将这里的源码证据接入 Harness 诊断与修复交接。
