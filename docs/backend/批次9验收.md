# 第九批次：审批与受控执行

实施日期：2026-10-02，最终验收日期：2026-10-03（Asia/Shanghai）。实现范围仅为持久化审批、固定 Action Skill、SSH 前置检查/执行/验证、追加审计及事故时间线。没有复盘、前端或远程部署。

## 实现与授权边界

- 固定注册表只提供 `restart_container` v1，风险 medium，要求人工审批；Knowledge Skill 文本不能定义命令，Harness 工具白名单保持只读，诊断提案仍为 `executable=false`。
- Operator/Admin 可从 completed 分析的提案申请审批及发起执行，仅 Admin 可批准或拒绝，无双人审批。审批绑定事故、容器资产 UUID、完整 Docker ID、服务器连接信息/固定主机公钥、凭据更新时间和 Skill 定义摘要，不复制凭据。
- 审批创建后 30 分钟到期，批准不延长时间，无目标/参数编辑接口。有效的相同分析审批请求返回原记录；重试动作必须另建审批。
- `approvals`、`skill_executions`、`audit_logs` 均包含 UTC 的三个时间字段，created_at/updated_at 非空且有默认值，deleted_at 可空，数据库触发器维护 updated_at。新增迁移为 `0009_approvals_execution`，健康检查同步核对该版本。
- 入队在一个事务中消费审批、创建唯一执行并追加审计和时间线；唯一约束保证每个审批一个执行，同容器最多一个 queued/prechecking/executing/verifying 任务。API 重复请求返回原执行。
- worker 使用现有 PostgreSQL 持久化队列、单实例 advisory lock 和单并发，启动时标记遗留活动任务中断，保留 queued 待重新校验。SSH 等待不持有事故全局事务锁。
- 前置检查与发送前再次校验申请人、审批人、发起人的当前权限、有效期、事故状态和绑定。事故 recovered/closed/merged、目标删除、凭据或连接信息变化均不能发送动作。
- SSH 使用加密凭据、固定主机公钥和禁用 Agent/自动加载本机密钥。固定 inspect 校验完整容器身份及状态；paused/restarting/removing/dead 不能执行。健康检查日志不入库。
- 唯一变更命令为 `docker restart -t 10 <资产解析的64位Docker ID>`。计划原写 `--timeout 10`，真实验收发现 Debian Docker CLI 不支持这个长选项；采用官方同义短参数 `-t` 兼容新旧 CLI，仍保持固定命令和 10 秒停止等待，不添加执行回退或重试。参数依据：[Docker 官方 restart 文档](https://docs.docker.com/reference/cli/docker/container/restart/)。
- SSH 连接 10 秒，动作总等待 30 秒，验证最多 60 秒。两次间隔 2 秒的检查均须 running；配置 Docker HEALTHCHECK 时均须 healthy，没有配置时明确记录 `application_health=not_configured`。
- 发送标记先提交数据库，再发送一次命令。SSH 断线/超时及发送后 worker 中断为 unknown；发送前中断为 interrupted。失败审批保持 consumed，终态不自动重试，重启动作无自动回滚。
- 每个输出流限制 16 KiB，落库前移除已知凭据并脱敏，包含退出码和截断标记。审计记录请求来源、操作者和关联 IDs，不提供修改/删除接口。执行器记录已有监控证据，告警恢复和事故状态由原监控链路决定。

接口、角色及启动命令详见根目录 README 的第九批次说明。
