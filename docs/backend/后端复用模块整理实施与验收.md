# 后端复用模块整理实施与验收

日期：2026-10-22。依据：[调研与实施计划](后端复用模块整理调研与实施计划.md)。本次在当前项目根目录完成源码整理，保持现有单体、数据库和部署入口。

## 已完成的整理

- 密钥读取与凭据加解密集中到 `app.core.secrets`，共用服务令牌校验放在 `app.core.service_auth`；调用方不再经过监控配置或 SSH 取得这些能力。
- 通用记录查询和保存分别归入 `services/records.py` 与 `repositories/records.py`。保留软删除过滤、404/409详情及原有提交、回滚、刷新顺序。
- 指标表达式与可用性处理归入 `services/monitoring/metrics.py`，资源指标读取归入 `services/resources/metrics.py`。资源路由、诊断、预测、恢复和监测直接调用所属模块。
- LLM 状态归入 `services/llm/status.py`；宽容的容器 ID 提取归入 `utils/docker.py`；报告及修复交接共用的 JSON 编码与摘要归入 `utils/canonical_json.py`。
- 同步更新应用、验收脚本和测试的导入。测试替身仍作用于实际使用依赖的位置，未保留旧业务模块作为公共转出口。
- 扩展现有架构检查，覆盖共用模块依赖、旧导入路径、绝对/相对导入；新增记录事务、软删除、唯一约束回滚、ID校验差异及固定摘要回归用例。

本次新增8个应用小模块，未引入新框架、依赖或通用仓储基类。执行 Skill 的严格 ID 校验、审批摘要、业务审计和 worker 处理流程保持原有实现。

## 兼容与回退基线

修改前保存了313个源文件与契约文件的快照、SHA-256清单、实际生成的 OpenAPI 和模型元数据。快照位于本机 `.local/reuse-modules-20261022-081454/`，仅用于本次比对与恢复，不作为部署源码分发。

已比较确认，完整源码整理不改变 OpenAPI、42张表的元数据、模型公开身份、24个迁移文件、依赖锁文件或 Compose 配置。模型、数据结构、迁移及关键配置共65个文件与快照逐字节一致。

18个迁移函数在排除仓储函数更名及相应调用名称变化后，语法树与原始实现一致。其余1,336个既有顶层函数/类在排除导入位置调整及资源路由别名调整后，语法树一致。结合实际回归，确认本次修改集中在能力归属与调用路径。

回退只需根据本次快照恢复变更文件并移除本次新增模块，无数据库数据迁移。测试日志、JUnit结果、函数比较、Ruff基线和容器验证记录保存在同一快照目录。

全仓 Ruff 与相同配置下的原始快照比较：原有17项，整理后11项，新增0项。剩余问题为既有测试文件的导入排序和长行，本次未进行无关格式整理。应用、脚本及本次新增/扩展的架构与回归测试均通过 Ruff。

29项跳过与基线一致：26项真实服务数据库集成用例由独立验收脚本执行，另3项需要当前宿主机未具备的 SVN/HTTPS SVN 工具。本次不能将这些跳过写成实际联调通过。
