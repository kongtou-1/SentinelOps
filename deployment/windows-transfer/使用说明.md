# SentinelOps Windows 离线迁移包

整个文件夹都要复制。`images.tar.gz` 是运行镜像，`payload.enc` 是加密的项目、模型、数据库及持久化数据；`manifest.json` 用于校验。迁移密码文件在包外单独保存，恢复时需要输入其中的密码。

## 新电脑首次启动

1. 准备 Windows x64 电脑，安装并打开 Docker Desktop，使用 WSL 2 与 Linux containers。先完成 Docker Desktop 初始化。无需安装宿主机 Python、Node、pnpm 或 PostgreSQL。
2. 把整个迁移包放到例如 `D:\SentinelOps-transfer`。同时保存迁移密码文件，不要把密码发到公开位置。
3. 准备一个空的项目目录，例如 `D:\research\sentinelops`。没有 D 盘时可换成 `C:\SentinelOps`；路径不必与原电脑相同。
4. 在迁移包文件夹内打开 PowerShell，运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Restore.ps1 -TargetRoot "D:\research\sentinelops"
```

看到 `Transfer password` 时，输入密码文件中的完整密码。脚本会校验文件、导入镜像、恢复数据库和八个文件卷、核对数据与权限、建立新电脑资产、重新关联服务和预测、验证 SSH，并启动平台和实测业务。整个过程不重新构建镜像，不下载项目依赖。

完成并显示 `Restore and verification passed` 后访问：

- 运维平台：http://127.0.0.1:8080
- 实测问答业务：http://127.0.0.1:18080
- 测试邮件箱：http://127.0.0.1:8025
- Prometheus：http://127.0.0.1:19090

使用原有账号登录。初始管理员凭据文件恢复在项目目录 `.local/admin-credentials.txt`，若此前改过密码，以当前实际密码为准。自动恢复需要这个文件与有效管理员密码保持一致；导出时已核对其可登录。

系统会保留应用、用户、历史事故、审批、诊断、报告、知识库、发布及源码快照。新容器使用新 Docker ID；当前部署和预测关联新容器，旧审批不用于新容器。旧服务器停止采集，新电脑另建资产，实时 CPU/内存来自新电脑的 Docker Desktop Linux 环境。旧监控历史仍按原有 35 天保留策略滚动，原始备份包应保留。

真实问答和 AI 诊断仍需联网访问 DeepSeek。离线环境可运行平台、查看历史、运行本地 `/work` 流量及故障场景；不能把离线启动成功当成外部 Provider 联调成功。

## 以后启动、停止、检查

Docker Desktop 先保持运行，在迁移包文件夹运行：

```powershell
# 启动已有环境
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -TargetRoot "D:\research\sentinelops"

# 检查当前环境
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Verify.ps1 -TargetRoot "D:\research\sentinelops"

# 停止，保留所有数据
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1 -TargetRoot "D:\research\sentinelops"
```

首次恢复完成后，不要再次运行普通 `Restore.ps1` 覆盖已有数据。日常使用 `Start.ps1`。运行配置保存在项目 `.transfer/`，日常脚本会使用这些已固定镜像和路径的配置。

## 端口冲突与失败重试

脚本会在导入前检查端口。若新电脑的 8080 被占用，可首次恢复时指定：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Restore.ps1 -TargetRoot "D:\research\sentinelops" -FrontendPort 18088
```

随后入口改为 `http://127.0.0.1:18088`。其他可配置参数为 `BackendPort`、`BusinessPort`、`SshPort`、`PrometheusPort`、`AlertmanagerPort`、`MailpitPort`、`DatabasePort`。

脚本拒绝覆盖已有 SentinelOps 容器和卷。若是本次恢复在中途失败，修复报错后使用原目录和原项目名重试：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Restore.ps1 -TargetRoot "D:\research\sentinelops" -Resume
```

若校验报文件缺失或修改，应重新复制相应文件。若密码错误，检查输入；不要删除原备份。若仅在解密阶段失败、还没有 `.transfer/restore-state.json`，换一个空的项目目录后重新运行首次恢复命令。

若设置了不同的 `ProjectName`，后续恢复重试也须传入同一名称。正常导入不需要改项目名。

## 导出更新的数据

需要导出下一份备份时，在已恢复的项目 `deployment/windows-transfer` 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Export.ps1 -SourceRoot "D:\research\sentinelops" -OutputDirectory "D:\SentinelOps-transfer-new"
```

导出会先保存镜像，再短暂停止平台和 testlab 写入，备份完成后自动恢复原环境。应在没有执行、诊断、源码同步、报告生成、知识索引、评测、归档清理或邮件发送任务时运行。生成的密码文件在输出目录旁边，应单独保存。

## 验收范围

脚本检查数据库启动前的全表数量和内容摘要、清单中各文件卷的内容/权限/所有权、镜像身份、应用原 ID、历史源码快照、当前部署、testlab 容器健康、SSH 身份、采集器配置下载和 worker 健康。文件卷现包含 `notification_config` 和 `archives`，不可只恢复数据库而遗漏归档。主平台运行服务数由完整 Compose profiles 解析，不固定为 18；组件健康另外核对预期 worker。验收结果在项目 `.transfer/verification.json`。

本包会在独立 Compose 项目、独立端口和以 `_test` 结尾的测试库执行恢复演练；演练禁用真实 LLM 定时探测和 AI 外部调用。最终随包提供本机演练结果。另一台电脑上的硬件、端口和 Docker 条件仍需在首次恢复时实际检查。

八项设计补全后，导出/恢复完成会登记产物摘要、实际完成时间及演练耗时，恢复重试沿用首次开始时间。独立看护另见 `deployment/watchdog/使用说明.md`。本轮已实际恢复全部 65 张表及归档并核对摘要，未重新执行完整加密交接包的全镜像搬迁；新字段、启用默认值和限制见[实施验收](../../docs/project/八项设计补全实施与验收.md)。
