# 服务与源码连接统一入口

实施日期：2026-10-15。

服务器页的新建、编辑服务现在可直接配置 Git HTTPS 地址、分支、主要源码目录、启动入口、用户名、只读令牌、本地后备目录和运行路径映射。容器页使用相同服务编辑组件。应用详情页共用源码连接字段，按钮明确命名为“编辑服务与源码连接”。

服务创建、修改请求接受可选 `source_connection`，与服务资料、本机容器归属在同一事务中保存。省略该字段保留已有源码配置。沿用 `sources:manage` 权限、HTTPS/路径校验及令牌加密、保留、清除和替换规则，不返回或审计令牌。没有新增数据库字段或迁移，保存连接不会自动发起同步或部署。

验证结果：

- 独立 PostgreSQL `service_sources_20261015_test`：`test_business_services.py`、`test_sources.py` 共 42 项通过，包含本机 HTTPS Git 的公开/私有虚构凭据同步。首次受限环境中的两项同步失败，核对回环目标并取得执行许可后复验通过；最终整组回归全部通过。XML 保留于 `.local/service-sources-tests.xml`。
- 前端 43 项测试通过；Vue 类型检查、生产构建和修改 Python 文件的 Ruff 检查通过。
- 浏览器在独立测试库验证服务器页创建服务及源码连接、再次编辑回填、修改分支保存，并在应用详情页确认同一仓库和修改后的分支。随后应用页反向保存的补充验证被浏览器来源授权拒绝，未绕过或执行该保存；两个 API 入口的双向修改由自动化测试覆盖。
- 本机后端和前端已更新；在线 OpenAPI 包含新的服务源码连接输入，`/servers` 和 `/health/ready` 返回 200，两个容器均健康。临时 API/Vite 已停止，独立测试库已删除。

上述同步测试只访问本机临时 HTTPS Git 服务，不代表真实外部私有仓库联调通过。
