# 智能巡检第二阶段实施与验收

日期：2026-10-29。范围：任务配置到报告的使用闭环；源码和本机隔离验证，不包含业务服务升级。

## 使用方式

入口统一为“智能巡检”，保留已有 URL，三个页签为“巡检任务、执行记录、连接管理”。

1. 在连接管理登记共享 HTTP 连接或复用现有 PostgreSQL/MySQL 只读连接。登记列表/详情查询、响应映射、分页和允许参数；复杂查询可登记参数化 SELECT，继续执行已有 AST、表列与只读事务校验。认证仅在连接或查询中加密保存。
2. 创建任务，依次填写“对象与数据、检查内容、执行安排”。对象可以来自查询，也可以手工填写稳定编号和 JSON 输入。查询预览显示映射后的最多 3 个对象及是否还有后续数据。
3. 添加独立规则和 Agent 检查。规则支持 AND/OR 条件组、字段比较、字符串、数值及集合判断；Agent 选择主/辅助 Skill、检查要求、授权查询和业务参数。模型继续复用系统中的巡检通道。
4. 点击“试运行 3 个对象”。当前表单直接形成临时快照，不必先保存；结果留在编辑页，可查看对象数据和逐项结论，也可在新页打开完整报告。真实查询、模型请求与代码执行均使用正式执行链和相同授权校验。
5. 保存后新任务保持暂停。详情中可启用调度，或在暂停状态下显式手动执行统一任务。Cron/间隔/单次安排可预览下三次时间，使用服务端调度算法和配置时区。

任务列表按服务/环境排序分组，组内标明筛选后的总任务数及本页数量，使用后端分页。支持搜索、启停、复制、编辑及最近报告直达。复制得到新 ID 的暂停任务，保留配置引用，不复制执行历史、游标或明文凭据。

## 报告与试运行边界

执行记录可以筛选正式执行或试运行。报告分别展示执行状态、检查结论、发现范围和检查覆盖，包含“结果概览、对象明细、执行过程、证据与产物”四个页签。

- 对象列表默认异常优先；对象内并列展示规则与 Agent 的结论和执行错误，原始结果与追加复核保留。
- 规则通过不能覆盖 Agent 的异常或执行错误。资料不足与执行未完成分别显示；未完成发现不能表示全量通过。
- 集合结果单列，不计入业务对象数。抽样未覆盖完整集合时，依赖全量输入的集合检查保持未完成。
- 工具轨迹、代码正文、环境、输入引用和输出按页读取；证据可在鉴权读取后下载。报告不展示模型内部思考，也不预加载全部轨迹。
- `run_kind=trial` 使用独立配置快照，样本上限 1–10，默认 3；该快照不进入正式任务列表和调度。样本完成不代表全量发现完成，`coverage.scope_is_sample=true`、原始发现状态和明确的样本提示同时保留。
- 试运行不推进正式 watermark/continuation，不更新正式最近结果或正式巡检总览；不会触发正式通知。模型使用量仍按实际调用记录。

内部复用现有任务实体持久化隐藏的只读试运行快照，以保留对象、结果、轨迹的现有外键与资源权限链。快照禁止编辑、启用、复制和作为正式任务执行；不会覆盖用户已保存的任务。留存与清理策略在第三阶段统一处理。

## 新增接口

前缀为 `/api/v1`。完整契约见 [OpenAPI](openapi.json)，前端类型由 `pnpm api:types` 生成。

| 方法与路径 | 行为与权限 |
| --- | --- |
| POST `/inspection-trials` | `{plan: InspectionPlanInput, sample_size: 3}`；统一检查任务，需 manage 且具备 run；返回 202 与可追溯运行 |
| POST `/inspection-plans/{id}/copy` | 复制为暂停任务，需 manage；只复用加密配置和查询引用 |
| POST `/inspection-schedule-preview` | 返回后续最多三次时间，需 manage；校验 Cron、时区与单次未来时间 |
| GET `/inspection-plans` | 增加 environment 筛选、group_total、last_run_id；组计数遵循相同筛选和资源权限 |
| GET `/inspection-runs` | 增加 run_kind=standard/trial 筛选 |
| GET `/inspection-runs/{id}/check-results` | 增加 item_id、scope 筛选，保持服务端分页 |
| GET `/inspection-runs/{id}/traces` | 可按 check_result_id 分页筛选 |
| GET `/inspection-data-sources` | 可按 http_connection_id 筛选连接下的查询 |

## 验证记录

使用独立 `sentinelops_inspection_stage2_test` 和浏览器专用 `sentinelops_inspection_stage2_preview_test`；两个数据库名均以 `_test` 结尾。PostgreSQL/MySQL 业务测试实例与 Python broker 独立于运行中的业务服务。未对业务库执行测试、迁移或清理。

验证覆盖：未保存表单试运行与正式状态隔离、复制及暂停执行、组计数与分页、权限拒绝、HTTP 状态规则、PostgreSQL/MySQL 登记查询及 300 对象分页、独立混合结论、未知/预算/零对象语义、跨对象引用拒绝、Python 失败修正和沙箱隔离、旧模式与历史结果兼容、模型配置和 API/元数据契约。

本地模拟 Provider 仅模拟模型决策；Harness、MCP、HTTP 查询、真实两种数据库、临时无网络 Python 容器及逐项落库均实际执行。它不能作为真实外部模型质量或真实业务 API 已联调的证据。

浏览器在隔离库完成：从查询预览 3 个对象 → 创建同任务规则/Agent 检查 → 未保存表单试运行 → 查看差额异常且保持表单 → 预览 Asia/Shanghai 下三次 Cron → 保存为暂停任务 → 手动执行 → 查看报告、对象明细与代码轨迹。样例报告为 3 个对象、6 项检查完成、1 个异常对象，规则通过没有覆盖 Agent 的金额差异。

自动验证：后端巡检、权限、模型配置及结构共 170 项通过；最终轨迹标签修改后，试运行、真实 Harness 和结构契约 17 项复验通过。前端 36 个文件、251 项通过，最终相关交互 18 项再次通过，含类型检查的生产构建通过。相关 Python Ruff 与格式检查通过。结果及截图保存在 `.local/inspection-stage2-release.xml`、`.local/inspection-stage2-traces.xml`、`.local/inspection-stage2-report.jpg`、`.local/inspection-stage2-code.jpg`。

## 迁移与后续边界

`0041_inspection_trials` 仅增加 `inspection_plans.trial_only` 和 `inspection_runs.run_kind`，默认将旧记录保留为正式任务/正式执行。不改写历史结论、证据或复核。模型与数据库元数据契约已同步；迁移仅在独立测试库验证。

业务库及 backend/worker/frontend 尚未升级。第三阶段仍需备份与一致升级、取消和进程中断恢复、可靠补检、留存清理、旧配置迁移与回退演练，以及真实业务/模型验证。当前编辑与启停仍沿用旧版对活跃运行的处理；暂停仅停止未来调度的新语义留在第三阶段。不得据此声称恢复与正式上线已完成。
