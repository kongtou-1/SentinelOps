## 本地完整闭环

`backend/scripts/accept_frontend.py` 每次创建新的 `ops_frontend_*_test`，只复制已有管理员身份用于授权操作，保留测试库和 `.local/batch11-acceptance.json` 供核查。复验期间临时切换本机 API/worker，结束后恢复正常服务配置并重新应用业务库规则。

故障由本地 Docker 测试容器停止产生，经 Prometheus 告警聚合为事故；本地模拟 Provider 配合真实 Harness/MCP 只读工具完成诊断与固定 `restart_container v1` 提案。未批准及已拒绝的审批不能执行。Admin 批准后独立发起执行，真实 OpenSSH/Docker CLI 完成前置检查、重启与 HEALTHCHECK；守卫容器不变，监控独立确认恢复后再人工关闭事故。

关闭后人工生成复盘，Admin 编辑、退回意见、审核，通过 PDF/Word 导出及显式 Mailpit 投递验证。重复执行请求复用同一执行记录且不会再次重启，重复发送请求复用同一投递记录。API、执行 worker 和报告 worker 重启后，执行、修订、投递状态及审计仍持久化；Provider 返回 401 时报告真实进入 failed/authentication_failed。

最终完整复验库为 `ops_frontend_ac574770_test`，原始记录 `.local/batch11-acceptance.json` 的 `status=passed`、`cleanup.complete=true`、`cleanup.errors=[]`、`normal_services_restored=true`、`normal_rules_applied=6`。三个临时浏览器账号已从正常业务库软删除，测试 SSH 私钥、允许目标文件与临时容器已清理。浏览器报告操作的独立证据保存在 `.local/frontend-browser-acceptance.json`。
