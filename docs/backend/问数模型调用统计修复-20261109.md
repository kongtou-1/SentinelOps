# 问数模型调用统计修复

## 问题与原因

原句“查看今天全部的模型调用次数、输入输出 token 计数”在原版平台持续修正 SQL，用户取消前已运行约 73 秒。问题涉及授权、查询和结果展示：

- 字段筛选把 `input_tokens`、`output_tokens` 当作凭据排除，旧模型不包含这两个字段；查询结果脱敏也会遮蔽数字计数。
- 提问缺少明确的业务日期与时区边界；数据库会话采用 UTC。
- 缺少外层 SQL 修正次数上限，缺失字段仍持续重试。
- 中文回答可能仅解释 SQL，没有报出实际查询数值；全数值汇总被错误生成柱状图，混合调用次数与 Token 单位。

## 修复与统计口径

允许明确列出的 Token 计数字段参与字段授权；结果仅保留数据库原生数值或 NULL。字符串、布尔值及访问令牌等凭据字段保持脱敏，未放宽一般凭据保护。

以提问时间固定 Asia/Shanghai 当天的半开区间，并向查询流程提供 UTC 边界。最多允许三次 SQL 修正，仍失败则返回需要补充授权或口径的说明。单行数值结果直接从最终执行、脱敏后的数据生成回答；没有分类或时间轴时不生成图表。

本机数据源补充 `public.model_usage.input_tokens`、`output_tokens` 两列的 SELECT 授权，更新表说明并完整重建、发布语义模型。调用次数使用 `SUM(calls)`，排除软删除记录；包含平台记录的连接测试与失败尝试。Token 汇总使用供应商已返回的计数，NULL 表示未知，不代表零，也不等于供应商账单总量。
