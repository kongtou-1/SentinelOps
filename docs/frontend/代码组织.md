# 前端代码组织

前端按业务归类，页面、业务组件、配置与模型放在一起；应用入口、布局和跨业务编排单独维护。

```text
frontend/
├── AGENTS.md                   # 前端协作规范
├── public/                     # 固定 URL 静态资源
├── src/
│   ├── main.ts                 # 应用启动、主题与插件
│   ├── App.vue                 # 布局选择、会话失效处理
│   ├── router/                 # 路由声明、守卫和路由契约测试
│   ├── layouts/                # 控制台与市场布局
│   ├── features/
│   │   ├── auth/               # 登录与认证 store
│   │   ├── dashboard/          # 总览
│   │   ├── resources/          # 服务器、容器、LLM 资源监控
│   │   ├── applications/       # 应用、服务、源码与关联
│   │   ├── alerts/             # 告警与规则
│   │   ├── predictions/        # 预测结果与任务
│   │   ├── incidents/          # 事故详情与看板
│   │   ├── diagnosis/          # 诊断工作台、模型与证据
│   │   ├── actions/            # 审批、执行与动作目录
│   │   ├── reports/            # 复盘与修复交接
│   │   ├── knowledge/          # 知识与 Skill
│   │   ├── market/             # 资源市场、投稿与审核
│   │   ├── system/             # 用户、角色、凭据、审计及状态
│   │   └── project-intro/      # 项目介绍
│   ├── views/                  # 跨业务列表页面、错误页面
│   ├── components/
│   │   ├── common/             # 状态与 JSON 证据
│   │   ├── charts/             # 指标图表与面板
│   │   └── records/            # 跨业务表单与关联记录列表
│   ├── api/                    # HTTP、SSE、OpenAPI 生成类型
│   ├── composables/            # 轮询、主题与导航偏好
│   ├── config/                 # 导航、指标与列表配置汇总
│   ├── types/                  # 共享记录与表单类型
│   ├── utils/                  # 显示、监控、流程与加载恢复
│   └── styles/                 # 全局样式入口与样式分组
├── package.json / pnpm-lock.yaml
├── vite.config.ts / tsconfig.json
└── Dockerfile / nginx.conf
```

业务目录按实际内容包含 `pages/`、`components/`、`model/`、`api.ts`、`store.ts` 和 `list.config.ts`，不创建空目录。例如预测表单字段修改在 `features/predictions/list.config.ts`，诊断事件处理在 `features/diagnosis/model/diagnosis.ts`，市场请求在 `features/market/api.ts`。

`config/lists.ts` 只组合各业务配置，`types/records.ts` 定义其结构，`config/metrics.ts` 保存共享指标。`views/RecordList.vue` 与 `components/records/RecordForm.vue` 沿用现有跨业务列表和表单逻辑；业务组件不再堆在公共目录中。公共组件和基础设施不反向依赖业务模块，跨业务页面显式组合具体组件。

跨目录引用使用 `@/`，由 Vite 和 TypeScript 共同解析。路由继续懒加载；URL、权限、接口及固定静态资源 URL 保持原样。测试随被测模块放置，路由契约覆盖 URL、权限、元数据、props 和重定向；所有路由页面还需实际执行一次懒加载导入。

全局 CSS 按 `base.css`、`console.css`、`appearance.css` 的原始顺序引入，分别保存基础规则、控制台样式和主题/导航覆盖。此次按原有连续区块拆分，保持选择器与级联顺序；局部样式仍随 Vue 组件维护。

生产构建仍为 `pnpm build`，输出 `dist/`，Docker 和 Nginx 入口保持现有方式。目录整理不改变后端、数据库或部署权限。开发命令见[启动与开发](启动与开发.md)，历史实施授权见[已确认实施范围](../project/已确认实施范围.md)。
