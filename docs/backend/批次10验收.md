# 第十批次 事故复盘

实施日期：2026-10-03（Asia/Shanghai）。完成关闭事故的复盘生成、版本编辑、人工审核、PDF/Word 导出、显式 SMTP 发送与审计。接口、配置和状态语义见根目录 README 第十批次。

## 实现边界

- Operator/Admin 发起，Admin 编辑、审核和发送，Viewer 读取及导出已审核报告。事故必须 closed，递归合并来源无活动诊断或执行任务。
- 不可变快照包含全部关联历史及来源摘要，不复制整套原始时序，不读取实时 SSH。缺少诊断或执行记录明确列为缺口；超过 256 KiB 明确失败，不截断。
- 报告 Harness 唯一只读工具为 get_postmortem_context。延续专用 profile、进程环境隔离、短期回环网关令牌、工具清单检查与超时终止；诊断和 Action Skill 权限不扩大。
- postmortem_reports、postmortem_revisions、postmortem_deliveries 含 UTC 的三个时间字段、默认值及数据库更新时间触发器。审计增加 report_id，approval_id 可空；原执行审计绑定不变。
- 已审核报告不可编辑。发送冻结明确版本、收件人、正文和 PDF，独立持久化幂等键。发送前权限重查；SMTP DATA 前提交发送标记，结果不确定不自动重发。
- report-worker 独立单实例、单并发、PostgreSQL 队列。重启保留 queued，运行中生成标记 interrupted；SMTP 发送中按发送标记区分 interrupted/unknown。SMTP 接受不表示已阅读。
- 没有前端、自动发送、自动知识入库或远程部署。
