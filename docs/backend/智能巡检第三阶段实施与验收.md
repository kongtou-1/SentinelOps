# 智能巡检第三阶段实施与验收

日期：2026-10-29。范围：取消、中断识别、显式补检、试运行留存、本机升级与回退验证。

## 执行与恢复

- 暂停任务仅停止后续调度，保留当前执行。任务启停仍使用版本校验；当前执行同步版本，不改变已冻结的检查内容。编辑检查配置、删除任务仍会取消当前执行。
- 取消操作和结果提交按任务锁串行；取消后拒绝工具读取、证据和晚到结果。已完成项保留，未完成项记录中断；取消状态不会被部分完成覆盖。
- inspection worker 取得独占锁后识别上次遗留的 collecting/evaluating 执行，保存 `inspection_worker_interrupted`。不会自动重新调用模型；queued 任务正常消费。
- 报告提供“补检未完成项”，调用 `POST /api/v1/inspection-runs/{id}/resume`，需 `inspections:run` 及原记录资源权限。仅适用于正式统一检查任务、已结束且发现完整的执行；任务版本、Skill 和查询授权必须保持一致，同时只允许一轮活跃执行。
- 补检创建独立运行，在 snapshot.resume 记录原执行 ID 与原观察窗口。对象保留原 observed_at 和证据，完成项保留原结论及 `inherited_result_id`，只重做未完成项。报告标明“沿用原始观察数据”，可返回原执行核对代码与轨迹。已完成的 unknown 和业务 fail 不自动重试。
- 对象发现未结束时，源端通常没有可冻结的快照，旧游标不能保证范围一致。本阶段明确拒绝此类补检，需重新执行任务。尚未提供带源端快照的跨页续扫。

## 留存

默认保留正式任务、执行、证据和人工复核，不自动清理。试运行可通过维护命令预览并软删除，最少保留七天，单次最多 100 轮；有未删除人工复核的试运行受保护。隐藏试运行任务、对象、检查项和轨迹统一更新 deleted_at/updated_at；不删除业务数据，不清理模型用量或追加审计。

```powershell
# 已部署环境；默认只预览候选 ID
docker compose exec backend /app/.venv/bin/python -m app.cli.inspection_retention --days 7
# 显式执行软删除
docker compose exec backend /app/.venv/bin/python -m app.cli.inspection_retention --days 7 --apply
```

不增加周期自动清理。正式记录仍使用现有授权删除入口。

## 语义检查补充验收

用户强调 Agent 应支持需要语义理解的任务。统一 Agent 检查继续使用 Skill、检查要求、授权对象材料和证据引用；提示词明确要求理解文本含义、上下文与业务意图，按 Skill 标准独立判定，不以字段完整、关键词或其他规则的结果代替本项判断。编辑页的 Agent 示例同步为“答复符合业务政策”，未增加新执行模式或判断框架。

在独立 `_test` 库使用现有真实模型通道完成两条构造政策样本：二者都有非空答复，均通过字段规则；第一条答复忽略七天与质量问题条件、承诺不适用的退款，Agent 判 fail；第二条正确适用已确认质量问题的例外，Agent 判 pass。结果引用具体政策、用户情况和答复原文。证据：`.local/inspection-semantic-real-model.json`。这是构造样例的语义链路验收，不代表实际客服规则，也不代表现有旧任务采集了问答正文。

转换后旧任务仍只覆盖工作接口响应快照；没有问题、回答与知识依据时，不评价答案正确性。支持语义巡检的实际任务应配置完整业务材料和明确 Skill 判断标准。相关后端回归 22 项、前端任务配置交互 39 项通过，类型检查及 Docker 构建通过。更新已同步部署 backend、七类 worker 与前端；转换前镜像保留为 `sentinelops-backend:before-independent-agent-20261029` 与 `sentinelops-frontend:before-independent-agent-20261029`。
