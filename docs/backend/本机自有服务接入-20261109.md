# 原版本机自有服务接入

入口为 `http://127.0.0.1:18088`，Compose 项目为 `sentinelops`。`sentinelops-demo` 为独立演示实例。

## 接入内容

- 资源中心登记“SentinelOps 本机 Docker”，复用现有 node-exporter、cAdvisor、Docker State Exporter 和 Blackbox，不新增宿主机或远程采集器。
- 业务服务“SentinelOps 运维平台”关联原版平台 10 个运行容器；不将 Demo 或隔离巡检 sandbox 关联为平台业务服务。
- 启用前端 HTTP、后端就绪 HTTP、PostgreSQL TCP、Prometheus 就绪 HTTP、Alertmanager 就绪 HTTP 共五项探测。
- 预测中心启用主机 CPU／内存、后端容器 CPU／内存、PostgreSQL 容器 CPU／内存，共六个任务，间隔五分钟。CPU 与主机内存阈值为 85%，容器内存阈值为 2 GiB，均可在任务中修改。
- node-exporter 展示 Docker Linux 运行环境的主机指标，不表示 Windows 宿主机原生性能计数器。没有旧资产标签的历史时序不会补写到新资产。

## 问数数据源

“SentinelOps 自有运维库”连接本机 `ops_platform`，关联平台业务服务。永久专用只读角色为 `sentinelops_askdata_ro`，只授予 26 张业务表、391 个字段的列级 SELECT；默认只读事务、语句超时五秒。口令由加密配置保存，不写入源码。角色不获得所有权、写权限、管理权限或未来新表的自动权限。

范围覆盖资源、服务探测、数据库连接状态、模型服务与通道状态、告警、事故、预测、巡检、审批、执行、复盘状态、模型调用统计以及服务发布部署关联。凭据字段、原始 JSON、证据及报告正文不在授权范围。旧“冒烟业务库”保留历史但停用。

五表目录来自 11 月 7 日限定权限验收，不是平台表数上限。扩大授权后必须真实重建并启用新版本；旧版本保留原始五表上下文。目录选择器优先选择启用连接，停用连接显示“已停用”，结构或授权版本变化显示“配置已变更”。

## 验证

本轮通道和问数版本相关后端回归使用隔离 `ops_platform_own_services_test`，21 项通过；前端 48 个文件、318 项通过，类型检查与生产构建通过。真实采集器在线、五项服务探测通过。新资产预测初期为“历史不足”；待真实历史累积后按原有质量门槛生成预测，不填充样例曲线。

26 表模型已真实构建并启用，版本为 `90201824-90cc-4c0a-b96e-c6299f113d5e`：391 个字段、26 个术语、327 个属性、64 条关系、770 条向量；构建耗时约 251 秒。未绑定源码快照，没有将自动生成语义视为人工认证。

三条真实问数与独立资源 API、导出 CSV 一致：启用预测任务为 6 个；诊断、巡检、复盘、评测各有 1 条启用通道；业务服务“SentinelOps 运维平台”有 10 个运行容器。API 中计数值序列化为字符串，核对按数值比较，同时保持服务名和模块标识精确一致。最终四条模型通道的真实连接测试全部成功。只读账号验证 `transaction_read_only=on`、权限 `verified`；密钥列、用户密码列 SELECT 和业务 UPDATE 权限均为 false。

最终六个预测任务均成功执行并读到真实采样；历史约 1.7–2 小时，数据质量为 `usable`，预测窗口仍由原有历史门槛约束。更新后已重新发现当前容器，并将后端预测任务绑定到新容器，保留旧容器和旧结果的历史含义。

最终核验发现版本详情接口漏传连接配置，导致其 `active=false` 与列表不一致；已修复，并在原有版本生命周期测试中覆盖发布后为 true、停用后为 false。

本轮部署期间 Docker Desktop 的 WSL 后端超时，构建被中断。取消本轮构建并局部重启 Docker Desktop 后恢复；没有清理原版数据卷或关闭其它 WSL 发行版。中断的问数构建保留为 `interrupted`，之后重新完整构建成功。顺序构建并部署的最终后端镜像为 `e2604e90c94622616cd15e6a7bf9af96261a54b4d91eb78e2e6c982d74789b2c`，前端为 `96e33ebb4b18c5daa4b98e54b97f9f37338f780cb6643c7aa68cb696a0a62776`；原版容器健康，保留 `own-services-before-20261109` 镜像标签用于回退。本轮未执行数据库迁移。专用测试容器和临时卷已清理。

浏览器检查因应用访问审批超时未完成；本轮页面验证依据前端测试、构建与部署资源，业务结果由真实 API 和 CSV 核对。本轮修改涉及的后端、前端、脚本、部署与文档源码扫描未发现明文 Provider Key；本机实际配置与凭据继续留在加密数据库和被忽略的本机目录，不表示已对全部历史交付包完成公开发布审计。

模型密钥仍在“系统管理 → Agent 配置”修改，问数复用诊断通道。连接测试关闭 DeepSeek 官方端点的默认思考，防止短测试额度误报；业务推理配置保持各自设置。发布源码与密钥配置方式见 [Agent 模型配置](Agent模型配置.md)。
