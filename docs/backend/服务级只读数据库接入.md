# 服务级只读数据库接入

数据库连接独立登记，服务关联可选；一个服务也可以关联多个 PostgreSQL 或 MySQL 数据库。巡检可使用同环境的独立连接，事故诊断仍只冻结明确关联该服务的连接，不自动扩大取证范围。连接测试由 API 执行，诊断读取由现有 AI worker 执行，两个进程都需要能够访问目标地址。数据库不必部署在已登记的服务器上。

## 使用流程

1. 打开「智能巡检 → 数据源管理 → 数据库连接」页签，在主页面查看列表并直接添加连接和环境，无需先选择服务；关联服务可留空。也可从「应用与服务 → 服务详情 → 数据库」添加该服务的连接。巡检使用时环境须一致。
2. 默认使用校验证书及主机名的 TLS，可填写自定义 CA；无 TLS 的隔离测试环境须明确选择关闭 TLS。密码和 CA 加密保存，响应不返回原文；编辑时留空保留原配置。
3. 测试连接并保存，再到「表结构与说明」刷新结构。连接测试带采样时间，不代表持续健康。
4. 补充数据库用途、逐表业务说明，例如状态枚举、关联字段、时间语义、正常处理时长。结构刷新保留人工说明，不修改目标库注释，也不自动采样业务记录。
5. 在「访问范围」逐表选择字段，再启用 AI 读取业务数据并保存。新表和新字段不会自动获得授权；密码、令牌等敏感字段禁选。
6. 从该服务关联的事故发起诊断。工作台提供本轮数据库资料、查询过程和证据；人工采用后进入正式诊断，复盘引用保存的证据。

仅登记连接、刷新结构时，AI 可读取结构资料；未启用业务查询时不读取业务记录。Admin 管理、测试和刷新连接，Viewer/Operator 可查看；Operator/Admin 按原有诊断权限发起查询。私有会话的所有者边界保持不变。

## 数据库账号

由数据库管理员在目标库准备专用账号。平台仅检查已有权限，不创建账号、授权、安装扩展或修改目标库。下列授权示例须由管理员在确认目标后自行执行，密码使用独立随机值：

```sql
-- PostgreSQL：替换库、schema 和表名
CREATE USER sentinel_reader WITH PASSWORD '<独立随机密码>';
GRANT CONNECT ON DATABASE business TO sentinel_reader;
GRANT USAGE ON SCHEMA public TO sentinel_reader;
GRANT SELECT ON public.jobs TO sentinel_reader;

-- MySQL：限制为平台实际出口地址
CREATE USER 'sentinel_reader'@'<平台出口地址>' IDENTIFIED BY '<独立随机密码>';
GRANT SELECT ON business.jobs TO 'sentinel_reader'@'<平台出口地址>';
```

PostgreSQL 检查继承角色、管理员属性、对象所有权、schema/database CREATE 权限及目标表/列写权限。MySQL 首版接受可明确核验的 SELECT/USAGE 授权；复杂角色授权返回待核验，不自动开放业务读取。每次业务查询重新检查权限。账号拥有写权限时，不能仅凭查询工具只读就启用。

## 查询与证据边界

- 只支持普通表的单条 SELECT、常用内置函数、过滤、聚合、排序和同库关联。使用明确的 `schema.table` 和字段；`COUNT(*)` 可用，`SELECT *`、视图、子查询、CTE、用户函数、锁定读取、文件操作和跨库访问不开放。
- SQLGlot 按方言解析并校验所有表达式中的字段，重新生成无注释 SQL。数据库只读事务提供第二层约束。PostgreSQL 限定函数搜索路径，拒绝用户自定义类型转换；MySQL 不启用多语句或本地文件导入。
- 默认连接 3 秒、语句 5 秒、锁等待 1 秒；最多 200 行、128 KiB，单元格最多 4096 字符。结果标明截断及行数上限，SQL 展示去除字面值。
- PostgreSQL advisory lock 保证 API 与 worker 的每连接单并发。忙时返回，不排队。停止后不发起新调用；执行中语句由服务端超时约束，返回前重新检查配置和诊断状态。
- 以明确服务目标及环境授权。主机告警不会授权同机所有服务；服务或环境无法唯一确定时记录缺口。数据库资料不依赖源码、发布或部署记录就绪。
- 每轮冻结连接版本、结构版本和说明；配置变更或停用使后续调用及旧候选采用失效。数据库取证诊断不使用五分钟完成结果缓存，多轮须重新取得数据证据。
- 查询结果表示查询当时的状态。数据库会话使用 UTC，但没有时区的业务字段仍需人工说明。没有历史记录时，不根据当前值补写事故发生时状态。
- 说明、注释和数据是证据，不能修改系统指令或扩大权限。凭据不进入模型、事件和审计；授权结果脱敏后才进入模型和持久化证据。

结构缓存最多 200 表、10000 字段、128 KiB；每轮数据库资料最多 64 KiB。超限明确返回缺口，不静默把不完整内容当成完整结构。连接失败、权限不足、结构变化和读取超时不阻断其他诊断工具。

## API 与迁移

接口统一加 `/api/v1`，完整结构见 [OpenAPI](openapi.json)。

| 方法和路径 | 功能 |
| --- | --- |
| GET/POST `/service-databases` | 独立连接列表、新建；`application_id` 可省略或为 `null` |
| GET/POST `/business-services/{id}/databases` | 列表、新建 |
| GET/PUT/DELETE `/service-databases/{id}` | 查看、修改、软删除 |
| POST `/service-databases/test` | 草稿或已保存配置测试；草稿不持久化 |
| GET `/service-databases/{id}/schema` | 缓存结构和人工说明 |
| POST `/service-databases/{id}/schema/refresh` | 手动刷新结构 |

工具为 `list_service_databases`、`get_database_schema`、`query_database_readonly`，沿用现有调用预算，没有开放通用 SQL REST 接口。

迁移 `0024_service_databases` 新增连接表，给直接诊断及会话运行增加 `database_context`；旧记录默认 `{}`，页面标记未记录。更新触发器和三个 UTC 时间字段遵循项目约定。新复盘冻结数据库上下文与引用证据，已有正式诊断和复盘不回写。

迁移 `0042_independent_databases` 将连接的 `application_id` 改为可空，保留已有服务关联及全部连接配置；编辑连接可清空关联。独立连接审计写入现有运维审计表，服务关联连接沿用源码/数据库审计。当前就绪检查要求 `0042_independent_databases`。回退前必须先处理独立连接，降级不会自动删除连接或伪造服务归属。

升级前备份平台库和独立主密钥，按 README 停止相关进程、构建、迁移并重建 API/worker/frontend。就绪检查要求 `0042_independent_databases`；目标数据库不执行迁移。宿主机和 Docker 内的可达地址不同，不能直接把浏览器或宿主机的 `localhost` 当成容器中的数据库地址。

依赖使用 uv 锁文件安装。PyMySQL 暂固定到官方提交 `5e4ac551416f77ec974008be27aada29d3bb7808`，该提交修复 1.2.3 的 SHA2 完整认证返回值缺失问题（[上游修复](https://github.com/PyMySQL/PyMySQL/commit/5e4ac551416f77ec974008be27aada29d3bb7808)）。构建时需要 Git 和 GitHub 访问，现有后端 Dockerfile 已安装 Git；不能用未含修复的 PyPI 1.2.3 替换锁文件。发布版包含该修复后，可在重新验收冷启动认证与 TLS 后切回发布包。

## 隔离验收

在仓库根目录执行：

```powershell
.tools/uv.exe run --project backend python backend/scripts/accept_service_databases.py --start
pnpm --dir frontend exec vitest run --maxWorkers=2
pnpm --dir frontend build
```

脚本为专用 Compose 项目 `sentinelops-database-acceptance` 生成本地随机密码、测试密钥和 CA，运行 PostgreSQL 17、MySQL 8.4。平台库为 `ops_databases_test`，目标库为 `business_test`；宿主端口为 15483、13386，只绑定回环。测试临时目录位于当前仓库 `.local/`，不使用业务库或默认用户临时目录。账号和任务记录均为测试数据。

验收完成后清理该隔离项目：

```powershell
docker compose -p sentinelops-database-acceptance --env-file .local/databases-acceptance.env -f testlab/compose.databases.yaml down -v
```

本机测试、模拟 Provider 的 Harness/MCP 验收与真实外部数据库、真实模型诊断质量分别记录；前者通过不表示后者已完成。
