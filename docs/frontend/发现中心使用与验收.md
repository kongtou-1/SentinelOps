# 资源中心：Skill 市场与实用工具

## 页面与操作

主应用右上角「资源中心」在新标签页打开独立页面，包含「Skill 市场」「实用工具」两个 Tab，并提供返回运维平台的入口。两个 Tab 直接展示搜索、分类与内容列表，不显示宣传介绍。两类内容共用分类，分别过滤和统计已发布条目；搜索名称、简介与标签，筛选和页码保存在 URL 中。

内置分类：办公效率、写作与翻译、科研与学习、数据与分析、设计与创作、开发与运维、其他。

- 所有登录用户：浏览已发布内容，在「提交内容」保存草稿、提交审核；在「我的提交」查看进度、编辑或撤回本人待审核内容。
- Admin：「内容管理」默认查看待审核内容，进入详情审核发布或填写原因退回；可切换全部状态管理已发布内容并填写原因下架。
- Admin：「内容管理 → 分类管理」新增分类、修改名称和说明、调整排序、启停或删除未被引用的分类。已有内容或历史版本引用的分类使用停用。

Skill 展示说明、适用平台、版本、依赖与权限及仓库／下载链接。实用工具展示使用说明、平台、收费方式、推荐理由及官网。首版保存文本与外部 HTTP/HTTPS 链接，不托管上传包。

## 审核规则

草稿提交后锁定，作者撤回后才可修改。退回必须填写原因；再次保存生成新版本，保留已审核版本和意见。

已发布内容修改后生成新草稿，审核期间继续展示旧版本；通过后才切换公开内容。审核绑定版本号并持有条目行锁，过期版本和重复审核返回 409。版本详情可并排对比发布版本和提交版本；查看历史版本时不能审核最新版本。

下架会同时隐藏列表、搜索、分类数量和普通详情访问；若存在待审更新，一并撤回成草稿，避免下架后被并发审核重新上架。重新上架仍须提交并通过审核。

停用分类不会隐藏已经发布的内容；保存草稿、提交审核和审核通过时均检查分类仍然启用。普通用户不能读取他人草稿、修改他人内容或访问管理员管理接口，Admin 也不能代改他人的投稿。

市场数据、权限和操作日志独立于 Knowledge Skill、Harness 工具、Action Skill 和运维审批，不授予运行或执行权限。

## 接口与数据库

接口前缀 `/api/v1/market`，沿用 Bearer 登录和 `X-Total-Count` 分页总数：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/categories?kind=skill或tool` | 分类及当前类型已发布数量 |
| POST / PUT / DELETE | `/categories`、`/categories/{id}` | Admin 分类管理；PUT 携带 `expected_updated_at` |
| GET | `/entries` | 默认已发布；`scope=mine` 本人提交，`scope=manage` Admin；支持类型、分类、状态、关键词与分页 |
| POST | `/entries` | 创建本人草稿，类型 `skill` 或 `tool` |
| GET | `/entries/{id}` | 只返回当前上架的已审核版本 |
| GET | `/entries/{id}/workbench` | 作者或 Admin 查看版本与操作记录 |
| PUT | `/entries/{id}/draft` | 保存本人草稿或生成修改版本，携带 `base_revision_id` 与 `expected_version` |
| POST | `/revisions/{id}/submit`、`/withdraw` | 本人提交或撤回；携带 `expected_version` |
| POST | `/revisions/{id}/review` | Admin 审核，`decision=approve或reject`；携带版本和意见 |
| POST | `/entries/{id}/unpublish` | Admin 填写 `note` 下架 |
| GET | `/category-audit` | Admin 最近分类操作记录 |

迁移 `0019_discover_market` 新增 `market_categories`、`market_entries`、`market_entry_revisions`、`market_audit_logs`。四表包含 UTC 带时区的三个时间字段、创建默认值、更新时间触发器及软删除过滤。操作日志只追加写入，没有编辑或删除接口。

新增权限：三个角色均有 `market:read`、`market:submit`；仅 Admin 有 `market:review`、`market:manage`，原有角色权限保留。

## 升级

备份业务库后，构建前后端镜像，停止 API 与 worker，执行 `docker compose run --rm migrate`，再恢复原有 profiles。就绪检查要求迁移版本 `0019_discover_market`。本功能不需要新增基础组件或 worker。

部署后核对 `/health/ready`、资源中心入口和七个内置分类，并在重启后检查分类和条目状态持久化。正常业务库初始只预置分类，实际内容通过投稿与审核添加。
