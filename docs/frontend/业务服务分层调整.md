# 业务服务分层与资源中心 UI

资源中心按“服务器 → 业务服务 → Docker 容器”组织。业务服务复用现有 `applications` 记录；容器是组成服务的运行组件，不再将每个容器称为一个业务服务。

## 界面与操作

- 选择服务器后，先展示业务服务卡片：名称、用途、负责人、容器数量、汇总状态及 CPU/内存占用。
- 服务器总览的两张环形图按业务服务汇总。进入服务后，按所属容器细分；分母始终是整台服务器，保留其他占用和剩余资源。
- 业务服务依赖在服务层维护。服务内部 Docker 连接关系、健康状态、网络归属和容器备注在容器层查看或维护，共享网络不自动推断为真实调用。
- Admin 统一在“应用与服务”的“登记服务”入口创建服务。服务器页、容器页保留查看、编辑和关联已有服务，不再提供重复的新建入口。容器只能归属一个服务，避免重复统计；共用组件可登记为独立共享服务，再由其他服务填写依赖。
- 服务器、容器及应用页新建和编辑服务共用负责人下拉框，搜索并选择已启用的系统用户，也可清空。用户列表按分页完整加载；已有未匹配启用账号的负责人显示为“原记录”，不自动清除或替换。两个后端保存入口均校验负责人，拒绝新填不存在、禁用或已删除的账号；编辑时允许保留原记录。
- 尚未归属的容器单独显示，原有容器别名、备注和技术依赖保留。移出服务后回到未归属；改变归属不删除容器，也不操作 Docker。
- 同一业务服务可在多台服务器分别登记容器。在一台服务器修改成员，不覆盖其他服务器的成员。业务用途属于服务的共用资料。
- 容器详情自动定位到其所属业务服务。“应用与服务”列表也显示相同的业务用途；原源码、发布和冻结证据保持独立。

## 数据与权限

迁移 `0018_business_services` 为 `applications` 增加 `purpose`、`depends_on`，为 `containers` 增加 `application_id`。不新增表；原表的 UTC 时间字段、软删除和更新时间机制保留。

已有唯一、当前有效的应用部署关联可回填归属；历史、未来或有歧义的关联不自动分组。新建和分组无需编造发布版本、镜像或源码记录，不触发部署、源码同步或运维执行。Docker 重建产生新资产时，不能仅凭同名容器推断业务关系。实时概览仅在服务器、Compose 项目、Compose 服务和实例名称全部一致，且只有一个实时实例、历史归属没有冲突时，沿用该实例槽位的业务分组；旧实例不重复计入实时概览。此规则只用于展示，不改写持久化容器归属、历史资产、部署绑定或源码证据。无 Compose 身份、无实时状态或归属有歧义时保留原分组，需人工确认。

接口沿用 `resources:read` / `resources:manage` 权限，当前所有三个角色可读，仅 Admin 可修改：

- `GET /business-services`：与应用实体共用的业务服务资料。
- `POST /servers/{id}/business-services`：原子创建服务并关联容器。
- `PUT /servers/{id}/business-services/{service_id}`：原子修改资料及本机成员。
- `PUT /servers/{id}/business-services/{service_id}/containers`：关联已有服务或调整本机成员。
- `GET /servers/{id}/container-overview`：服务分组、未归属清单及原有监控观测。

服务资源汇总仅累计有效样本，并显示采样覆盖数量。没有采样不会变成零占用。服务健康分为“正常 / 异常 / 无法判断”：所有关联容器均在运行且 Docker 健康检查通过才显示正常；已发现退出、停止、重启中或健康检查失败时显示异常，即使其他容器缺采也不隐藏已知异常；运行状态缺失、未配置健康检查、健康检查启动中或结果缺失时显示无法判断。页面展示原因数量，并可展开查看具体容器。CPU/内存缺采不单独改变健康结论，业务请求可用性不由容器状态推断。

### 容器运行、主动监测与 Docker 检查分离（2026-10-17）

总览此前仅用 Docker 检查判断应用健康，忽略了前端配置的主动监测。总览和应用详情现分别展示以下三类状态，不再把 Docker 检查未配置解释为容器运行未知：

| 状态 | 数据来源与判定 |
| --- | --- |
| 容器运行 | 当前实例的运行观测；全部运行显示“运行中”，已知停止或重启显示“运行异常”，运行样本缺失显示未知。 |
| 服务监测 | 现有 `/service-monitors` 接口。所有启用的关键监测通过才显示正常；任一关键监测失败显示异常；过期、待判定、暂停、未配置和读取失败分别展示。辅助监测结果单列数量，不覆盖关键监测的可用性结论。 |
| Docker 检查 | 独立显示通过、未通过、未配置、启动中、已停止及结果未知的容器数量。保留真实异常和缺口。 |

- Admin 在应用详情“服务监测 → 添加监测”配置 HTTP、TCP、DNS 或 ICMP。保存和手动探测使用已有接口，无须重建目标容器。总览每 30 秒刷新，也可手动刷新。
- 未配置主动监测时显示“未配置”，不根据容器进程状态声称业务可用。应用详情读取失败时清除上次数据，避免继续显示旧的正常结果。容器页原有 Docker 健康汇总保持不变。
