# 复盘报告固定大纲

模型必须按下列大纲填写已有结构化字段。页面及 PDF/Word 正文使用相同章节名；关键时间线直接来自平台冻结记录，完整时间线及证据另存附录。正文约 1500–3000 字，不把采样和原始 JSON 当成正文。

| 章节 | 必须说明 | 证据不足时 |
| --- | --- | --- |
| 事故摘要 | 触发、涉及资源、核心问题及最终状态，一段概括 | 不提前认定根因或恢复成功 |
| 影响范围 | 已观测到的影响、尚未确认的业务影响 | 不编造停机时长、用户数或损失 |
| 关键时间线 | 平台记录的人工处理、诊断、核验及关闭节点 | 不由模型补写事件；完整自动告警记录留在证据中 |
| 原因与证据 | 主要原因、证据 ID、已确认/推测/未知 | 直接说明根因未确认；诊断建议不等于已确认根因 |
| 处置与恢复核验 | 实际动作、执行结果、恢复核验和关闭决定 | 区分建议、审批和执行；强制关闭不等于修复成功 |
| 经验教训 | 本事故暴露的具体问题 | 不凑条数，不写泛泛的管理口号 |
| 改进措施 | 每项具体动作、负责人及计划时间 | 未指定的人和时间写待分配、待确定 |
| 证据缺口 | 缺少哪些资料、哪些结论仍需核实 | 系统记录的缺口必须保留 |

报告先生成待人工审核的草稿。模型不得新增任意章节；缺少必填结构字段、无效 JSON 或越界引用不发布正文。

复盘专用输出额度为 16,384 token，流式响应传输上限配套为 8 MiB，诊断默认额度不变。冻结摘要只完整返回一次，重复读取不再复制整包材料；模型输出截断明确记为 `model_output_limit`。引用允许外层冻结记录 ID 和冻结诊断内实际存在的 `e_...` 证据 ID，编造的 ID 仍拒绝，人工编辑时同样可选择这些诊断证据。生成失败不自动重试，不自动批准、导出发送或写入知识库。
