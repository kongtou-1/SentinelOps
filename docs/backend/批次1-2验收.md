## 实现选择

- Python 3.12、同步 SQLAlchemy/psycopg，满足当前请求规模；没有异步任务需求，暂不引入 Redis/Celery。
- 每个用户一个固定角色，预置 Admin、Operator、Viewer。Viewer 查看本人信息；Operator 额外查看系统运维状态；Admin 管理用户及角色分配。后续资源权限在相关业务批次增加。
- 按 PDF 的 JSON 登录形式和 Access/Refresh 建议实现；认证会话持久化，刷新标识只保存哈希，刷新通过行锁保证一次消费。退出、禁用、软删除、重置密码撤销会话，权限修改立即生效。
- 默认访问令牌 30 分钟、刷新会话 7 天；刷新轮换不延长绝对期限。密码以 Argon2id 哈希入库，管理员通过 CLI 首次初始化，没有预设密码或公开注册。
- 只创建 `roles`、`users`、`auth_sessions`、`alembic_version` 四张表。所有表具有带时区的创建、更新、删除时间字段，以及数据库更新时间触发器。
- 用户软删除后，普通查询不可见，用户名继续保留；三个角色不开放编辑或删除接口。并发降级仍保留至少一个有效管理员。
- `.env` 随机数据库密码和 JWT 密钥由初始化脚本生成，配置文件及初始管理员凭据均被 `.gitignore` 排除。

## 处理的问题

Docker Hub 认证连接曾超时，改用 uv 官方 GHCR Python 3.12 派生镜像后构建通过，没有修改宿主机网络配置。最终后端基础镜像为 `ghcr.io/astral-sh/uv:0.12.21-python3.12-trixie-slim`。

验收发现宿主机与 Docker 数据库的亚毫秒时钟差导致软删除时间偶尔晚于更新时间。已让数据库生成删除、登录和会话撤销的记录时间，并保留原测试断言重新通过。

当前 Starlette 测试客户端要求 httpx2；已按官方接口调整开发依赖，测试无弃用警告。
