# 后端十批次必修补缺验收

验收日期：2026-10-03。依据 `docs/plan.txt`、落地技术方案 PDF 与用户批准的补缺计划实施。六项本地可验证整改已经完成；真实 DeepSeek、外部 SMTP 和真实周期预测效果仍须分别验收。

## 实施结果

| 必修项 | 最终行为 |
| --- | --- |
| AI 读取 LLM 延迟 | 使用 `llm_latency_avg_seconds`、`llm_latency_p95_seconds`；查询及证据单位均为秒，两种工具均有回归覆盖。 |
| 通知结束与资源恢复 | 保留 Alert 的 firing/resolved，另存冻结规则、恢复核验状态、原因、检查时间及证据时间。只有同一资产、同一规则、同一采集配置的新鲜正常证据才能恢复事故；数据缺失和 unknown 保持 pending。停用、退役、条件或来源变更记为 terminated，人工说明后关闭，不生成恢复时间。 |
| 预测来源与异常处理 | 采集配置变更时间进入来源快照和采集标签；切换目标或启停监控使旧结果失效。按顺序处理所有未检测的完整点，以此前预测作为基准，累计 EWMA 漂移；插值点不判断异常。取最近长缺口后的连续历史，重新判断训练和回测条件。保存历史尖峰，实时异常仅表示最新完整点。保留 MSTL + AutoETS。 |
| 必需监控 | 增加 16 项固定查询及规则能力：Load1、IO Wait、可用内存、Swap、剩余磁盘、Inode、读写速率、平均 IO 等待、网络收发错误/丢包、HTTP 总延迟、Docker 重启/OOM 五分钟计数。无配置或无有效样本明确返回 unconfigured/unavailable，不补零；规则仍由 Admin 显式应用。 |
| AI 队列配置一致性 | 诊断、复盘 worker 在调用前核对保存的 Provider、模型和超时快照；不一致以 `configuration_changed` 结束，由人工重新发起。网关调用时继续核对，不自动重试付费推理。 |
| 部署说明 | README 更新至批次 1–10 和迁移 0011，补全模型准备、知识索引、凭据同步、四类 worker、健康检查及升级顺序。 |

恢复核验由既有 prediction-worker 每 60 秒运行：每轮最多 10 条、15 秒预算，查询超时有界。优先处理具备冻结规则的可核验通知，避免旧的无绑定历史记录占满核验队列；这些历史记录不会因轮询补写为验证成功。核验完成前重新检查规则和资产，防止查询期间发生配置变化。

Docker 状态采集器只提供 `/metrics`，使用固定 Engine API 读取容器状态和生命周期事件；没有命令入口、代理或任意 API 转发。采集不完整、轮询间断或事件读取失败时，不把缺失窗口记为零。新增可选 `docker_state_target`，通过既有服务发现接入。名称修改和 SSH 测试不改变采集时间边界。

告警核验字段已进入事故详情、只读诊断上下文和复盘快照。新报告注明核验恢复时间及未核验证据缺口。旧审核快照保持原内容；同一报告版本已有发送记录时，PDF 下载及后续人工发送复用冻结附件，避免渲染器变化改写原审核文件。

## 仍需外部或长期验收

- **真实 DeepSeek 联调**：需要有效独立诊断凭据；本地 Provider 通过只证明协议、工具边界、配置一致性及错误处理。
- **外部 SMTP 投递**：需要有效 SMTP 凭据与明确收件人；Mailpit 收信和附件核对不代表外部投递通过。
- **真实周期预测效果**：需要同一有效采集配置下足够连续历史，并按既有训练、回测和质量门槛评价；合成历史回归不代表生产预测效果。

没有增加前端、Redis/Celery、自动修复、自动入知识库或远程部署。通知结束行为依据 [Prometheus 告警规则说明](https://prometheus.io/docs/prometheus/latest/configuration/alerting_rules/)；独立 Docker 生命周期采集的取舍依据 [cAdvisor 0.55.1 Docker handler](https://raw.githubusercontent.com/google/cadvisor/v0.55.1/container/docker/handler.go)。完整启动与复验命令见项目 [README](../../README.md)。
