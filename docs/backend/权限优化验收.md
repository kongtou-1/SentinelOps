# 权限优化验收

日期：2026-10-25。

## 交付结果

- 保留三个角色，Viewer、Operator 默认权限可按模块配置，Admin 保留完整管理能力。
- 前端使用查看、诊断、日常操作等权限组，支持多资源、多组批量申请，一次批准或拒绝。
- 支持普通/受限资源、下属归属继承、限时或长期授权、撤回、到期、撤销及角色变更回收。
- 接口、业务查询、总数、看板、冻结证据、私有会话、归档、后台任务和事故通知发送采用统一权限与范围检查。

操作和接口详见[权限与资源授权](权限与资源授权.md)。

## 页面验收

使用独立 `ops_platform_access_ui_test` 数据库及合成账号完成 Viewer、Operator、Admin 验收：

1. Viewer 按应用选择诊断权限，填写理由并提交 7 天申请。
2. Admin 查看申请人、资源及权限，批准后申请退出待审批列表。
3. Viewer 刷新后看到对应应用的有效补充授权。
4. Admin 修改 Viewer 的知识查看默认权限，Viewer 已有会话随下一次导航被拒绝；恢复后默认权限恢复。
5. Operator 可以申请权限，不能访问角色管理页面。
6. 角色矩阵按主要动作显示状态，基础查看不会被标成部分拥有诊断或执行权限。

本机验收记录：`.local/access-acceptance/results.json`；截图：`.local/access-acceptance/role-permissions.png`。分批测试 XML 位于 `.local/access-backend-tests-*.xml`。
