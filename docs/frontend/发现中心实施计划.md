# 资源中心：Skill 市场与实用工具实施计划

状态：已实现，验收结果见《资源中心使用与验收》。用户于 2026-10-15 确认名称为「实用工具」，两个 Tab 内置分类且由 Admin 管理；Skill 首版展示介绍、使用说明和仓库／下载链接。

## 1. 功能定位与首版范围

在 SentinelOps 中新增独立的「资源中心」，包含左右并排的「Skill 市场」「实用工具」两个 Tab。从现有应用顶部右侧进入，中心内提供「返回运维平台」。覆盖办公、写作、科研、设计、数据处理、开发和运维等用途。

独立指页面布局与业务模块独立，仍复用当前 Vue 前端、FastAPI 后端、PostgreSQL、登录与角色权限，不拆出第二套应用。

首版按用户已确认的「介绍、使用说明、来源与仓库／下载链接」设计。站内保存 SKILL.md、完整包上传和托管不属于首版范围。市场审核只决定内容能否展示，不授予 Harness 工具调用、服务器操作或平台执行权限。

## 2. 页面与入口

| 页面 | 建议路径 | 内容 |
| --- | --- | --- |
| Skill 市场 | `/discover/skills` | 分类、关键词搜索、分页卡片 |
| 实用工具 | `/discover/tools` | 分类、关键词搜索、分页卡片 |
| 条目详情 | `/discover/items/:id` | 介绍、适用场景、使用说明、来源链接 |
| 我的提交 | `/discover/mine` | 本人草稿、待审核、退回、已发布条目 |
| 新建／编辑 | `/discover/items/new`、`/discover/items/:id/edit` | 根据条目类型展示表单 |
| 内容管理 | `/discover/manage` | Admin 审核、已发布内容与分类管理 |

资源中心使用独立布局：顶部保留品牌、返回入口、主题与账户；不展示运维模块导航与运维闭环页脚。Skill 市场与实用工具共用列表结构，但详情字段按类型展示。

主页面右上角使用带文字的「资源中心」入口。资源中心顶部主要顺序为：两个 Tab、搜索、分类筛选、卡片列表、分页；右侧提供「提交内容」「我的提交」，Admin 额外看到「内容管理」。

Tab、搜索、分类与页码写入 URL，支持直接分享、刷新和浏览器返回。窄屏分类横向滚动，卡片改单列。

## 3. 分类与展示内容

首版采用一级分类与标签：每个条目一个主分类，可填写少量标签，不建立多级分类树。

建议初始化分类：办公效率、写作与翻译、科研与学习、数据与分析、设计与创作、开发与运维、其他。两个 Tab 共享分类字典，分类数量分别按当前类型的已发布条目计算。

分类由 Admin 管理名称、排序及启停；停用分类不接收新提交，已有内容保留。已有内容或历史版本引用的分类使用停用；仅未被引用的分类可以删除。

| 内容 | 共用字段 | 类型专属字段 |
| --- | --- | --- |
| Skill | 名称、简介、分类、标签、详细说明、作者／来源、来源链接 | 适用平台、版本、使用方式、依赖与权限说明、仓库／下载链接、许可证（已知时填写） |
| 工具 | 名称、简介、分类、标签、详细说明、作者／来源、来源链接 | 官网、支持平台、收费方式、推荐理由、使用场景 |

卡片仅展示名称、简介、分类和少量类型信息；详细使用说明放详情页。默认按发布时间倒序，首版使用关键词查询和常规分页。

「推荐理由」由提交者撰写、Admin 审核，不需要引入推荐算法。未知费用、兼容性或许可信息允许标注「未提供」，不编造数据。

## 4. 提交、审核与发布

建议所有已登录角色均能浏览并提交内容，Admin 审核。Viewer 的提交权限仅作用于资源中心，不改变现有运维权限。

基本流程：保存草稿 → 提交审核 → Admin 查看 → 通过发布／退回修改。退回必须填写原因，提交者修改后重新提交。待审核版本锁定；提交者可以撤回为草稿后再修改。

已发布条目的修改生成新草稿，旧的已审核版本继续展示；新版本审核通过后替换。审核绑定具体版本，服务器同时检查版本与状态，避免提交者修改或重复点击导致错误发布。

Admin 可以下架内容，下架后从浏览列表、搜索与普通详情访问中隐藏；作者与 Admin 仍能在管理界面看到记录。下架后再次发布也要通过明确的审核发布操作。

审核界面展示提交人、类型、分类、内容全文、来源、修改时间与当前发布版本；更新审核展示前后变化。检查分类是否合理、说明是否完整、来源是否清楚、链接是否有效、是否含敏感信息，以及 Skill 是否说明所需依赖与权限。

管理员自行录入也经过明确的发布操作并记录操作者；首版不强制两名管理员共同审核。

## 5. 权限与业务边界

| 操作 | Viewer | Operator | Admin |
| --- | --- | --- | --- |
| 浏览已发布内容 | 是 | 是 | 是 |
| 新建、修改、撤回本人提交 | 是 | 是 | 是 |
| 查看他人未发布内容 | 否 | 否 | 是 |
| 审核、发布、退回、下架 | 否 | 否 | 是 |
| 分类管理 | 否 | 否 | 是 |

新增独立权限 `market:read`、`market:submit`、`market:review`、`market:manage`，由现有 `/me` 返回，后端执行权限与所有权检查。审核不复用运维 Approval 表。

现有 `/skills` 是诊断知识 Skill，`/action-skills` 是受控执行动作。新市场采用 `/discover` 与 `/api/v1/market` 命名空间，不改变这两类能力。

正文使用现有 Markdown 展示与净化机制；外部链接限制为 HTTP/HTTPS。首版只保存链接，服务器不自动抓取网页或下载执行包。

## 6. 数据与接口组织

采用四个新业务表。现有审计日志必须绑定事故，不适合直接复用；市场单独记录内容操作，避免修改原有运维审计结构：

| 表 | 职责 |
| --- | --- |
| `market_categories` | 分类名称、排序、启停 |
| `market_entries` | 稳定条目 ID、类型、所有者、上下架状态、当前发布版本引用 |
| `market_entry_revisions` | 内容快照、分类与标签、类型专属信息、版本号、草稿／待审核／通过／退回状态、提交与审核时间、审核人、审核意见 |
| `market_audit_logs` | 操作者、条目／版本／分类引用、操作类型、时间与必要变更信息；只追加写入 |

所有审核相关展示字段保存在版本快照内，避免直接修改条目字段绕过审核。已审核版本不再编辑，历史审核信息保留。发布引用只能指向当前条目已通过审核的版本；发布、替换和审计写入同一事务。

四表均继承现有时间字段规则，包含 `created_at`、`updated_at`、`deleted_at`，使用 UTC 带时区时间，正常查询排除软删除。分类、内容与审核变更都维护更新时间，审计表不提供编辑和删除接口。

接口前缀统一为 `/api/v1/market`：

- 浏览：分类列表、条目列表与详情；列表按类型、分类、关键词过滤，返回分页总数。
- 投稿：创建条目、保存本人草稿、提交审核、撤回，以及本人提交列表。
- 审核：Admin 待审核列表、版本详情、通过／退回、下架。
- 管理：Admin 分类新增、修改、启停及软删除。

普通浏览接口只读取当前已发布版本。作者与管理员的草稿、审核内容走受控接口，不能通过更换 ID 或增加状态筛选参数越权访问。

前端新增资源中心布局、列表、详情、提交表单与管理页；修改 `App.vue` 的布局选择和右上角入口，并在 `router.ts` 添加路由。后端新增独立 market API、校验结构与业务模块，沿用项目现有组织习惯。

## 7. 实施顺序与验收

1. **入口与浏览**：数据库迁移、独立权限、分类和已发布查询、资源中心布局、两个 Tab、详情、搜索与分页。
2. **投稿与审核**：草稿、提交、撤回、Admin 审核、版本替换、下架、分类管理与审计。
3. **本机验收**：三个角色的 API 和浏览器验证，前端类型检查与构建，后端相关测试、迁移及重启持久化验证。

验收重点：

- 主页面右上角能进入，两个 Tab 可切换且分类互不串筛选，刷新和返回正常。
- 未审核内容不会出现在浏览列表、搜索、分类数量或普通详情中。
- 普通用户不能审核、管理分类或修改他人内容，直接调用 API 也被拒绝。
- 已发布内容更新后，审核通过前仍展示旧版本；审核通过后列表和详情一致切换。
- 撤回、退回重提、重复审核和过期版本审核符合状态约束；审核及下架记录可追溯。
- 下架立即影响列表、搜索和普通详情；容器重启后状态保留。
- 办公、科研等非开发运维内容可以完整提交、分类、审核和展示。
- 原有运维导航、Skill、执行审批与诊断功能不受影响。

首版完成内容发现与人工审核闭环。完整包托管、站内安装和执行应在用户明确要求后分别设计。
