# 项目介绍页：全屏滚动与交互调研

日期：2026-10-24。范围：现有 `/project-intro` 的呈现方式、参考案例和实现路线；本次未修改页面代码、安装依赖或更新部署。

## 建议

采用「全屏章节 + 自然纵向滚动 + 关键段落固定演示」。背景铺满浏览器可视区域，正文保留适合阅读的宽度；首屏突出项目定位，架构和闭环两段随滚动分步展开，其余章节以轻量入场和背景过渡连接。

这里的全屏指占满浏览器视口，不需要进入 F11 模式。炫酷感主要来自构图、尺度变化和内容推进顺序。每屏围绕一个重点安排画面，避免所有元素同时出现。

## 当前页面具备什么基础

源码：`frontend/src/features/project-intro/pages/ProjectIntro.vue`。

- 已有现状、痛点、方案、架构、能力、闭环、优化、展望八章，可保留叙事顺序。
- 已有 SVG、HTML/CSS 图示和三张产品截图，可直接用于动画，不必先制作视频或三维素材。
- 已有吸顶目录、章节高亮、平滑定位、截图预览和手机布局。
- 当前章节外层 `max-width: 1360px`，页面四周有 24px 留白，白色内容块带阴影，因此整体更像连续摆放的汇报页。
- 内容块最小高度为 `min(780px, calc(100svh - 120px))`；高屏幕上高度上限为 780px，没有形成完整视口的章节舞台。
- 目前没有 GSAP 等动效依赖。现有 `IntersectionObserver` 用于章节高亮，尚未承担连续滚动动画。

本次浏览器访问 18088 地址后进入登录页，未取得该部署登录后的实时画面。布局判断依据当前源码、页面说明，以及 `.local/project-intro-20261017/` 内的历史验收截图；历史截图不视为当前部署截图。

## 常见效果，以及怎样用于本项目

| 方式 | 滚动时的体验 | SentinelOps 的使用位置 |
| --- | --- | --- |
| 全屏章节 | 每一段占据一屏，背景与画面形成完整构图 | 全篇基础布局 |
| 固定画面、分步推进 | 画面暂时停在屏幕内，继续滚动时图内内容变化 | 架构逐层搭建、事故闭环推进 |
| 卡片错峰入场 | 卡片按顺序出现，建立阅读主次 | 三个痛点、三项方案 |
| 卡片叠放 | 后一张覆盖或替换前一张，保持视觉焦点 | 能力展示的备选形式 |
| 局部横向推进 | 向下滚动时，一段内容沿水平方向展开 | 闭环的备选形式；不作为首选 |
| 轻视差与缩放 | 背景、主图以不同速度移动或改变尺度 | 首屏主视觉和章节过渡 |

全屏切页和固定演示是两种不同体验：前者主要切换章节，后者在一章内讲清楚过程。当前内容包含架构与流程，适合组合使用。第一版保留自然滚动，先不叠加全局强制吸附。

## 值得打开学习的案例

以下借鉴位置是针对本项目的设计建议，不表示对方网站使用相同技术栈。

| 案例 | 重点学习什么 | 转化到当前页面 |
| --- | --- | --- |
| [Linear 官网](https://linear.app/) | 核心价值主张与产品界面结合，按产品工作流程组织章节 | 首屏建立定位；能力章放大真实产品界面，让界面承担主要信息 |
| [Vercel Fluid](https://vercel.com/fluid) | 围绕请求、并发、资源使用讲解技术概念，并组织前后对比 | 用图示说明证据如何进入诊断、提案如何进入审批与执行 |
| [Apple AirPods Pro](https://www.apple.com/airpods-pro/) | 大幅主视觉与明确的章节主题，每一段突出一个卖点 | 借鉴首屏尺度、留白与章节节奏；我们的主视觉可用系统关系图 |
| [GSAP：Scrubbed Bento Gallery](https://demos.gsap.com/demo/scrubbed-bento-gallery/) | 布局随滚动进度改变，有公开演示和代码入口 | 学习产品界面由组合展示转为单个重点画面的方式 |
| [GSAP：Card stack](https://demos.gsap.com/demo/card-stack/) | 卡片堆叠层次与切换构图 | 可借鉴能力章的画面层级；该示例是点击驱动，不能直接当作滚动实现 |
| [fullPage.js 官网](https://alvarotrigo.com/fullPage/) | 整屏切换、章节锚点和纵横组合的直观体验 | 对比是否需要强烈的翻页感；本项目先不采用整站强制切页 |

已核对两个 GSAP 示例的公开代码：[Bento Gallery](https://codepen.io/GreenSock/pen/vYMzKZx) 使用 `ScrollTrigger` 的 `pin`、`scrub` 配合 `Flip`；[Card stack](https://codepen.io/GreenSock/pen/Yzdzxem) 由点击事件触发 `Flip`。可以学习它们的交互结构，再替换为本项目图示和截图，无需照搬整站样式。

外部官网通过公开页面核对了内容与章节，未完成逐段动效实测；上表不作为对方动画实现的技术鉴定。

## 八章可以怎样安排

| 章节 | 建议画面 | 滚动推进方式 |
| --- | --- | --- |
| 01 现状 | 全屏项目主视觉；保留团队运维与项目增长的核心论点 | 标题先建立焦点，资源与服务关系展开，增长曲线随后显现 |
| 02 痛点 | 三个大编号痛点，减少同屏争抢注意力的框线 | 三卡依次出现，最后形成共同结论 |
| 03 方案 | 预测、诊断、知识与 Skill 三项能力汇入人机协同 | 能力图示依次展示，连线汇聚到人工决策 |
| 04 架构 | 中央架构舞台，四层结构逐层搭建 | 固定舞台；资源→证据→智能能力→业务流程依次高亮，权限审批贯穿全程 |
| 05 能力 | 一个较大的产品界面，搭配当前能力标签 | 预测→诊断→修复交接依次成为主图；保留点击查看完整截图 |
| 06 闭环 | 一条清晰的事故处理路径 | 固定画面；监测、诊断、人工决策、审批、执行、核验、复盘依次推进 |
| 07 优化 | 已有基础、经验沉淀、新事故应用的关系图 | 先展示已有链路，再展开后续能力；规划状态保持明确 |
| 08 展望 | 三阶段路线图，形成干净的结束画面 | 阶段依次显现，最后停留在整体路线图 |

视觉保留项目蓝色体系，可以在首屏、闭环使用深色背景加强节奏，正文以浅色为主。每章保留清楚的标题、图内标签和状态，不添加装饰性说明小字。动画不能让尚属规划的能力看起来已经上线，也不能将模拟验收画面表达为真实生产成效。

## 技术路线比较

| 路线 | 能完成什么 | 适用判断 |
| --- | --- | --- |
| CSS + IntersectionObserver | 满屏布局、章节高亮、进入视口时淡入或位移 | 轻量方案；如果只要全屏与入场效果，这一层就够用 |
| Vue 3 + GSAP / ScrollTrigger | 固定画面、滚动进度控制、多个图层按顺序联动 | 推荐用于架构与闭环；沿用当前 Vue 页面即可 |
| CSS scroll-driven animations | 使用滚动或可见范围驱动 CSS 动画 | 可作为增强；MDN 当前仍将 `animation-timeline` 标为兼容性未全面覆盖，不作为唯一实现 |
| fullPage.js | 整屏切页及配套导航 | 更适合简短的逐屏展示；当前页面图文密集，第一版收益不足以支持增加一套滚动管理 |

技术依据：[ScrollTrigger 官方文档](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)、[GSAP 的 Vue 生命周期与清理示例](https://gsap.com/resources/frameworks/)、[MDN animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline)、[MDN scroll-snap-type](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-type)。fullPage.js 的采用还需符合其[官方许可要求](https://github.com/alvarotrigo/fullPage.js#license)。

实现时的具体取舍：

1. 章节背景全宽；内层内容保持最大阅读宽度。桌面章节使用扣除导航高度后的视口最小高度，内容较多时允许自然长高，不用固定高度裁切文字。
2. 继续使用页面原生纵向滚动。架构、闭环各自拥有一段动画进度，结束后进入下一章；暂不加入平滑滚动库、三维引擎或全局滚轮拦截。
3. `pin` 表示在一段滚动距离内固定舞台；`scrub` 表示动画进度跟随滚动位置。先用这两个能力做清楚一个流程，再考虑复杂图层切换。
4. 在介绍页组件挂载后建立动画，离开路由时清理。截图、布局尺寸稳定后计算触发位置；保留现有目录和预览功能。
5. 手机端取消长距离固定和横向推进，按正常纵向顺序展示。减少动态效果的系统偏好下直接展示完整内容。

## 如何学习和验证

建议按这个顺序推进：

1. 先看 Linear 和 Vercel，只记录每段的主标题、主图、视觉焦点如何切换，形成八章分镜。
2. 阅读 ScrollTrigger 官方最小示例，依次理解 `trigger`、`start/end`、`pin`、`scrub`；先不加入吸附、惯性或复杂插件。
3. 打开 Bento Gallery 的源码，观察固定区域和动画内容的分工。保留这种分工，用我们的架构图替换图片组。
4. 先制作首屏、架构、闭环三段原型，检查整体气质和滚动手感，再决定其他五章需要多大动效。
5. 桌面核对鼠标滚轮、触控板、目录跳转和反向滚动；手机核对阅读顺序与溢出；短视口和放大文字时不得裁掉内容。
6. 真正实施后再执行前端类型检查、现有测试、生产构建及浏览器验收。本次为调研，未运行代码测试，也未作性能结论。

优先验证的体验是：读者能快速理解项目定位，继续滚动时能看懂架构与事故处理过程，目录仍能直接到达任一章节。
