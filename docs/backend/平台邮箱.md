# 平台发件邮箱与服务通知

全平台使用一套发件邮箱。Admin 在“通知与维护 → 平台邮箱与通知”填写 SMTP 服务器、端口、SSL/TLS 或 STARTTLS、发件邮箱、登录账号及邮箱服务商提供的授权码。本页不再配置服务接收人或列出用户邮箱，也不跳转用户管理完成发件配置。

“保存平台邮箱”只保存设置，不发送邮件；“发送测试邮件”仅发送至管理员当次填写的测试地址。修改尚未保存时不能发送测试邮件。SMTP 接受邮件后仍需在收件箱确认；保存成功不等于通过外部邮箱联调。

各服务在自己的“服务响应与通知”配置主要负责人、备用负责人、通知关注人和接单时限。主要负责人及关注人接收初始事故通知；接单超时通知备用负责人和管理员。平台邮件寄往所选账号已有的通知邮箱，未填写邮箱的账号仍保留平台待办。全局邮件启用不再依赖先配置某个用户的邮箱。

告警通知和经人工批准发送的复盘报告共用平台 SMTP 设置。复盘邮件仍绑定审批版本与收件人，不自动发送。发信前核验配置版本；配置在发送过程中变化时停止该次投递，发送状态不明时不自动重试。

## 接口与存储

- `GET /api/v1/system/mail-settings`：`system:read`，读取发件设置和授权码是否已配置，不返回授权码。
- `PUT /api/v1/system/mail-settings`：`users:manage`，保存设置，使用 `expected_version` 防止覆盖并发修改；授权码留空保留，改变服务器、端口、加密方式或登录账号时需重新填写授权码。
- `POST /api/v1/system/mail-settings/test`：`users:manage`，显式提供已保存配置版本与测试收件邮箱；不自动重试写请求。

`0038_platform_mail` 为 `notification_policy` 增加 `encrypted_smtp_config` 和 `smtp_version`。SMTP 配置整体使用既有凭据主密钥加密保存，密钥与数据库分离，接口和审计均不输出授权码。保留原通知策略、服务接收规则和历史数据。operations-worker 与 report-worker 均需读取 `/run/secrets/credential_key`。

未保存平台发件设置时兼容原部署配置。默认 `mailpit:1025` 与测试发件地址仅供本机验收，不声称可投递到真实外部邮箱。
