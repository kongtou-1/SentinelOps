# 回收站与资源恢复

入口：系统管理 → 回收站，地址 `/recycle-bin`。巡检任务列表也提供管理员回收站入口。回收站与数据管理中的历史归档分开：前者恢复保留在数据库中的软删除记录，后者是历史清理导出的归档包。

## 使用

- 巡检任务行的“更多 → 删除任务”将任务移入回收站，停止进行中的巡检，保留历史记录；恢复任务后保持暂停。
- 展开的巡检记录行提供“删除”。排队、取数和检查中的记录须先停止，后端同样校验。删除的记录及随本次删除的对象结果可一起恢复；此前单独删除的对象结果不随之恢复。
- 回收站按名称搜索、按类型筛选并分页展示资源。恢复前确认资源及恢复方式；恢复成功后该条记录从回收站移除。
- 必需关联资源已删除时，显示具体恢复顺序。例如先恢复服务器，再恢复容器；先恢复任务，再恢复巡检记录。
- 回收站每行增加“永久删除”，确认后物理清除所选记录，无法通过回收站恢复；删除成功刷新列表与类型数量，当前页为空时返回有效页。

## 接入范围

覆盖当前具有删除或退役入口的 26 类资源：

| 分类 | 资源 |
| --- | --- |
| 资产与连接 | 服务器、容器、应用与服务、SSH 凭据、LLM 服务、服务监测、数据库连接、LLM 服务关联 |
| 巡检与预测 | 巡检任务、巡检记录、巡检对象结果、巡检数据源、旧版巡检 API 连接、预测任务 |
| 知识与报告 | 知识文档、Skill、复盘报告、私人诊断会话 |
| 运维与系统 | 告警规则、服务目标、维护窗口、告警抑制关系、个人通知、资源中心分类、Agent 模型通道、用户账号 |

公共资源仅管理员可查看和恢复。其他用户仅能管理自己的个人通知，以及在原诊断权限和资源范围内的私人会话；管理员也不能借回收站写入他人的私人会话或个人通知。

审批、执行授权、权限授予、登录会话和审计日志不开放回收站恢复或永久删除。不提供批量清空入口，原有定时保留策略不变。

## 永久删除

- 沿用恢复权限：公共资源仅管理员操作；个人通知与私人诊断会话仅原所有者且满足原资源权限。管理员不能删除其他用户的私人记录。
- 仅能删除已在回收站中的记录，必须提交当前 `expected_deleted_at`。已恢复、再次删除或删除时间变化后，旧请求不能清除新状态的记录。
- 巡检记录可连同已删除的对象结果、检查明细及调用轨迹清除；单个巡检对象结果只清除自身检查明细及调用轨迹。存在仍可见的对象结果或人工复核记录时拒绝删除。任务仍有运行历史时须先处理历史记录。
- 私人诊断会话清除自己的消息、事件及运行明细；知识文档清除其索引分块。处理中的诊断、巡检、报告、通知发送或知识索引须先结束。
- 其余业务关联、审批、执行、审计、报告版本及发送记录均不级联清除。包括已软删除的引用在内，存在外键引用时返回 409；巡检连接的 JSON 配置引用及维护窗口的范围引用也会拦截。
- 永久删除只操作平台数据库，不执行 SSH、不删除真实容器或远程资源，不清除独立备份、历史导出包或监控时序。每次成功删除追加 `resource_purged` 运维审计，失败时回滚整个删除事务。

## 恢复行为

- 自动任务、规则、知识、模型通道、连接等保持停用；服务器监控与 LLM 探测保持停用；数据库的查询授权开关保持关闭。由管理员检查后通过原业务入口启用。
- 恢复用户后保持禁用，不恢复已撤销的登录会话；不修改账号角色或增加权限。
- 恢复资产仅修改平台记录，不启动容器、不执行 SSH、不部署采集器。
- 恢复巡检记录、诊断会话或报告不重新执行任务、不发送邮件。通知恢复为已读，原未发送的邮件不进入发送队列。
- 维护窗口保持原有效期；告警抑制关系校验循环依赖。确认框展示恢复方式，由管理员明确发起恢复。
- 应用退役时原逻辑已清除的源码凭据不重建，需重新配置。已被物理清除的记录或文件无法通过本回收站恢复，须使用原备份或归档。

## 接口与数据

- `GET /api/v1/system/recycle-bin/types`：当前用户可管理的类型与数量。
- `GET /api/v1/system/recycle-bin?kind=&search=&offset=0&limit=20`：仅返回资源名称、类型、时间、恢复方式及关联阻塞原因；总数位于 `X-Total-Count`。不返回密码、密钥、凭据密文或业务原始证据。
- `POST /api/v1/system/recycle-bin/{kind}/{id}/restore`：提交 `expected_deleted_at`，状态过期、关联缺失、抑制循环或唯一约束冲突时拒绝恢复。不自动重试写请求。
- `DELETE /api/v1/system/recycle-bin/{kind}/{id}`：JSON 请求体 `DeleteInput` 必填带时区的 `expected_deleted_at`；成功返回 204，权限不足返回 403，资源不在回收站返回 404，状态变化、处理中或关联引用返回 409。不自动重试删除。

复用各资源现有的 `deleted_at`，没有增加业务表或数据库迁移。恢复时维护 `updated_at`，有版本号的配置推进版本；恢复操作追加到运维审计，动作代码 `resource_restored`。每个资源类型使用显式白名单，不接受任意表名。
