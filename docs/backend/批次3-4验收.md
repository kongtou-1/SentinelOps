## 实现选择

- 沿用同步 FastAPI/SQLAlchemy 模块化单体；邮件分组、去重和重试交给 Alertmanager，同时配置 Email + Webhook receiver。当前不需要 Redis/Celery。
- Viewer 读取资源、指标、规则和事件；Operator 额外发现容器与确认告警；Admin 管理服务器、凭据及规则并执行 SSH 连接测试。
- SSH 凭据的密码、私钥和口令全部加密，接口不返回密文或明文。Fernet 主密钥与数据库分离；提供经过核对的主机公钥后才允许连接，未知或不匹配主机密钥不能被自动接受。连接测试只进行握手和认证，不执行命令。
- 采集由 node_exporter、cAdvisor、Blackbox Exporter 完成。默认采集与服务发现间隔 15 秒，Prometheus 保留 15 天原始时序；数据库不复制指标序列。
- Prometheus 通过带独立 Bearer 密钥的 HTTP 服务发现读取有效服务器。新增、修改、禁用和删除服务器无需改 Prometheus 配置文件。Linux Docker 采集器固定模板通过 Admin 接口下载；本次实际部署仅限本地测试环境。
- 容器发现读取 cAdvisor 的 `container_last_seen`，以服务器和 Docker ID 唯一标识资产。Prometheus 每 30 秒采集后端容器指标接口，自动同步状态；Operator 也可显式同步。正常采集下超过 60 秒未出现的资产标为 stopped，已发现资产持续输出 `platform_container_up=0`，避免序列消失被当作恢复。采集失败保留最后已知状态并输出 `platform_inventory_up=0`，纳入 `target_up` 告警；显式同步返回 502。无 HTTP 容器使用 `container_up` 规则。Admin 可软删除退役资产，后续同步不会重新登记同一 Docker ID；替换后的新 ID 为独立资产。
- 指标查询只开放预定义指标，按服务器或容器限定；瞬时和范围查询使用 Prometheus 官方 HTTP API。范围最大 31 天、每序列 11000 个点，要求带时区时间。容器 CPU 汇总固定版本 cAdvisor 的各核心计数，100% 表示占用一个 CPU 核心。
- 规则只选择固定指标、阈值、持续时间、严重程度及可选服务器，不开放任意 PromQL。Admin 显式调用 apply-rules：串行生成规则、原子替换文件、重新加载并查询 Prometheus 实际规则后才返回成功。失败会恢复文件、重新加载并核对旧规则；即使首次 reload 实际成功但响应丢失，也会恢复运行时。恢复无法确认时明确报 effective rule state is unknown，不能据数据库配置假定已生效。校验兼容 Prometheus 标签排序和空白标准化。
- 文件型 Compose secrets 不支持文件 UID/mode 覆盖，因此使用一次性 root 初始化服务复制源文件至各服务专用 Linux 卷；凭据目录 0700、文件 0400，分别归后端 UID 1000 或监控 UID 65534 所有。复制采用原子替换；业务服务非 root、凭据卷只读。规则目录 0755、规则文件 0644，后端可写、Prometheus 只读。已应用规则保存在 platform_rules 卷，初始化保留已有规则，备份需要包含此卷。
- Webhook 与服务发现分别使用独立服务密钥，不接受用户 JWT。每个告警以 `fingerprint + starts_at` 建唯一约束，支持重复与并发投递；恢复对单次事件为终态，迟到 firing 不会重新打开。同一 fingerprint 的下一次起始时间产生新事件。
- 人工确认保存操作者、确认时间和评论，与 firing/resolved 分开。未提供人工编辑或删除告警事件接口，也没有将告警当作事故或执行审批。
- 新增 `ssh_credentials`、`servers`、`containers`、`alert_rules`、`alert_events` 五张表，全部含 UTC 带时区创建、更新、删除时间及 UPDATE 触发器。服务器删除时其容器资产同步软删除；普通列表和服务发现排除软删除数据，名称继续保留。

## 接口

所有路径以 `/api/v1` 开头。列表支持 offset/limit，最多 100 条；PUT 为完整替换。

| 方法 | 路径 | 权限/用途 |
| --- | --- | --- |
| GET/POST | `/ssh-credentials` | Admin；列表/创建，创建提交 name、auth_type、secret、可选 passphrase |
| PUT/DELETE | `/ssh-credentials/{id}` | Admin；替换/软删除，正在被有效服务器使用的凭据不能删除 |
| GET/POST | `/servers` | Viewer 列表，Admin 创建 |
| GET/PUT/DELETE | `/servers/{id}` | Viewer 详情，Admin 完整替换/软删除 |
| POST | `/servers/{id}/test-ssh` | Admin；校验主机密钥并认证，返回 success、status、latency_ms |
| GET | `/servers/{id}/collectors-compose` | Admin；固定 Linux Docker 部署模板，不执行部署 |
| POST | `/servers/{id}/sync-containers` | Operator；从真实 cAdvisor 发现和更新容器资产 |
| GET | `/servers/{id}/metrics` | Viewer；metric，或同时提供 start/end/step |
| GET | `/containers`、`/containers/{id}` | Viewer；支持 server_id、status 过滤 |
| GET | `/containers/{id}/metrics` | Viewer；容器指标及可选时间范围 |
| DELETE | `/containers/{id}` | Admin；软删除退役容器，停止该资产监控 |
| GET | `/monitoring/targets` | 服务发现专用密钥 |
| GET | `/monitoring/container-metrics` | 服务发现专用密钥；定时同步资产并输出容器可用性和同步健康指标 |
| GET/POST | `/alert-rules` | Viewer 列表，Admin 创建 |
| PUT/DELETE | `/alert-rules/{id}` | Admin 完整替换/软删除 |
| POST | `/monitoring/apply-rules` | Admin；生成并应用有效规则 |
| POST | `/hooks/alertmanager` | Alertmanager 专用密钥；Alertmanager v4 payload |
| GET | `/alerts`、`/alerts/{id}` | Viewer；支持 status、server_id 过滤 |
| POST | `/alerts/{id}/ack` | Operator；提交 comment，重复确认保留首次记录 |

服务器创建示例，不含 SSH 凭据：

```json
{
  "name": "local-docker-test",
  "host": "127.0.0.1",
  "environment": "local-test",
  "node_exporter_target": "node-exporter:9100",
  "cadvisor_target": "cadvisor:8080",
  "health_url": "http://test-app:8001"
}
```

SSH 可选字段为 ssh_port、ssh_user、credential_id、ssh_host_key。引用凭据必须同时提供主机公钥，例如 `ssh-ed25519 <base64公钥>`，不能将首次连接收到的未知公钥直接当作已可信密钥。

指标名：`host_cpu_percent`、`host_memory_percent`、`host_disk_percent`、`host_network_receive_bytes`、`host_network_transmit_bytes`、`container_cpu_percent`、`container_memory_bytes`、`container_network_receive_bytes`、`container_network_transmit_bytes`、`target_up`、`http_up`、`container_up`。网络指标单位为字节/秒；内存指标为字节；磁盘按文件系统返回系列。可用性规则 threshold 固定 1，低于 1 触发，其余指标超过阈值触发。

## 验证记录

独立 PostgreSQL `ops_platform_test` 上运行 **71 项测试全部通过**。在原 64 项基础上，增加三种并发登录与密码重置/禁用/删除的真实数据库锁等待验证，定时资产更新、消失检测、采集失败保留、恢复与退役测试，两种邮件状态的旧消息和其他告警发生次数拒绝测试，以及旧规则数值和标签顺序的标准化验证。规则测试补充“reload 成功但响应丢失”的运行时恢复，以及无法确认恢复的明确报错。

并发登录持有用户行锁直到会话创建完成；账户修改先按固定顺序锁定角色与用户再撤销会话。测试确认账户修改确实等待 PostgreSQL 行锁，随后新建会话也被撤销，旧密码不能继续登录；最后管理员和刷新令牌并发测试仍通过。

独立 Linux 容器使用合成凭据执行 `backend/tests/linux_permissions_check.py`：源凭据为其他 UID 所有的 0600 文件，初始化后检查各服务 UID 可读本方 0400 凭据、不能写凭据或读取对方凭据；只有 UID 1000 可写规则，UID 65534 能读且不能写，重复初始化保留已应用规则。运行服务的实际卷也核对了 UID、0400 文件权限及非 root 用户。这验证 Linux 权限行为，不声称用户远程 Linux 部署已验收。

SSH 测试由本机临时 SSH 服务真实执行 Paramiko 协议握手，验证密码认证、私钥认证、错误密码拒绝与主机密钥不匹配。没有将 mock 的 SSH 成功当作真实服务器集成；尚未连接用户的远程服务器。

迁移包含 `0003_resources`、`0004_alerts`。测试对全部九张表逐一检查三个时间字段的类型、默认值、可空性、UTC 与更新触发器，并测试降级与重做。运行容器内 `alembic check` 显示 `No new upgrade operations detected`。

真实运行组件的 `promtool check config` 验证配置和六条规则通过，`amtool check-config` 验证 Alertmanager receiver 通过；代码的 Ruff 检查和格式检查通过。

真实 HTTP 验收由 `backend/scripts/accept_monitoring.py --fault-test` 完成，证据保存在本机 `.local/batch3-4-acceptance.json`：

1. 登录已有管理员，健康与数据库检查通过。
2. 登记测试服务器并应用 CPU、内存、磁盘、Exporter、HTTP、容器停止六条规则。
3. 查询十一类真实主机/容器/HTTP 指标及历史数据，发现容器资产；重复同步的资产 ID 集合一致。
4. 记录邮件基线后只停止本项目无 HTTP 端口的 `test-worker`；定时同步自动标记 stopped，Prometheus 规则变为 firing，Alertmanager 投递 Webhook，业务库建立事件。故障中不手动同步资产。
5. 重复发送该实际事件两次，changed 均为 0，事件仍只有一条；保存人工确认。
6. 本地 SMTP 收到新的 `[FIRING:1] LocalWorkerDown` 邮件，正文匹配本次服务器、容器和告警起始时间。按容器 ID 分组，其他容器告警不会遮蔽本次恢复通知。
7. 恢复 test-worker；同一事件更新 resolved，保留确认信息和 ends_at；SMTP 收到新的 `[RESOLVED] LocalWorkerDown` 邮件并通过同一事件匹配；资产自动恢复 running。

故障测试使用真实运行容器、真实采集器、真实 Prometheus 规则、真实 Alertmanager、真实 PostgreSQL 和本地 SMTP。没有用直接构造告警替代真实故障；直接重复通知只用于验证幂等。

## 当前限制与后续接入

- 测试服务器为本机 Docker Desktop Linux VM，不能据此声称 Windows 宿主机全部指标或用户远程 Linux 服务器已验收。远程 SSH 与采集器需要实际目标及授权；本次没有改变远程服务器状态。
- 邮件默认送到本地 Mailpit，已验证 SMTP 接收及内容；没有外部邮箱配置，未声称外部投递成功。真实 SMTP 参数配置在根目录 `.env`，重新生成监控配置并重启 Alertmanager。
- 本地 Docker Desktop 根挂载不支持 rslave，测试 profile 使用只读普通挂载；远程 Linux 模板保留主机挂载传播方式。本地文件系统指标含 Linux VM 可见的宿主共享挂载，其告警需按实际资产解释。
- 当前接口只认证 SSH，不包含任意 Shell、容器日志读取、远程 bootstrap 执行或审批执行器。固定模板支持经授权人工部署，不提前实现第九批次审批模块。
- 规则应用与数据库配置为显式两步，服务器删除/禁用后需再次应用以清除专用规则。API/服务发现故障不清空已有 Prometheus 目标，使用最后成功发现的目标继续采集。
- 容器状态定时更新依赖 Prometheus 对资产接口的采集；采集失败时状态代表最后已知结果，应结合 `target_up` 的同步健康值判断。邮件与 Webhook 是 Alertmanager 独立投递，两者没有跨系统事务；Webhook 重试靠数据库唯一约束去重，SMTP 异常靠 Alertmanager 重试。
- `.local/credential.key` 必须随数据库分开备份；丢失后已有凭据不可解密。配置生成脚本不会覆盖已有密钥。默认入口仅绑定本机，外部部署需实际配置 HTTPS、网络限制及 SMTP。
